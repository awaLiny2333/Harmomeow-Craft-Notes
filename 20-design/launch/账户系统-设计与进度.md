## 0. 结论先行
1. **MC 客户端本身不校验用户名**；离线身份 UUID 在 `--uuid` 缺失/非法时由 **MC 自算**：`UUID.nameUUIDFromBytes("OfflinePlayer:"+name)`（1.7.10+）。**但"语法合法"的 UUID（如全零）会被 MC 直接采用 → 必须由启动器传正确派生值**。
2. 我们**当前离线实现有多处偏差**：传全零 UUID、token 被 Java 改写、`userType=mojang`、用户名零校验 → 与 HMCL/原版不一致（见 §2.2）。
3. **正版登录 = MSA OAuth2 → Xbox Live(XBL→XSTS) → Minecraft Services(login_with_xbox) → profile/entitlements 四级链**；对无浏览器回调的 2in1，**Device Code Flow 最优**（无需 redirect_uri）。
4. 鸿蒙平台能力齐备（`http` / `startAbility(viewData)` 开浏览器 / **Asset Store** 存 token / `pasteboard` 复制 code / `Image(url)` 头像）。唯一硬约束：token 可能超 Asset `SECRET` 的 1024B 上限（改用 `DATA_LABEL_*`）。
5. **改造核心落点不是 argv**：ArkTS 当前**不向 MC 传任何账户 argv**；账户真身是 `<filesDir>/meow-home/accounts/<name>.json`，由 Java 按"玩家名=文件名"加载。账户系统 = **账户层的生成/选择/跨进程选中态** + （必要的）launcher.jar 契约校准。
6. 目标：**删除高级选项的「离线玩家名」，替换为与 HMCL 对标的账户管理**（多账户、类型化、选中、头像）。

## 1. MC 认证契约（跨时代，jar 实证）

### 1.1 启动参数（认证相关）
| 版本 | 形式 | 认证参数 |
|---|---|---|
| 1.6.1 / 1.6.4 | `minecraftArguments` | `--username --session <任意串> --version`（**无 uuid/accessToken/userType**） |
| 1.7.10 / 1.8.9 | `minecraftArguments` | `--username --uuid --accessToken --userProperties --userType --version` |
| 1.12.2 | `minecraftArguments` | 同上，**去掉 `--userProperties`**，加 `--versionType` |
| 1.13.2–1.17.1 | `arguments.game` | `--uuid --accessToken --userType --versionType` |
| 1.21.10 / 26.x | `arguments.game` | **去 `--userType`**，加 `--clientId ${clientid} --xuid ${auth_xuid}` |

客户端 `Main` 里 `.required()` 的只有 `--accessToken`（1.6.x 是 `--session`）与 `--version`；`--uuid` 可空→MC 自算；`--xuid`/`--clientId` 可空（空串→`Optional.empty`）。**`userType` 默认 `legacy`（1.7.10–1.17.1），1.21+ 移除。**

### 1.2 离线 UUID 派生（关键）
- 算法 = Java type-3：`nameUUIDFromBytes(("OfflinePlayer:"+name).getBytes(UTF_8))`。
- MC 在 `--uuid` 缺失/**不可解析**时自算（1.7.10 `nn.a`、1.16.5 `bfw.c`、1.21.10 `ke.a`、26.3 `UUIDUtil.createOfflinePlayerUUID`）。
- **全零 UUID 能 `fromStringLenient` 解析 → 判"合法" → MC 直接采用、不再派生** → 我们的 profile/皮肤/玩家数据键全落全零，与 HMCL/原版不一致。
- **1.6.x 没有 UUID**（jar 全量无 `OfflinePlayer:`/`nameUUIDFromBytes`）→ 该代按用户名标识。
- 测试向量：`Alex → 36532b5e-c442-3dbb-a24c-c7e55d0f979a`、`Player → a01e3843-e521-3998-958a-f459800e4d11`、`Notch → b50ad385-829d-3141-a216-7e7d7539ba7f`。
- 启动器算并传（HMCL：`OfflineAccountFactory.getUUIDFromUserName` `:85-87`；`DefaultLauncher` 传**无连字符** `UUIDs.toCompactString` `:628`）。我们 `ArgBuilder` 也 `stripDashes(profileId)`（契约一致）。
- **联机 offline server 不受客户端 UUID 影响**（服务端 `online-mode=false` 自己按名派生）；受影响的是**单机/客户端 profile**。

### 1.3 用户名规则
- 客户端 `Main` **不校验**（默认 `"Player"+rand`）。
- **服务端**校验（现代）：`StringUtil.isValidPlayerName` = 长度 ≤16 且字符 `>32 && <127`（可打印 ASCII，无空格/非 ASCII）；1.6.4 仅剔控制符。
- 正版名（外部系统）：3–16，`[A-Za-z0-9_]`。HMCL 离线创建**警告** `^[A-Za-z0-9_]+$`+≤16 但可继续。
- 我们：`AdvancedOptionsView` 仅 `trim()` → 空/中文/超长会原样传入，进现代集成服即 `Invalid characters in username`。

### 1.4 离线最小集
- 1.6.x：`--username <name> --session <任意串> --version <id>`（+ gameDir/assetsDir）。
- 1.7.10–1.17.1：`--username --uuid(派生) --accessToken(任意非空) --version`（+JSON 要求的 `--userProperties {}` / `--userType msa`）。
- 1.21+/26.x：`--username --uuid(派生) --accessToken --version`（xuid/clientId 可空）。

## 2. 离线账户：现状 → 目标

### 2.1 HMCL `OfflineAccount`
- 字段：`profileName`、`profileID`(UUID)、`skin`、`downloader`（`OfflineAccount.java:52-74`；空名抛异常）。
- 登录产物 `AuthInfo(name, uuid, UUID.randomUUID() 当 token, userType=msa, "{}")`（`OfflineAccount.java:103-106`；注释提醒 `mojang` 联机可能 invalid session）。
- 序列化：`profileID/profileName/skin`（`:191-203`）；从存储读回时缺 `profileID` 则按名派生（`OfflineAccountFactory.java:70-83`）。

### 2.2 我们的现状与缺陷（要修）
| # | 现状（`file:line`） | 问题 | 修法 |
|---|---|---|---|
| 1 | `OfflineAccount.ets`/`LaunchDefaults` 传 `OFFLINE_UUID='00000000-…'` | MC 采用全零 UUID（不派生）→ profile 键/皮肤错 | 传 `nameUUIDFromBytes("OfflinePlayer:"+name)`（ArkTS 侧实现；Java 侧 `ArgBuilder` 已 stripDashes） |
| 2 | `Account.java:30-32`：`xuid!=null ⇒ accessToken:='88888888-…'`；我们 JSON 恒写 `xuid='0'` | token 语义漂移 | 离线 `xuid` 置空（不是 `'0'`），并校准 Java 逻辑；token 用明确常量 |
| 3 | `ArgBuilder.java:42` `user_type='mojang'`（仅遇 `--xuid` 才切 `msa`） | legacy(1.7.10–1.17.1) 传 `mojang`，联机风险 | 统一 `msa`（或 `legacy`），需改 launcher.jar |
| 4 | 用户名零校验 | 现代集成服拒收 | UI + 落盘前校验可打印 ASCII/≤16（对标 HMCL） |
| 5 | `MinecraftLauncher.ets:273` `-Dmeowcraft.path.private.account` | **死参数**（Java 从不读） | 删 |
| 6 | ArkTS `makeMacros` 设 `user_type=legacy`（`MinecraftLauncher.ets:406`）与 Java `mojang` 冲突 | 死代码/隐患 | meow 路径不走它，清理 |

> **硬契约**：账户 JSON 键 `accessToken/clientToken/profileId/username/xuid` 必须与 Java `Account.java:16-20` 逐键一致；改契约须同步 `launcher.jar`（javac 由人跑）+ 递增 `EXTRAS_VERSION`。

### 2.3 目标模型（离线）
- 账户对象：`{ type:'offline', name, uuid(派生), skin? }`；`accessToken` 用离线常量、`userType=msa`、`clientId/xuid` 空。
- 名字校验：`^[A-Za-z0-9_]{1,16}$`（超限/非法给出提示，兼容 HMCL 的"警告后可继续"）。
- 保留 1.6.x 分支（该代只用 name+session，无 uuid）。

## 3. 微软（正版）在线登录协议

### 3.1 四级链（端点）
| 步 | 端点 | 关键字段 | 产出 |
|---|---|---|---|
| 1 | `POST login.microsoftonline.com/consumers/oauth2/v2.0/devicecode` | `client_id`, `scope` | `device_code/user_code/verification_uri/expires_in/interval` |
| 2 | 浏览器访问 `verification_uri`（`microsoft.com/link`）输 `user_code` | — | 用户授权 |
| 3 | `POST …/oauth2/v2.0/token`（device_code grant） | `code=device_code` | MSA `access_token` + `refresh_token` |
| 4 | `POST user.auth.xboxlive.com/user/authenticate` | `RpsTicket:"d="+MSA_token`, `RelyingParty:http://auth.xboxlive.com` | XBL token + `uhs` |
| 5 | `POST xsts.auth.xboxlive.com/xsts/authorize` | `SandboxId:"RETAIL"`, `UserTokens:[XBL]`, `RelyingParty:"rp://api.minecraftservices.com/"` | XSTS token + `uhs` |
| 6 | `POST api.minecraftservices.com/authentication/login_with_xbox` | `identityToken:"XBL3.0 x=<uhs>;<XSTS>"` | MC `access_token` |
| 7 | `GET api.minecraftservices.com/entitlements/mcstore` | `Bearer <MC>` | 所有权（200=有） |
| 8 | `GET api.minecraftservices.com/minecraft/profile` | `Bearer <MC>` | `id`(UUID 无横线) / `name` |
| 9 | `POST …/oauth2/v2.0/token`（refresh grant） | `refresh_token`（**轮换，需存新值**） | 新 MSA token |

- **scope** = `XboxLive.signin offline_access`（HMCL `MicrosoftService.java:57`）。
- **client_id**：HMCL 构建注入（`HMCL/build.gradle.kts:32`）；公开通用 `00000000402b5328`（移动端生态）。建议**自注册 Azure 公有客户端**（启用 device code）以避免频控/地区限制（决策点）。
- **轮询**：`authorization_pending` 继续；`slow_down` 加大间隔；`expired_token` 终止；总超时 ~900s（HMCL `OAuth.java:116-167`；注意 HMCL 漏 `bad_verification_code`，我们要补）。

### 3.2 刷新 / 生命周期
- 存 `refreshToken + profileID + profileName + accessToken + notAfter`；`now > notAfter` 或 `validate()` 非 200 → 用 refresh 换新 MSA token → **整链重跑** XBL/XSTS/login_with_xbox（HMCL `MicrosoftService.java:88-97`、`MicrosoftAccount.java:78-118`）。
- 失效（`invalid_grant / AADSTS70000`）→ `CredentialExpiredException` → 重新 Device Flow。

### 3.3 启动参数注入
- `--accessToken <MC token> --username <name> --uuid <无横线 id> --userType msa`；可选 `--xuid <uhs>`（uhs 即 user hash）。
- HMCL 不解析 `${clientid}/${auth_xuid}`（字面量透传，游戏仍可启动）→ **非硬性必需**。

### 3.4 失败模式（做错误本地化用）
XSTS `2148916227`(封禁) / `2148916233`(无 Xbox 账号) / `2148916235`(地区不支持) / `2148916236/37`(需成人验证) / `2148916238`(儿童需 Family)；XBL 400；MC `profile` 404 区分"无所有权(license)"vs"未建档案"；HTTP 429 频控。

### 3.5 ★ client_id 实测结论（2026-09-11，实机遇错）
- 用 `client_id=00000000402b5328` 走 **v2.0 设备码** → `unauthorized_client / AADSTS700016`（该 id **不在** AAD `consumers` 目录 `9188040d-…`）。
- 根因：`00000000402b5328` 是 **live.com v1.0 MSA 原生客户端 id**，只存在于 MSA 目录，**不是** Azure 注册 app → v2.0 端点不认。
- HMCL / HomoLauncher 的 v2.0 设备码**都要自注册 Azure 公有客户端**：client_id 为构建期注入（HMCL `MICROSOFT_AUTH_ID`）/ 字符串资源（HomoLauncher `MicrosortAuthClientId`），**仓库内默认空串**，无公开可用值。
- Pojav_iOS / Amethyst 走的是 **v1.0 授权码 + 内嵌 WebView**（`login.live.com/oauth20_authorize.srf` + `oauth20_token.srf`，`redirect_url=…oauth20_desktop.srf`，scope `service::user.auth.xboxlive.com::MBI_SSL`，`RpsTicket` **裸 token 无 `d=` 前缀**）——**没有设备码流**。
- **两条路**：**(B，推荐) 自注册 Azure 公有客户端**（Personal accounts only + Allow public client flows=Yes；只改 `MS_CLIENT_ID` 一行，其余 v2.0 设备码逻辑不动）；**(A) 改 v1.0 授权码 + ArkUI `Web` 组件截获回调**（无需注册，但要新增 WebView/回调截获，且 v1.0 有下线风险）。

## 4. 数据模型与持久化（对标 HMCL）

> 本节的事实底稿见 [`../../10-research/hmcl-存储模型.md`](../../10-research/hmcl-存储模型.md)。

### 4.1 HMCL schema
- 类型：`offline | microsoft | authlibInjector`（老 Mojang 仅遗留迁移）。
- 主键 `accountID = "account:<uuidv7>"`。
- **公开 metadata** `config/accounts.json`：`{accountID,type, profileID/profileName/skin…}`；**私密** `private/account-private-data.json`：信封 `{protection:'hmcl-obfuscated-v1', nonce, payload}`（ChaCha20 + **硬编码 key**，弱混淆，非设备密钥库）。
- 选中：`launcher-settings.json → selectedAccount`；优先级 遗留 `selected` → 该字段 → 首个账户。
- 头像：按 `uuid.hashCode()` 从 **9 个内置皮肤**（alex/steve/…）选默认，**不用 Crafatar**；在线皮肤下载缓存。

### 4.2 账户 schema（P1 已落地）
- **账户本体全部走应用沙箱文件**：账户 metadata + token（含微软 refresh/access）存
  `<filesDir>/meow-settings/accounts.json`（`format: 1`，形状 `{format, accounts:[…]}`）；选中项 `selectedAccount`
  与目录枚举、全局设置共用 `app-settings.json`。2026-09-11 最初定 Preferences，**2026-09-15 用户决定"全部搬成文件"**；
  **2026-09-15 二轮决策连 Preferences 及迁移代码一并删除**（开发阶段无历史包袱，不做历史迁移、旧值自行重填）。
  沙箱应用私有但**不加密**（随导出/备份可外泄）——接受此权衡以简化实现；
  日后若要更安全可换 Asset Store（`@ohos.security.asset`，`SECRET`≤1024B，见 §5）。
  详见 [`实例设置存储-方案.md`](实例设置存储-方案.md) §3.3。
  - `Account = { id:'account:<...>', type:'offline'|'microsoft', name, uuid }`；账户 `id` 实际格式形如
    `account:<毫秒时间戳>-<4位hex随机后缀>`（`newAccountId` 生成，随机后缀防同毫秒碰撞）；
    离线 `uuid` 留空（launcher 按名派生），微软为真实 UUID。
- **启动用账户档案**：`<filesDir>/meow-home/accounts/<name>.json`，键 `accessToken/clientToken/profileId/username/xuid`（launcher.jar 硬契约）——由 `AccountsTools.writeAccountFile` 生成。
- **跨进程**：主进程写应用沙箱文件（`accounts.json` + `app-settings.json`）；`:game` 进程读。want 只带 gameRoot/jsonPath/versionId → 账户选择走文件。
