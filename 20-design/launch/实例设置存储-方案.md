## 0. 结论先行

1. **逐版本设置从"全局 Preferences 按实例 id 存"改为"存在实例自己的目录里"**：
   `<gameRoot>/versions/<id>/.hmmcraft/instance-settings.json`，一个文件装全部。
2. **收益**：① 设置跟着实例目录走，**跨机拷贝/迁移实例时一起带走**；② 天然带"目录"维度，
   **不同游戏目录下的同名实例不再撞键**（旧实现的真实 bug）；③ 删实例目录即可，无孤儿键。
3. **对齐 HMCL 的隔离表示法**（不是裸布尔）：开 = `overrideProperties` 含 `"runningDirectory"`
   且 `runningDirectory = "versions/<id>"`；关 = 两个键都不写。**三态语义**（用户 2026-09-15 定）：
   **无文件 = 从未配置 → 取默认（隔离`开`）**；有文件且含 `runningDirectory` = 开；有文件但不含 = **显式关**
   （故"关"必须落盘才算数）。
4. **只写"脏"字段**：值为默认（隔离**开** / 后端 `auto` / glthread 开）时**不写**该键；`format` 总写。
5. **不迁移**：文件缺失 / 解析失败 / schema 不认 → 一律默认值（隔离**开**），且**不覆盖**坏文件（读失败只记日志）；
   旧 Preferences 键（`version_isolation` / `renderer_overrides` / `glthread_off`）**直接弃用**。
6. **代价**：既有实例的旧设置丢失（见 §5「已知后果」）。
7. **全局设置并入应用级文件（2026-09-15 二次决策，**取代**此前的"存游戏根"口径）**：`SettingsTools` 的高级选项 /
   下载源 / client_id / "上次启动"等，统一收进 `<filesDir>/meow-settings/app-settings.json` 的 **`global` 段**，
   分 `launcher` / `runtime` / `network` 三组。**应用级、全局唯一**——不再按游戏目录各存一份、也不再随游戏目录迁移。
   同样 **plain JSON + `format: 1`**、**稀疏**、**读失败退默认不回写**、**底稿合并保留未知键**。详见 §3.2。
8. **应用级设置（`filesDir/meow-settings/`）：目录枚举 + 账户 + 全局设置三合一所在**。目录枚举（`dirs` / `selectedDir`）、
   选中账户指针（`selectedAccount`）与全局设置（`global`）共处 `app-settings.json`；账户本体（含 token）单独 `accounts.json`。
   理由：目录枚举是"解析游戏根"的前置（存游戏根内会循环）、账户与全局设置跨目录或全局唯一，均不属于任何单个 `.minecraft`。
   **本轮彻底删除 Preferences（含迁移代码）**，不做任何历史迁移；新增「导出设置」入口把两份 JSON 导出到用户选择目录（含凭据 → 必须确认告警）。详见 §3.3。

## 1. 动机

### 1.1 真实 bug：只按实例 id 存 → 跨游戏目录同名实例撞键

旧实现把三项逐版本设置存在**全局 Preferences**（`STORE_NAME = meowcraft`）：

- `version_isolation`：JSON 字符串数组（已隔离的**实例 id**）；
- `renderer_overrides`：JSON 数组 `[{id, backend}]`；
- `glthread_off`：JSON 字符串数组（glthread 关闭的**实例 id**）。

实例身份 = `versions/` 下的**目录名**（对齐 HMCL，见 `VersionScanner.GameVersion.id`），
而实例名**只在单个游戏目录内唯一**。用户可在两个不同的 `.minecraft` 根下各放一个名为 `1.21.10` 的实例
（或直接拷贝整份 `versions/` 过去）——此时两条记录**共用同一个 id 键**：

- 在一个根里开隔离 → 另一个根的同名实例**被顺带隔离**；
- 在一个根里改渲染后端 → 另一个根的同名实例**跟着变**；
- 删一个根的实例时，为免误删另一个根的设置，旧代码甚至要写"**elsewhere 判断**"
  （`state.dirs.some(...)` 看别的根是否还有同名实例）才决定清不清 Preferences —— 这个补丁本身就是撞键的证明。

### 1.2 跟随文件迁移

设置存在实例目录内，则：把 `versions/<id>/`（或整个 `.minecraft`）拷到另一台设备/另一个目录，
设置**随文件一起生效**；不需要"导出/导入配置"的额外机制。

### 1.3 选择：一个实例一个文件、一个文件装全部

对齐 HMCL 的"**一个存储域 = 一个带 `$schema` 的 JSON 文件**"思路，但用我们**自有**的
dot-dir 与 schema（见 §4 取舍）。

## 2. HMCL 对照事实（源码级）

> 以下为 `ref/HMCL`（现代重构版）的核对结论；仅作**概念参考**，落地为净室实现（HMCL 为 GPL-3.0）。
> 详细键清单与迁移机制见 [`../../10-research/hmcl-存储模型.md`](../../10-research/hmcl-存储模型.md) §6/§7。

| 事实 | 证据 |
|---|---|
| 每实例设置文件路径 = `<游戏目录>/versions/<id>/.hmcl/config/instance-game-settings.json` | `HMCL/game/HMCLGameRepositoryLayout.java:27/30/36/50-61`（文件名常量与 `getInstanceGameSettingsFile`；研究文档 §7.1 记为 `:26-62`） |
| 该文件 schema = `instance-game-settings/1.0.0`，`additionalProperties: true` | `docs/schemas/instance-game-settings/1.0.0.json` |
| **未知成员被保留**（前向兼容，不丢字段） | `JsonSettingFile.java:113-114`、`SimpleSettingProperty.java:62` |
| **隔离不是布尔**：= `overrideProperties` 集合是否含 `"runningDirectory"` + 该属性值 | `HMCL/setting/GameSettings.java:162-169,536-540`（`PROPERTY_RUNNING_DIRECTORY`） |
| 每实例只存"覆盖"，父预设给默认；"恢复继承"= 从白名单移除属性名 | `GameSettings.java:853-897`；UI 开关 = 增删 override（`GameSettingsPage.java:1726-1731`） |
| 图形后端是**另一个枚举轴**：`graphicsBackend` ∈ {DEFAULT, OPENGL, VULKAN} | `GameSettings.java:609` 附近的 `GraphicsBackend` 枚举 |

**关键差异**：HMCL 的 `graphicsBackend` 是 `DEFAULT/OPENGL/VULKAN`（桌面平台语境：默认/强制 OpenGL/强制 Vulkan），
与我们的后端轴（`auto` / `openglv4` / `gl4es`，见 `LaunchDefaults`）**不是同一维度** ⇒ 我们**不复用 `graphicsBackend` 键**，
而用自有键 `hmmcraftRendererBackend`；线程化渲染同理（HMCL 无对应键）用 `hmmcraftGlThreadEnabled`。

### 2.1 有意偏离 HMCL：**一个 mod loader 一个下载源**（决策记录 · 2026-09-30）

**HMCL 只有两个全局旋钮** —— `versionListSource`（版本列表）与 `fileDownloadSource`（文件），外加一个只给 addon 用的默认源 `defaultAddonSource`；一次 loader 安装的**整条链**（loader 版本列表、installer jar、loader 库，以及它顺带拉的 **vanilla 清单 / client jar / vanilla 库 / 资产**）**全走那同一个 file provider**。
证据：`ref/HMCL/HMCL/src/main/java/org/jackhuang/hmcl/setting/LauncherSettings.java:517-543`（三源字段）、`.../setting/DownloadProviders.java:70-85`（两源合成一个 `AutoDownloadProvider`）；下载任务 `ref/HMCL/HMCLCore/src/main/java/org/jackhuang/hmcl/download/forge/ForgeInstallTask.java:78-80`、`download/neoforge/NeoForgeInstallTask.java:69-72`、`download/fabric/FabricInstallTask.java:58,96`、`download/game/GameLibrariesTask.java:198-199`、`download/game/GameDownloadTask.java:71-84`（一律经 `getDownloadProvider().injectURL*(...)`）。

**我们有意偏离**：**每个 loader 各持一个下载源**（`fabricSource` / `forgeSource` / `neoForgeSource`），该 loader 的**整条安装链**（其制品 + 它拉的原版件）**都按这个 loader 自己的源**；共享的 `downloadSource` **只再管纯原版路径**。
**理由（面向用户清晰）**：Forge / NeoForge 的制品**不是 Mojang 提供**（分别来自 MinecraftForge / NeoForged），Fabric 早已有自己的源（见 [`Fabric安装-方案.md`](../../90-archive/Fabric安装-方案.md) §2）——把"loader 的源"与"原版的源"分开，用户不必为一个全程走镜像的 loader 去动版本源。
**与 HMCL 一致而被保留的部分**：**一个源管住一次安装的整条链（含它拉的原版件）**；差异只在隔离维度 —— HMCL 是 **列表 ↔ 文件**，我们是 **原版 ↔ loader**。

## 3. 选定格式

三类文件共用同一种约定：**plain JSON + `format: 1`**（不用 JSON Schema / `$schema`）+ **稀疏**（默认值不写、空组不写）
+ **写前底稿合并**（保留未知键）+ **写盘用 2 空格多行缩进**（`JSON.stringify(obj, null, 2)`，2026-09-15 用户要求：
文件是给人看/备份/手改的；格式化 JSON 仍是合法 JSON，`JSON.parse` 与平台 JSON 工具都认）。

### 3.1 实例设置文件

路径：`<gameRoot>/versions/<id>/.hmmcraft/instance-settings.json`

```json
{
  "format": 1,
  "overrideProperties": ["runningDirectory"],
  "runningDirectory": "versions/1.21.10",
  "hmmcraftRendererBackend": "auto",
  "hmmcraftGlThreadEnabled": true
}
```

- `format`：固定写 `1`（**plain JSON**，不用 JSON Schema；与全局设置文件同一约定）。早期形态的
  `$schema: "hmmcraft:instance-settings/1.0.0"` **已改为 `format`**：读时 `format` 缺失宽容按 1（旧 `$schema` 文件仍能读出），
  写时**显式移除**遗留 `$schema` 键。
- **隔离 = 对齐 HMCL 表示法**：开 → `overrideProperties` 含 `"runningDirectory"` 且
  `runningDirectory = "versions/<id>"`；关 → **两个键都不写**。
- `hmmcraftRendererBackend`：`auto` / `openglv4` / `gl4es`（用 `LaunchDefaults` 现有常量，不新造字面量）。
- `hmmcraftGlThreadEnabled`：boolean，默认 `true`。
- **稀疏**：值为默认（隔离**开** / 后端 `auto` / glthread 开）时不写该键；`format` 总写。

读取判定（`readInstanceSettings`）：文件缺失 / JSON 解析失败 / `format` 存在且 ≠1 → **默认值**
（隔离**开** / auto / glthread 开），**绝不回写覆盖坏文件**（只记日志）。
隔离三态：**无文件 → 默认（开）**；有文件含 `runningDirectory` → 开；有文件不含 → **显式关**。

写盘（`writeInstanceSettings`，**返回 `boolean`**）：`fileIo.mkdirSync(dir, true)` 建目录 → 先写**同目录**临时文件
`instance-settings.json.tmp` → **先尝试 `fileIo.renameSync(tmp, target)` 直接覆盖**（无空窗）；平台若不允覆盖
已存在目标，才 `unlink` 目标再 rename；**两步都失败则保留 `.tmp` 并记 error**（不静默丢弃）并返回 `false`
——调用方据此**不更新 UI 镜像**，改为从磁盘重读恢复真实值（**写失败绝不"撒谎"**）。
姿势对齐 `Downloader.ets:168-169` 与 `VersionInstaller.ets` 的 `ensureParent`/`writeText`。

### 3.2 全局设置（并入 `app-settings.json` 的 `global` 段）

路径：`<filesDir>/meow-settings/app-settings.json` 的 **`global` 段**（**应用级、全局唯一**；不再按游戏目录各一份、
也不再随游戏目录迁移——见 §3.3 同一文件）。
实现：`common/data/GlobalSettings.ets`（数据类 `GlobalSettings` + 归一化 `normalizeVersionType` / `normalizeSource` /
`normalizeRenderScale` / `normalizeCount` / `normalizeScrollSpeed` / `readLastLaunch` + `parseGlobalNode` / `buildGlobalNode`）；
文件级读写与 `global` 段接入在 `common/data/AppSettings.ets`
（`readAppGlobalSettings` / `tryReadAppGlobalSettings` / `writeAppGlobalSettings`），由 `SettingsTools`（公开 API 不变、仅换后端）承接。

```json
{ "format": 1,
  "dirs": [ { "uri": "…", "name": "…" } ],
  "selectedDir": "", "selectedAccount": "",
  "global": {
    "launcher": { "scrollSpeed": 100, "showInputRate": false, "versionType": "release",
                  "lastLaunch": { "dir": "<gameRootUri>", "version": "1.18.2", "jsonPath": "…" } },
    "runtime":  { "cpuCount": 0, "maxHeapMb": 0, "renderScale": 1, "renderEnv": "", "jvmArgs": "" },
    "network":  { "downloadSource": "mirror", "fabricSource": "mirror", "forgeSource": "mirror",
                  "neoForgeSource": "mirror", "msClientId": "" } } }
```

分组与字段（默认值即既有代码默认；**稀疏**：等于默认的键不写、空组不写）：

| 组 | 字段 | 语义 | 默认 |
|---|---|---|---|
| `launcher` | `scrollSpeed` | 滚轮速度百分比 | `100` |
| | `showInputRate` | 采样率 overlay | `false` |
| | `versionType` | 版本类型过滤（release / snapshot / other） | `release` |
| | `lastLaunch` | 上次启动 `{dir,version,jsonPath}` | 无（不写） |
| `runtime` | `cpuCount` | CPU 线程数覆盖 | `0`（自动） |
| | `maxHeapMb` | 最大堆 MB 覆盖 | `0`（自动） |
| | `renderScale` | 显示缩放 N（1/1.5/2/3/4） | `1` |
| | `renderEnv` | 额外渲染环境变量 | `""` |
| | `jvmArgs` | 额外 JVM 参数 | `""` |
| `network` | `downloadSource` | 版本下载源（mirror / official）—— **现仅管纯原版路径** | `mirror` |
| | `fabricSource` | Fabric loader 下载源（mirror / official） | `mirror` |
| | `forgeSource` | Forge loader 下载源（mirror / official） | `mirror` |
| | `neoForgeSource` | NeoForge loader 下载源（mirror / official） | `mirror` |
| | `msClientId` | 微软 client_id（用户自填） | `""` |

- **四个源的读写落点**：`SettingsTools.downloadSource/setDownloadSource`、`fabricSource/setFabricSource`、
  `forgeSource/setForgeSource`、`neoForgeSource/setNeoForgeSource`（**下载面板写、安装时读**）；UI 上 `downloadSource`
  在**纯原版**下载面板，`fabricSource` / `forgeSource` / `neoForgeSource` 在**各自 loader 的子面板**
  （`components/GameVersionsView.ets`）。**一 loader 一源**的理由与 HMCL 对照见 §2.1（有意偏离）。
- **plain JSON + `format: 1`**（`format` 由 `app-settings.json` 顶层承载，`global` 段自身不再带 `format`）。
  读：文件缺失 / JSON 坏 / `format` 存在且 ≠1 → **`null` / 默认值，且永不回写**；`format` 缺失 → 宽容按 1。
  写：`writeAppSettings` 以磁盘现有整文件 JSON 为底 merge，`global` 段由 `buildGlobalNode(data, 磁盘上的 global)` 同样**以底稿合并**
  （保留未知键 / 未知组）；枚举类取值（渲染缩放 / 下载源 / 版本类型）写前**夹到合法集合**。ArkTS 禁 `delete` ⇒ 用"赋 `undefined`
  让 `JSON.stringify` 省略"删键。落盘姿势同 §3.1（`.tmp` + 先试 `renameSync`）。
- **不迁移**（本轮彻底删除 Preferences 与其迁移代码）：原 `SettingsTools` 在 Preferences 的各键
  （`show_input_rate` / `cpu_count` / `max_heap_mb` / `scroll_speed` / `download_source` / `fabric_source` /
  `version_type` / `render_scale` / `render_env` / `jvm_args` / `ms_client_id` / `last_launch`）**不读不转写**，全部取默认；
  连"从 Preferences 读一次写入文件"的迁移分支与 `STORE_NAME` / `KEY_*` 常量也一并删除（开发阶段无历史包袱，用户已确认旧值丢弃、自行重填）。
- **全局唯一、无授权窗口**：文件在 `filesDir` 应用沙箱，App 启动即可读写，**没有**旧口径那种"文件在用户存储的游戏根里、
  目录授权随 App 退出失效 → 启动早期读失败"的问题。
- **缓存 / 跨进程**：`SettingsTools` 用**模块级缓存**（只缓存这一份全局对象）避免每个 getter 都读文件，写成功后更新；
  读不到时**不写缓存**（否则后续重读仍会命中默认值）。主进程（启动器）与 `:game` 进程都经 `common.Context.filesDir`
  读同一份文件（AppStorageV2 不跨进程）。**读不到用 `null` 表示**（`tryReadAppGlobalSettings`），与"读到了但内容是默认值"区分。
  守卫：`SettingsTools.update()` 在**读不到且文件已存在**（坏文件 / 异格式）时**拒绝写**，避免"以默认对象为起点 merge"
  把磁盘上其它键删掉（文件根本不存在＝首次写入才允许以默认值起底）。
  `SettingsTools.update()` 还在 mutate 之后、写盘之前调用 `GlobalSettings.normalizeGlobalSettings`（`GlobalSettings.ets`）
  ——缓存（写成功即缓存归一化后的对象）与磁盘（`buildGlobalNode` 同规则夹取）**恒一致**。

### 3.3 应用级设置也文件化（`filesDir/meow-settings/`）

**背景**：目录枚举、账户与全局设置都不属于任何单个游戏根（目录枚举是"解析游戏根"的前置，存进游戏根会循环；
账户与全局设置跨目录 / 全局唯一），所以它们**不去 `.hmmcraft/`**；也**不再留 Preferences**（用户 2026-09-15 决定
"全部搬成文件"），改存**应用沙箱**。实现：`common/data/AppSettings.ets`。

路径（`filesDir` 应用私有沙箱，**无需任何目录授权**）：

| 文件 | 形状 |
|---|---|
| `<filesDir>/meow-settings/app-settings.json` | `{ "format": 1, "dirs": [{"uri","name"}], "selectedDir": "", "selectedAccount": "", "global": { …见 §3.2… } }` |
| `<filesDir>/meow-settings/accounts.json` | `{ "format": 1, "accounts": [ …Account 原样（含微软 token）… ] }` |
| `<filesDir>/meow-settings/touch-controls.json` | `{ "format": 1, "touchAsMouse": true, "touchControls": false, "touchSensitivity": 128, "touchControlsScale": 100, "insetTop": 12, "insetRight": 12, "insetBottom": 12, "insetLeft": 12 }`（**扁平**，无嵌套段；2026-09-21 追加） |

- **plain JSON + `format: 1`**；读：文件缺失 / 坏 / `format` 存在且 ≠1 → **`null`**（与"读到但内容为空"
  区分，同 §3.2 的 `tryReadAppGlobalSettings` 语义；**空 / 纯空白文件按"缺失"处理**，同样返回 `null` 但语义=缺失、可写，
  不会把写入通道锁死）；写：**以磁盘现有 JSON 为底 merge 保留未知键**、
  `mkdirSync(dir, true)` → 写同目录 `.tmp` → 先试 `renameSync` 覆盖、不允覆盖才 `unlink` 再 rename、
  两步皆败保留 tmp 并记 error、返回 `boolean`。ArkTS 禁 `delete` ⇒ 赋 `undefined` 让 `stringify` 省略。
  存在性判定 `appSettingsFileExists` / `accountsFileExists` 与此口径一致（**空 / 纯空白文件视作不存在**）。
- **写入起点的三分支（`loadAppSettingsOrDefault`，给"目录/账户首次写入"用）**——这是对上面"读不到返回 `null`"的**例外**：
  文件**缺失**（含空 / 纯空白）→ 返回**空设置**、可安全作为写入起点；**存在但读不出**（坏 / 异格式）→ 返回 `null`
  （拒写护栏，绝不以默认对象为起点 merge 而删掉磁盘未知键）；读得出 → 原样返回。
- **`global` 段与目录/账户同处 `app-settings.json`**：`writeAppSettings` 一次写入 `dirs` / `selectedDir` / `selectedAccount` / `global`
  （四者互为底稿合并，互不覆盖未知键）；`GlobalSettings.ets` 只负责 `global` 段的数据类与解析/组装，文件级读写在 `AppSettings.ets`。
- **`selectedAccount` 是指针，跟 `app-settings.json` 走**；账户本体与凭据单独一份 `accounts.json`（用户决定）。
  `GameDirsTools` 读写 `app-settings.json`；`AccountsTools` 列表读写 `accounts.json`、选中项读写 `app-settings.json`。
  **两者公开 API 不变**，所有调用点零改动。
- **无授权窗口**：文件在 `filesDir` 沙箱，App 启动即可读写，**没有**旧全局口径那种"目录授权随退出失效 →
  启动早期读失败"的问题；代价是**外部不可见**（其他应用 / 文件管理器都读不到），故需导出入口（下条）。
- **不迁移（本轮彻底删除 Preferences）**：旧 Preferences 键（目录 / 账户 / 全局设置）**一概不读不转写**；
  连 `loadAppSettings` / `loadAccounts` 里"文件缺失时从 Preferences 迁移"的分支、`migratedFrom` 标记与
  `STORE_NAME` / `KEY_*` 常量也一并删除。`loadAppSettings` / `loadAccounts` 退化为"读文件，读不到返回 `null`"。
  **已迁过的文件里可能残留 `"migratedFrom": "preferences"`**：代码已无任何读取点 ⇒ **纯死字段，可忽略**；
  写盘是"以磁盘为底 merge、保留未知键"，故它**不会自愈** ⇒ 想清掉就**直接改文件删掉那一行**
  （用户 2026-09-15 明确：**不为一次性残留加清理代码**，保持实现干净）。
  理由（用户 2026-09-15 二次决策）：应用仍在开发阶段、**无历史包袱**，追求干净实现；旧值用户已知会丢、自行重填。
- **导出入口**：「高级选项」区最下面「导出设置」（`AdvancedOptionsView`）—— 它导出的正是应用级数据（目录 + 账户 + 高级选项）。
  流程：`pickDirectory` 选目标目录 → `authorizeDirectory` 授权一次（**一次性导出不持久化授权**）→ `exportSettings` 按
  **原文读取 → 解析 → 多行写出**（`writeJsonAtomic`，2 空格缩进，未知键原样保留）把
  `app-settings.json`（含 `global` 段）+ `accounts.json` 写到目标下的 `meow-settings-backup-<yyyyMMdd-HHmmss>/` 子目录
  （避免覆盖）→ 成功提示里显示路径。**单份缺失或解析失败 → 跳过该份**（返回 `{outDir, skipped}`；`skipped` 只列
  "存在但读不出"的文件，调用方弹「部分内容无法读取，已跳过」提示；**两份皆缺 / 皆败 → 整体失败**）；
  **授权失败 / 写失败 → 弹 `settings_export_failed`**；**仅用户取消选目录才静默**。
  **导出前必须 `UIContext.showAlertDialog` 确认**，文案明确提示
  **包含微软登录凭据（access/refresh token）、请勿分享**；不崩。
- **第三个文件：触控设置 `touch-controls.json`（2026-09-21 追加）**：与上两文件同处 `<filesDir>/meow-settings/`，
  装**触控 8 项**（`touchAsMouse` / `touchControls` / `touchSensitivity` / `touchControlsScale` / `insetTop` / `insetRight` /
  `insetBottom` / `insetLeft`），**扁平** JSON + `format: 1`（键在顶层、无嵌套段）；写回**以磁盘现文件为底保留未知字段**、
  **文件不存在即写一份默认**、**解析不了先把原文件备份成 `.bad` 再用默认**（备份逻辑 `backupBadTouchFile`）。
  **生效时机 = 开窗生效**（模块级缓存不失效）；缓存与旧值迁移的定案见
  [`../../00-current/已知限制与待解.md`](../../00-current/已知限制与待解.md) **§B6**。落地：`common/constants/Paths.ets`、
  `common/data/SettingsTools.ets`、`common/data/AppSettings.ets`（导出/备份已包含该文件）。

## 4. 明确的取舍

1. **自有 `.hmmcraft` dot-dir，不做 `.hmcl` 互操作**：我们不去读写 HMCL 的
   `versions/<id>/.hmcl/config/instance-game-settings.json`。理由：HMCL 为 GPL-3.0，且其键集/语义
   （预设继承、`graphicsBackend` 枚举）与我们的后端轴不同；读它要承担 schema 与许可负担。
   我们**只对齐"隔离 = overrideProperties + runningDirectory"这一表示法**（概念，非代码）。
2. **不做迁移**：旧 `Preferences` 三键直接弃用，不读、不转写。理由：旧键只按 id 存，本身就有撞键歧义，
   无法可靠映射回"哪个根下的哪个实例"；宁可一次干净切换。
3. **保留未知键（对齐 HMCL 的实践）**：写入以**磁盘现有 JSON 为底 merge** —— 只改我们认识的键，
   未知成员**原样保留**；`overrideProperties` 里 `runningDirectory` **之外**的项也保留（将来加字段 /
   跨版本共存不丢数据）。实现细节：ArkTS 禁用 `delete`，故用「赋 `undefined` 后 `JSON.stringify` 自动省略」
   实现"删键"（写入前把后端取值夹到合法集合，非法值按 `auto` 处理）。
4. **默认值硬化**：任何异常（缺失/坏文件/`format` 不认）都退默认、不回写——避免"读崩了反而把用户文件清空"。
5. **隔离默认开（2026-09-15 用户定）**：早期曾走"默认关 + 安装后自动开"，改为**默认开**后，升级时既有实例不会因
   "没有文件"而回落到共享根，从而少一类"存档看似不见"。代价是对称的另一面：**不是**本启动器装的、或手工拷进
   `versions/` 的版本目录也会按隔离跑——它们看不到共享根里的 `mods/`、`saves/`（对这些实例手动关隔离即可）。
   参考 HMCL：它不是裸默认开，而是全局策略 `defaultIsolationType ∈ ALWAYS|MODDED|NEVER`（默认 `MODDED` = 仅带
   modloader 的实例在创建时隔离）；我们取更宽的"默认开"，将来若要精细策略，`GameVersion.loader`/`form` 已有现成判定可用。
6. **全局设置并入应用级文件、不迁移**（见 §3.2）：旧全局键直接弃用、不转写；`global` 段形态与实例文件统一为
   **plain JSON + `format: 1`**，落盘姿势复用（`.tmp` + 先试 `renameSync`），**应用级全局唯一**（不再按游戏根各一份）。
7. **应用级设置"存沙箱文件、不迁移"**（见 §3.3）：目录 / 账户 / 全局设置旧键**全部弃用、不转写**，连迁移代码一并删除；
   沙箱外部不可见，补「导出设置」入口取出口。与 ①② 的差别只在"存在哪"：① 存实例目录，②③ 存应用沙箱。

## 5. 已知后果

- **既有实例的旧设置丢失（一次性）**：升级后旧 Preferences 键不再被读，所有既有实例**取默认**
  （隔离**开** / auto / glthread 开）。影响分两侧：
  - **原先开着隔离的实例**（本启动器安装的，数据本就在 `versions/<id>/`）→ 行为不变，**照常可玩** ✅；
  - **原先没开隔离的实例**（数据在共享根，含手工放入的 `mods/`、`saves/`）→ 现在按隔离跑，会去
    `versions/<id>/` 找运行目录，**共享根里的东西对它"看似不见"**（文件都在，没动）。
  - 这与 [`决策与不变量.md`](决策与不变量.md) §11
    「未做/待办 · 世界迁移提示」**同因**：隔离切换（开↔关）时，另一侧目录里的存档**不会自动迁移**，
    只是本次"切换"是升级**隐式**触发的。
  - 用户恢复手段：**关掉**该实例的隔离即回到共享根（数据一直未动）；或把 `versions/<id>/saves/`
    与根 `saves/` 手工对齐。
- **无孤儿键**：设置随实例目录删除，删实例后不会残留按 id 的配置项。
- **同名实例不再串**：跨根同名实例各读各的 `.hmmcraft`，旧 `elsewhere` 特判**已删除**。
- **旧的全局设置丢失（一次性，同因）**：升级后原 Preferences 里高级选项（采样率 overlay / CPU 线程数 / 最大内存 /
  滚轮速度 / 显示缩放）、下载源 / loader 源 / 版本类型 / client_id / "上次启动"**全部回默认**。本轮**连 Preferences 读取与
  迁移代码一并删除**（不做任何转写）；旧值用户已知会丢、自行重填。
- **全局设置不再按目录隔离**：现为**应用级全局唯一**——切游戏目录**不再切换另一份**，也不再有旧口径那种
  "文件在用户存储的游戏根、启动早期目录未授权 → 读失败 → 选项全空"的窗口（文件在 `filesDir` 沙箱，App 启动即可读写）。
- **"继续上次"跨目录语义**：`lastLaunch` 记录 `{dir, version, jsonPath}`，仍能直接重开记录里那个版本；
  删版本时 `clearLastLaunchIf(dir, version)` **同时匹配目录与版本**，避免误清另一目录下的同名实例。

## 6. 保留的行为

- **新装默认隔离**（2026-09-13 起，对齐 HMCL 安装期 `enableIsolation()`）：安装完成后立即
  用 `writeInstanceSettings(root, <实例名>, isolation=true)` 写入实例文件（原版 / Fabric 两条安装路径一致）。
- **隔离只切"运行目录"一个变量**：`assets/` / `libraries/` 仍共享，不随隔离移动（见 §11 关键点）。
- **游戏进程读取口径**：`GameLauncher`（`:game` 进程）按 `gameRoot + versionId` 读**实例文件**（逐版本设置），
  并按 `ctx.filesDir` 经 `readAppGlobalSettings(ctx)` 读**应用级全局设置**（与主进程同一份 `app-settings.json`）；
  `renderer.env === RENDERER_ENV` 门控与 `guardNeedsSync` 逻辑保持。
- **「高级选项」区顶部有"作用域"提示**（2026-09-15 按用户要求加；同日一度改名「游戏目录高级选项」并带当前目录昵称，
  后随全局设置应用级化**改回「高级选项」**）：文案说明本区选项**对整个启动器生效**、存在应用私有目录、可用「导出设置」带走
  （`advanced_scope_hint`）；**不**再提"按游戏目录各存一份 / 随目录迁移 / 目录昵称"。
  **别当冗余文案删掉**——用户明确要求"在高级选项区域提到一嘴"。
- **锚点纪律（2026-09-15 复核后加固）**：列表镜像（隔离 / 后端 / glthread）**归 `LauncherState` 统一持有**，
  在 `refreshVersions()` 里**一次遍历、每实例只读一次**文件重建；**编辑面板的读与写一律以面板锚定的
  `editingRoot` 为准**（缓存 `editingSettings`），仅当 `editingDirUri === state.selected` 时才顺带刷镜像。
  ⇒ 杜绝"面板停在 A 目录却读写 B 目录镜像"这类跨目录串扰（与 §1.1 的编辑态串行 bug 同源）。
- **「导出设置」入口别当冗余删掉**（2026-09-15 按用户要求加）：应用级设置存 `filesDir` 沙箱后**外部不可见**，
  用户要靠这个入口把 `app-settings.json` + `accounts.json` 导出到自己选的目录。它挂在**「高级选项」区最下面**
  （同日从目录区移来 —— 高级选项区本就是"应用级设置"区，语义最近），导出前有**含微软凭据的确认弹窗**（见 §3.3）。
  看起来"只是个复制按钮"，但它是沙箱数据唯一的取出口。
