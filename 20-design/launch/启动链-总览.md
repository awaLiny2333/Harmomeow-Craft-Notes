## 0. 总纲：三条「切轴」+ 三个「分流问题」

### 0.1 三条切轴（同一份启动代码按三条轴分流）

| 轴 | 切点 | 切点两侧 |
|---|---|---|
| **LWJGL 代** | **1.13** | ≤1.12.2：MC 自带 LWJGL2 + 自编 `liblwjgl.so`；≥1.13：**随包单代 3.4.3**（overlay 带 3.4.x 兼容 shim 服务 1.13.x–26.x） |
| **GL 后端** | **1.17** | ≤1.16：固定管线 ⇒ **gl4es（FPE）**；≥1.17：core 渲染器 ⇒ 有系统桌面 GL 的设备走桌面 GL，无桌面 GL 的设备走 **gl4es core**（`MEOW_GL3`） |
| **窗口/渲染层** | **26.3** | ≤26.2 走 GLFW 路径；≥26.3 走 **SDL3**（见 [`../render/SDL3适配-复盘.md`](../render/SDL3适配-复盘.md) 与 [`决策与不变量.md`](决策与不变量.md) §13.1） |

三轴都**按"解析后的真 MC 版本号"判**（`MinecraftLauncher.readVersionId` 的产出），**不是实例名/目录名** —— Fabric 实例的目录名与 json `id` 都不是 MC 版本号。落点见 §6。

### 0.2 三个分流问题（决定 loader 侧怎么处理）

| # | 问题 | 判据函数 / 常量 | 结论 |
|---|---|---|---|
| ① | 要不要**真 maven 树** classpath？ | `MinecraftLauncher.needsRealClasspath` + `LaunchContract.REAL_CLASSPATH_MAIN_CLASSES`（另有 `loader === neoforge` 兜底） | 按**启动形态主类**判：Forge ≥1.13 三代 + NeoForge 走 `real-tree`；legacy 走 `ordered`；vanilla / Fabric 走 `flat` |
| ② | 要不要自研 system CL / 经一层 Java 启动器？ | `MinecraftLauncher.buildLaunchArgv` | **已取消** —— **一律直启 `json.mainClass`、恒不设 `-Djava.system.class.loader`** |
| ③ | 哪个 JRE 档？ | `JavaPolicy.requirementFor`（表 A「段→约束」× 表 B `JavaRuntime.BUNDLED_RUNTIMES`） | 见 §5 与 [`环境与载体.md`](环境与载体.md)；无规则命中的组合一律「取最新」= 现代套 26 |

> 设计用心：三个问题**各自一个判据**，且都**按形态（主类 / form）判**，不按 loader 名或版本号字符串 —— 这族实例可能是薄 `inheritsFrom`、`detectLoader` 认不出，但主类稳定。病根正是"同一判据散成两处布尔"。

### 0.3 两个「另起 JVM / 加载器」的必备项

1. **平台伪装**：任何**另起 JVM**（安装期工具 JVM / 各子进程）都必须带 `LaunchDefaults.TOOL_JVM_PLATFORM_SPOOF_ARGS`（= `-Dos.name=${SPOOF_OS_NAME}` + `-Dos.version=${SPOOF_OS_VERSION}`，紧随 `java` 之后）；游戏路径同源（`buildLaunchArgv` 的"固定 JVM 参数"段也 push 同一对 `-Dos.*`）。**为什么**见 [`决策与不变量.md`](决策与不变量.md) §25。
2. **强封装参数由 json 给、原样透传**：`--add-opens` / `--add-exports` / `--add-modules` / `-p`（module path）全部来自版本 json 的 `arguments.jvm`，`buildLaunchArgv` 只做规则过滤 + `${...}` 宏替换，**不自造**。

### 0.4 桌面基线（我们要复刻什么）

桌面启动 = `java -cp <版本 jar + 全部 libraries> <mainClass> <游戏参数>`，进程内**真实 GLFW + 桌面 OpenGL 上下文**，无任何代理。对照基线（1.21.10 真件）见 [`../../90-archive/桌面标准启动链路-对照.md`](../../90-archive/桌面标准启动链路-对照.md)。对本工程的含义：**游戏主类 / 参数 / 库解析全部与平台无关**（只要 JVM 能跑 + `os.name` 伪装 `Linux`）；被"卡住"的只有三处 = **JRE**（arm64 + 足够新的 class）、**GLFW**（桌面 `libglfw.so` 不可用，需 stub / 真 SDL3）、**桌面 OpenGL**（鸿蒙只有 GLES/Vulkan，需翻译）。

## 2. Forge（四代）

> 主类随代际变化；应用内安装判型只认 `install_profile.json` 的**形态键**，MC 版本号不参与判型（`VersionInstaller.classifyForgeProfile` + `forgeClientProcessorCount`）。

### 2.0 逐代表（先看这张）

| 世代 | MC 段 | 主类 | classpath | JRE 档 | `-p` | 安装方式 | 关键坑 |
|---|---|---|---|---|---|---|---|
| **legacy** | ≤1.12.2 | `net.minecraft.launchwrapper.Launch` | **`ordered`（清单顺序绝对路径 + 实例 jar）** | **强制 ≤8** | 无 | **零 JVM**（`classifyForgeProfile` = `legacy` / `spec-no-processor`） | `--tweakClass` 体系 |
| **①** | 1.13–1.16.5 | `cpw.mods.modlauncher.Launcher` | **`real-tree`（充要）** | **8**（`max17 prefer8`） | 无 | processor 链 | `Missing forge!` |
| **②** | 1.17.1–1.20.1 | `cpw.mods.bootstraplauncher.BootstrapLauncher` | **`real-tree`** | **26**（无 17 档） | 有 | processor 链 | 反射被模块系统拒 → 直启 |
| **③** | ≥1.20.3（含 1.20.3 / 1.20.4 / 1.20.6 / 1.21.1 / 26.3） | `net.minecraftforge.bootstrap.ForgeBootstrap` | `real-tree` | 26 | 无 | **应用内安装未适配**（政策范围外） | 见 2.4 |

> **世代 ②→③ 切点 = 1.20.2 → 1.20.3**：1.20.2 的主类是 `net.minecraftforge.bootstrap.BootstrapLauncher`（**不在** `REAL_CLASSPATH_MAIN_CLASSES` 清单里），1.20.3+ 才是 `ForgeBootstrap`。
> **所有世代一律直启 `json.mainClass`、恒不设 `-Djava.system.class.loader`**；legacy 走 `ordered` 显式有序绝对路径（`assembleRealTreeClasspath` + `launchWrapperOptifineOrder`）。

### 2.1 legacy（≤1.12.2）

- **主类** `net.minecraft.launchwrapper.Launch`（`MinecraftLauncher.LAUNCHWRAPPER_MAIN` / `isLaunchWrapperMain`）；用 `minecraftArguments` + `--tweakClass`。
- **classpath = `ordered` 显式有序绝对路径**：`assembleRealTreeClasspath` 按**清单顺序**逐条绝对路径 + 实例 jar（OptiFine 置末、丢 `optifine:launchwrapper-of`）。**根因** = 通配 `<dir>/*` 的展开序 = 文件系统 `readdir`，OptiFine 的 `TRSRTransformation` 空壳可能先于 Forge 本体命中 ⇒ `NoSuchMethodError`。
- **直启、不设 system CL**：`Launch.<init>` 的 `(URLClassLoader) getClassLoader()` 强转**只在 Java 8 档**跑这类实例，而 JDK 8 的 app classloader 本身就是 `URLClassLoader` 子类 ⇒ 强转原生成立、**不需要**换系统 CL；`LaunchClassLoader` 的委派父指向"定义 `Launch` 的那个 CL" ⇒ tweaker 实现类与 `net.minecraft.launchwrapper.ITweaker` **同源** ⇒ 单一 CL 下无 CCE / 无 CNFE。
- **JRE 强制 ≤8**（`JavaPolicy.requirementFor` 的 `forge ≤1.12.999 → (0, 8, 8)`）：`java.util.jar.Pack200` 已在 JDK 14 删除、`SecurityManager` 已在 JDK 24 禁用 ⇒ 结构性不可启动。
- LWJGL debug 开关**默认不设（= 关）**：`org.lwjgl.util.Debug=true` 会开启 LWJGL 的额外运行期检查并刷诊断；legacy 也必须保持关 —— LWJGL2 的 `LWJGLUtil.DEBUG` 门控 `Display.swapBuffers` 的"交换前 `glGetError`"，会把 gl4es 的良性 GL 错误变成致命 `OpenGLException`。

### 2.2 ①（1.13–1.16.5）

- **主类** `cpw.mods.modlauncher.Launcher`。
- **`real-tree`（充要）**：FML 的 `LibraryFinder.findLibsPath()` 取 `ClassLoader.getResource("org/objectweb/asm/Opcodes.class")` 得到 **ASM jar 路径**后连续 `getParent()` **×6** 当作 `libraries` 根，再拼 `net/minecraftforge/forge/<ver>/forge-<ver>-universal.jar` 只做 `Files.exists` 校验（`FMLCommonLaunchHandler.validatePaths`）。平铺目录里 ASM 落在任意深度 ⇒ 上溯 6 级落到**别的目录** ⇒ fatal `Missing forge!`（jar 其实在盘上）。FML **不读任何 `-D`**、也不扫 `java.class.path` ⇒ 换任何深度的平铺都只会错成另一个值。
- 直启、不设 system CL；**无 `-p`**（该代 json 无 module path）。
- **JRE 落 8**（`1.13–1.16.999 → (0, 17, 8)`，preferred = 8 ⇒ pickBest 选 8）。
- GL：gl4es **FPE**（该段 ≤1.16）。

### 2.3 ②（1.17.1–1.20.1）

- **主类** `cpw.mods.bootstraplauncher.BootstrapLauncher`。
- **`real-tree` + 直启**。**为什么直启**：老 `bootstraplauncher`（0.1.17 / 1.0.0）的 `module-info` **一个包都不导出** ⇒ 从无名模块反射调用会被 Java 9+ 模块系统拒（`IllegalAccessException … does not export … to unnamed module`）。NeoForge 一直直启、从未踩此坑 ⇒ 让 Forge ≥1.13 与它同口径。
- `-p` / `--add-modules` / `-DignoreList` / `-DmergeModules` / `-DlibraryDirectory` **由 json 给、原样透传**。
- **JRE 落 26**：`1.17–1.20.4 → (16, 0, 17)`（preferred 17），而随包只有 26 与 8（8 < min 16 不满足）⇒ 选 26。**没有 17 档**（见 [`环境与载体.md`](环境与载体.md)）。
- **1.19.x 需要 ASM 替换**：`org.objectweb.asm` 9.7.1 读不懂 JDK 26 的类文件（`major 70`），modlauncher 10.0.8 的 `ClassTransformer.transform → computeHierarchyFromFile` 抛 `Unsupported class file major version 70`。判据 = `MinecraftLauncher.needsAsmOverride`（**modlauncher ≥ 10 且声明 ASM 能力 < 当前 JRE class major**）。随包 ASM 9.9.1 落在 `<cache>/mc-cp/<key>-<id>/asm9/`（**子目录**不平铺），`rewriteAsmList` **同时改写 `-cp` 与 `-p`** 且不残留旧套。分界：1.17.1(ML 9.0.7)/1.18.2(ML 9.1.3)/1.20.1(ML 10.0.9 但 ASM 9.9.1) **不触发**；1.19.4(ML 10.0.8 + ASM 9.7.1) **触发**。见 [`环境与载体.md`](环境与载体.md) §5。
- **NeoForge 同形态但刻意不替换**：`needsAsmOverride` 对 `looksLikeNeoForge` 一律返回 false（其 `-DignoreList` 按**带版本文件名**点名 ASM ⇒ 改名会静默脱靶）。

### 2.4 ③（≥1.20.3；1.20.2 为过渡）

- **`real-tree` + 直启**。
- **政策上范围外**（支持面截至 1.20.1）。**但这是政策、不是技术必然**：直启加载器主类后随包 `launcher.jar` 桩件不进 classpath ⇒ `com.mojang.text2speech` 只剩真实库一个提供者 ⇒ 模块化撞包消除（`ResolutionException` 不再出现）。**应用内安装未适配**：③ 代另有 `hideExtract` / `serverJarPath` / `path` 带 `:shim` 三项形态差异（见 [`安装链-总览.md`](安装链-总览.md)）。

## 3. NeoForge（仅 MC 1.20.2+）

| 项 | 结论 | 为什么 / 证据 |
|---|---|---|
| **主类两代** | `cpw.mods.bootstraplauncher.BootstrapLauncher`（≤1.21.x）→ `net.neoforged.fml.startup.Client`（26.x） | `stuffs/research/neoforge/extracted/*.version.json` |
| **classpath** | **`real-tree`** | `needsRealClasspath`：主类命中 `REAL_CLASSPATH_MAIN_CLASSES`（含 `fml.startup.Client`），**另有 `loader === neoforge` 兜底** —— 兜底理由：NeoForge 演进快、主类会改，classpath 形态不得掉回平铺 |
| **直启 / system CL** | **一律直启**；**不设** system CL | 这族自带模块层 / 类加载体系；设 `-Djava.system.class.loader` 会在 JVM 启动期 `Class.forName` 直接 ClassNotFound |
| **JRE** | 无分段 ⇒ **26** | `requirementFor` 返回 null |
| **`--add-opens/--add-exports`** | 由 json 给、原样透传 | 同 §0.3 |
| **应用内安装** | 它自己的链（`installNeoForgeVersion` + `runNeoForgeProcessors` + `:neoinstall` 无窗载体） | 与 Forge 的链**代码独立**（方案 B，见 [`安装链-总览.md`](安装链-总览.md)） |

**与 Forge ② 的关系**：**同主类、同 classpath 形态**（都走 `BootstrapLauncher` / `real-tree`），但**安装链**与**"是否 ASM 替换"**是分开的：**安装办法分开**（方案 B，隔离风险）；**ASM 替换分开**（NeoForge 从不替换，其 `-DignoreList` 按带版本文件名点名）。

## 4. Fabric / Legacy Fabric

| 项 | 结论 | 为什么 / 证据 |
|---|---|---|
| **主类** | `net.fabricmc.loader.impl.launch.knot.KnotClient`（来自 Fabric meta `launcherMeta.mainClass.client`；`VersionInstaller.fabricMainClass`） | 见 [`Fabric支持-调研.md`](Fabric支持-调研.md) §4.1 |
| **classpath** | **`flat`（平铺）** | `needsRealClasspath` 为 false（主类不在清单、`loader` 非 neoforge）；Fabric 的 loader 自行处理 classpath 追加 |
| **直启 / system CL** | 直启 `KnotClient`；**不设** system CL | Knot 要求 loader 类由**父加载器**持有；自设 system CL 会破坏该契约 |
| **JRE** | 无约束 ⇒ **26** | `requirementFor` 返回 null |
| **应用内安装** | `installFabricVersion` + **每 loader 独立下载源** `fabricSource` | 整条链按 Fabric 自己的源（vanilla 件也不走版本源，对齐 HMCL） |

**两形态（磁盘上）**：**形态①** = 官方安装器 `inheritsFrom`（子版本靠继承合并父版本）；**形态②** = HMCL `patches[]` 补丁式单实例（顶层扁平化 + 为实例复制 `<id>.jar`）。启动侧由 `VersionResolver` 把两形态归一成同一"有效清单"（只读顶层字段）⇒ 两种形态等同处理。

## 5. 总表（核心）

| 类型 | 主类 | classpath 形态 | JRE 档 | LWJGL 代 | GL 后端 | 需 ASM 替换 | 安装方式 | 范围 / 政策备注 |
|---|---|---|---|---|---|---|---|---|
| **vanilla** | `net.minecraft.client.main.Main` | `flat` | 26（无约束） | ≤1.12.2=LWJGL2；≥1.13=3.4.3 | ≤1.16=gl4es FPE；≥1.17=桌面 GL / gl4es core | 否 | 4 类文件 + 严格复刻 HMCL | 全窗口 1.6.x–26.x |
| **legacy Forge**（≤1.12.2） | `net.minecraft.launchwrapper.Launch` | **`ordered`** | **8（强制 ≤8）** | LWJGL2 | gl4es FPE | 否 | **零 JVM** | 已支持 |
| **Forge ①**（1.13–1.16.5） | `cpw.mods.modlauncher.Launcher` | **`real-tree`** | **8**（max17 prefer8） | 3.4.3 | gl4es FPE | 否（ML < 10） | processor 链 | 已支持 |
| **Forge ②**（1.17.1–1.20.1） | `cpw.mods.bootstraplauncher.BootstrapLauncher` | **`real-tree`** | **26**（无 17 档） | 3.4.3 | ≥1.17 桌面 GL / gl4es core | **1.19.x 需**（ML≥10） | processor 链 | 已支持 |
| **Forge ③**（≥1.20.3） | `net.minecraftforge.bootstrap.ForgeBootstrap` | （`real-tree`） | 26 | 3.4.3 | 同上 | 否 | 未适配 | **政策范围外**（启动侧实测可用） |
| **NeoForge**（1.20.2+） | `BootstrapLauncher`（≤1.21.x）→ `fml.startup.Client`（26.x） | **`real-tree`** | 26（无约束） | 3.4.3 | 同上 | **不替换**（`-DignoreList` 点名） | 它自己的链 | 仅 1.20.2+ |
| **Fabric / Legacy Fabric** | `net.fabricmc.loader.impl.launch.knot.KnotClient` | `flat` | 26（无约束） | 3.4.3 | 同上 | 否 | `installFabricVersion` + `fabricSource` | Fabric / Legacy Fabric |

> **所有形态一律直启 `json.mainClass`、恒不设 `-Djava.system.class.loader`**。

### 为什么这么切（把三轴与三个分流问题串起来）

1. **classpath 形态 = 加载器**能不能**按自身 jar 位置反推 maven 根**：Forge ①（`Launcher` 上溯 6 级找 `:universal`）**必须** `real-tree`；②③ 的 `-p`/`-DignoreList`/`-DmergeModules` 需要真实、稳定、有序的条目集合；launchwrapper（legacy）走 `ordered`（通配没有顺序语义）；vanilla/Fabric 仍走 `flat`。
2. **要不要自研 system CL = 加载器**是否要求 classpath 里有一个 **URLClassLoader 子类**。launchwrapper 的强转只在 **Java 8 档**出现 ⇒ **无需换 CL**；其余一律直启 `json.mainClass` + 不设 system CL。
3. **JRE 档 = 加载器对 JDK 的硬依赖**：legacy 卡 `Pack200`/`SecurityManager`（≤8）；① 偏好 Java 8；②③/NeoForge/Fabric/vanilla 在"只有 26 与 8"的供给下取 26。
4. **三条切轴彼此独立、切点不同**：LWJGL 切 **1.13**、GL 切 **1.17**、窗口层切 **26.3**。
5. **政策 ≠ 技术**：Forge ③ 的"范围外"是**政策选择**（支持面截至 1.20.1），技术上启动侧在直启实现下已可用。

## 6. 判据与落点索引（让人能改）

| 判据 / 常量 | 落在哪个 文件 + 函数/常量名 |

## 7. 常见误判速查

| 现象（稳定英文诊断串） | 判读 | 该去哪条轴 |
|---|---|---|
| `Missing forge!`（jar 其实在盘上） | Forge ① 被喂了**平铺** classpath ⇒ FML 上溯 6 级算错 maven 根 | classpath 形态（`needsRealClasspath`）—— 应走 `real-tree` |
| `IllegalAccessException … does not export … to unnamed module` | 从**无名模块**反射调用"有模块"的加载器主类 | 直启加载器主类（全形态一律直启） |
| `Unsupported class file major version 70` | 声明 ASM 太老（典型 = Forge 1.19.x）读不懂 JDK 26 的类文件 | ASM 替换（`needsAsmOverride`） |
| `AssertionError: Platform not recognized` / `A JNI error has occurred`（另起 JVM 时） | 工具/子进程 JVM 漏了平台伪装（JDK 8 按 `os.name` 精确匹配） | 平台伪装（`TOOL_JVM_PLATFORM_SPOOF_ARGS`，见 [`决策与不变量.md`](决策与不变量.md) §25） |
| `ResolutionException … export package com.mojang.text2speech` | 随包 `launcher.jar` 桩件进了**会被模块解析**的 classpath | 桩件已退役 —— 不再进任何 classpath |
| `Duplicate key …/failureaccess-1.0.1.jar`（NeoForge） | 真树 classpath 里**同一绝对路径**出现两次 | 真树去重（`assembleRealTreeClasspath` 按**绝对路径**去重，**不可**按 artifact 名去重） |
