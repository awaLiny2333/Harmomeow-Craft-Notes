# 安装链总览：原版 / Fabric / Forge / NeoForge 应用内安装

> **术语定义见 [`术语与定义.md`](术语与定义.md)**（`processor` / `spec` / `outputs` 幂等 / 占位符展开 / ZIP 结构降级 … 等专业名词的唯一权威）。
> **用途**：一页看明白四类实例"应用内装"的**入口 / 判型 / 产物形态 / 幂等 / 失败诊断**。
> **边界**：本文只写现行"安装路由 / 契约"。**启动路由**见 [`启动链-总览.md`](启动链-总览.md)；**定案与不变量**见 [`决策与不变量.md`](决策与不变量.md)；
> **JRE / 工具 JVM 载体 / 平台伪装 / ASM**见 [`环境与载体.md`](环境与载体.md)；活状态见 [`../../00-current/现状基线.md`](../../00-current/现状基线.md)。
> **代码路径相对 `Harmomeow-Craft-Launcher/`；只引符号名（文件 / 函数 / 常量），不写行号。**
> 真件取证：工作区根 `stuffs/research/{forge-support,neoforge}/**`。

## 0. 四条链（先看这张）

| 链 | 判型 / 入口 | 是否需要 JVM | 产物 |
|---|---|---|---|
| **vanilla** | `VersionInstaller.installVersion`（远程版本列表 → 选一个） | 否 | `versions/<id>/{<id>.json,<id>.jar}` + 共享 `libraries/**` + `assets/**` |
| **Fabric** | `VersionInstaller.installFabricVersion`（选 loader 版本 + 独立源 `fabricSource`） | 否 | 同 vanilla（顶层扁平化 + `patches[game,fabric]`） |
| **Forge** | `VersionInstaller.installForgeVersion` → 判型（`classifyForgeProfile`） | **看判型** | 零 JVM 子形态：纯解包 / 纯复制；processor 子形态：`installForgeNewVersion` + `ForgeNewInstaller` |
| **NeoForge** | `VersionInstaller.installNeoForgeVersion` + `NeoForgeInstaller`（仅 MC 1.20.2+） | 是（≥1.20.2 恒需 processor） | 同 vanilla（顶层扁平化 + `patches[game,neoforge]`） |

- **所有链都只写两处**：实例目录 `versions/<id>/**` 与共享池 `libraries/**`（+ assets）—— **不把我们的私有状态写进游戏目录**；我们的状态放 `<gameRoot>/versions/<id>/.hmmcraft/`（见 [`决策与不变量.md`](决策与不变量.md) §0.1 与 §11）。
- **不引入 `launcher_profiles.json` 前置**：那是**官方 installer 的前置**，HMCL 式自研安装不需要。
- **失败即中止**（比 HMCL 的"libraries/assets 非致命"更严格，便于用户重试；重试幂等）；半装实例只清**本实例**目录。

## 1. 原版（vanilla）

**填 4 类文件 + 落 2 个版本文件**：`versions/<id>/<id>.json`、`versions/<id>/<id>.jar`、`libraries/<maven 路径>`、`assets/indexes/<assetId>.json` + `assets/objects/<2>/<hash>`。

- **Mojang 契约极简**：一个 manifest 列版本 → 每版本一个 json → json 给出 client jar / libraries / assetIndex 的地址 + sha1。**sha1 是唯一完整性原语**。
- **严格复刻 HMCL 的下载行为（决策）**：即使某些件我们启动期不加载，也**照下**（含 natives classifier jar、`org.lwjgl:*` 库等），以保证产物对**其他平台 / 其他启动器兼容**。"我们启动期不加载下载的 `.so`"是运行期选择，与安装无关。
- **原始 Mojang json 直存**（不做 HMCL 式归一化）；**最后**才写 `<实例名>.json`，保证扫描器不会识别到半装版本。
- **rules 按 linux/aarch64 过滤**（与 HMCL 当前环境一致）；下载源 = `downloadSource`（镜像 BMCLAPI / 官方 Mojang）。
- **幂等**：目标文件已存在即跳过；新下载做 sha1 校验（`@kit.CoreFileKit` `hash.hash`，返回大写 hex；注意大小写归一）。
- **资产对象按 hash 去重 + 下载项按 `destPath` 去重**：老版本（如 1.7.10）资产索引里**多个名字指向同一 hash**，若每个名字生成一个下载项，两条并发任务会写同一个 `destPath.part` → 互相截断 → sha1 mismatch。
- **实例名**：点远程版本「安装」→ 设实例名（默认 = 版本号）；校验 `isValidInstanceName`（对齐 HMCL：非空且非纯空白、非 `.`/`..`、不以 `.`/空格结尾、不含 `/` `\` 控制字符及 `: * ? " < > |`）+ `versionDirExists`（命名冲突）。**实例名 = `versions/<实例名>/` 目录名**（承接"身份 = 目录名"）。
- **UI**：版本区「下载 / 收起」按钮展开下载面板 —— 下载源 `Select`、版本类型过滤 `Select`（正式版 / 快照 / 其他，改类型即时过滤、不重拉）、「获取版本列表」按钮（**不自动拉**）、远程列表用 `List` + `Repeat<RemoteVersion>().each(ListItem).virtualScroll()` 懒加载、单任务（`installingId` 占用即拒绝并行）、阶段 / 进度 / 当前文件显示。
- **体量参考**：1.21.10 ≈ 547 MB（client 30.6 MB + 115 库 82 MB + 资源 4397 个 435 MB）。

## 2. Fabric（含 Legacy Fabric 识别）

- **单实例写盘**：`versions/<名>/<名>.json` = **顶层扁平化** + `root:true` + `jar:"<名>"` + `patches:[game, fabric]`；客户端 jar 落 `versions/<名>/<名>.jar`；库落共享 `libraries/`；assets 共享。
- **端点**（Fabric meta，`@since` 实测）：`.../v2/versions/loader/<game>`（列表）与 `.../v2/versions/loader/<game>/<loader>`（单点）；取 `launcherMeta.mainClass.client`（= `KnotClient`）、`launcherMeta.libraries.common`（+`server`，**忽略 `client`/`development`**，HMCL 同款）；追加两条坐标（`url=https://maven.fabricmc.net/`）：`intermediary.maven`、`loader.maven`（26.x 的 `intermediary` 版本可能是 `0.0.0`，按端点原样用）。
- **源路由 = 每 loader 独立源**：Fabric 的 loader 列表 / 单点元数据 / fabric 库全部按 **`fabricSource`**（`镜像 = <BMCLAPI_ROOT>/fabric-meta` 与 `/maven`；官方直连），**不复用版本源 `downloadSource`**；vanilla 件也走 Fabric 的源（对齐 HMCL）。同样的"每 loader 独立源"原则扩到 Forge `forgeSource` / NeoForge `neoForgeSource`。
- **库去重（对齐 HMCL `uniqueLibraries`）**：同 `group:artifact` 留**最高版本**、位置保持首次出现、分类器变体保留；但**规则不同则不合并**，且**原生载荷不同（`natives` / `downloads.classifiers`）也不合并**（否则会丢掉"普通 jar + natives 包"里的原生包）。
- **两形态**：形态②（HMCL `patches[]`）已落地；**形态①（官方 `inheritsFrom`）启动侧由 `VersionResolver` 归一支持**（无实例可测，属独立课题）。
- **手机首次 remap**：Fabric 的 `tiny-remapper` 经 `jdk.zipfs` 写 `<gameDir>/.fabric/remappedJars/*.jar` 时会 `Files.setPosixFilePermissions`（chmod），而手机游戏目录在用户存储（FUSE/hmdfs，**拒 chmod**）⇒ 崩。修法 = 把该 chmod 改为 **best-effort** + JDK 官方 `--patch-module jdk.zipfs=` 投放（见 [`环境与载体.md`](环境与载体.md) §6 与 [`../../00-current/现状基线.md`](../../00-current/现状基线.md) §5 第 27 条）。

## 3. Forge（应用内安装覆盖 1.7–1.20.1）

**判型 != MC 版本号**：判据是 **client 侧 processor 数**（`VersionInstaller.classifyForgeProfile` + `forgeClientProcessorCount`，缺省 `sides` = 双端），**不是 `spec` 有无**。

| 子形态 | 判据 | 走法 |
|---|---|---|
| **legacy / 零 JVM** | `install` + `versionInfo`（≤1.8.9），或 `spec:0` 但 `processors: []`（1.12.2） | **纯解包 / 纯复制**：下 installer → 读 `install_profile.json` → 把 `install.filePath` 的内嵌 jar 写到 `libraries/<install.path>`（或把 `maven/` 命中项 + 主制品 `path` 落库）→ `composeForgeManifest`。**不跑 JVM** |
| **processor** | `spec` + client processor > 0（1.13–1.20.1） | `installForgeNewVersion` + `common/data/ForgeNewInstaller.ets`（**独立实现、不调 NeoForge 侧**）→ 逐 processor 跑 `:neoinstall` 无窗载体 |
| 两键皆无 | — | 报错（明确的形式错误；对齐 HMCL 抛 `IOException`） |

- **写清单前必须拒绝**：不留"能列出但起不来"的残缺实例（拒绝分支在 `writeText` 之前）。
- **零 JVM 面 = 1.7–1.12.2 全段**（由真件支撑；不在物证列内的细分版本由 `classifyForgeProfile` 兜底 —— 形态不落两子形态之一即判 `unsupported` 并明确拒绝）。
- **processor 链（1.13–1.20.1）关键项**：
  - **内嵌 `maven/**` 解包（1.13–1.16.5 必需）**：主制品 `net.minecraftforge:forge:<ver>` 与 `:universal` 的 `url` 为空（会穿透到缺省库仓 404），必须取自 installer 内嵌 `maven/`（① 代恒 7 条 = 5 目录项 + 主制品 + `:universal`），靠"目标已存在即跳过"接住；**在库下载之前**。
  - **`mergeModules` 补库**：安装期解析 `arguments.jvm` 的 `-DmergeModules=` 文件清单，按声明的库仓库补缺件到 maven 树（**基址须参数化** —— 现补库 URL 曾硬编码 `NEOFORGE_RELEASES`，对 Forge 语义错）。**不阻塞**：启动侧对点名缺件已按 warn 处理。
  - **`outputs` 幂等**：`outputs` 形态是**对象**（`{路径: sha1}`）：展开 key/value → 逐项比 sha1 → **全命中且非空 ⇒ 整条 processor 跳过** → 不符 ⇒ **先删产物再抛**。判据 = sha1 为主，**仅 `.jar`** 不符时退化为「ZIP 结构可读 + 条目完整」（对齐 HMCL：processor 动态生成的 jar 在 deflate 实现不同的沙箱里 sha1 必然不符）。
  - **`{MINECRAFT_JAR}` 用独立 temp 副本**（工具会就地改写）；**workDir 按"源 / 版本"隔离且 Forge ≠ NeoForge 目录**。
- **UI 门控**：`GameVersionsView` 的 `FORGE_MIN_MC` / `FORGE_MAX_MC`（上界 = 1.20.1）；JRE 就绪门覆盖 Forge **≥1.13**（≤1.12.2 零 JVM 分支无前置）；工具 JVM 与启动 JVM **同源解析**（`JavaPolicy.resolveJavaRuntime`）。
- **③ 代（≥1.20.3）安装未适配**：③ 代另有 `hideExtract` / `serverJarPath` / `path` 带 `:shim` 三项形态差异；政策范围外。

## 4. NeoForge（仅 MC 1.20.2+）

- **主线 = 自研编排（对齐 HMCL）**；installer jar **只当数据容器**（解包读 `install_profile.json` / 内嵌 `version.json` / `data/*.lzma`，**不加载它的任何类**）。
- **逐 processor**：按 profile 顺序、只跑 client 侧、参数**原样**来自 profile（只做占位符替换）；每个 processor 起一次**无窗 `:neoinstall` 进程**；退出码由桥在 headless 模式写 `<filesDir>/meow-neo-jvm-result.txt`；**产物齐备（`PATCHED` 断言）才写清单**。
- **数据流**：下 installer → 读三份数据 → 下载 `install_profile.libraries` 全量到 maven 树 → 准备 vanilla（原版 client jar → 独立 temp 副本作 `{MINECRAFT_JAR}` + 作为 `game` patch 底座）→ 逐 processor → 写盘（顶层扁平 + `patches[game,neoforge]`）+ `<id>.jar` 复制件 → 刷新实例列表。
- **`DOWNLOAD_MOJMAPS`**：② 代（1.17.1+）client 侧 processor 里有 installertools 的 `--task DOWNLOAD_MOJMAPS`；该工具**硬编码 `launchermeta.mojang.com`、在工具内自建 HTTP** ⇒ 我们的镜像 / 源切换对它无效（**不可镜像**）。当前按 processor 原样执行（**降级为"健壮性改进"**，见 [`../../00-current/已知限制与待解.md`](../../00-current/已知限制与待解.md) §J2）；可仿 HMCL 特判为"可镜像纯下载、不起 JVM"。
- **判据 / 写盘**：见 [`NeoForge支持-调研.md`](NeoForge支持-调研.md)、[`NeoForge安装链-逐行取证.md`](NeoForge安装链-逐行取证.md)、[`NeoForge无JVM安装-可行性与取证.md`](NeoForge无JVM安装-可行性与取证.md)。

## 5. 产物形态（HMCL 双向兼容）

- **顶层扁平 + `patches[]`**：`patches[game]`（priority 0，vanilla 全字段，含 `complianceLevel` / `compatibilityRules` / `logging` / `version`）+ loader patch（priority 30000，来自 loader 的 `mainClass` / `libraries` / `arguments`）；实例 jar = `<id>.jar`（vanilla client jar 的复制件）。
- **库落共享 `libraries/`**（maven 布局）；**同坐标高优先胜出**（`mergeLibsByCoordinate` / `libraryMergeKey`）。
- **库落位判据 `hint=="local"`**（HMCL 口径）；**不留 installer / `install_profile.json`** 在游戏目录。
- **不写 `launcher_profiles.json`**；**不把 forge / neoforge 模板的 `javaVersion` 写进 patch**（留在 vanilla 顶层与 `game` patch）。
- **安装期只写** `versions/**` + `libraries/**`（+ assets）—— 不把我们的私有状态塞进游戏目录。

## 6. 失败诊断与自愈

- **installer jar 无强校验 ⇒ 「结构可解 + 复用期自愈」**：官方源元数据无 installer 的 sha1 ⇒ 不做哈希校验；改为**复用前先解一次**（`extractArchive` 要求解出所需文件：`install_profile.json` + 内嵌启动清单；缺任一即判坏）→ 打稳定英文告警（`cached … installer unusable, re-downloading: …`）→ 删文件 → 重下（**当次安装内自愈**）。为此 installer 走**下载原语 `downloadFile`**（非 `runDownloads`）以保官方兜底不丢。
- **产物断言优先于退出码**：工具可能 fail-open（错参数也退 0）⇒ 不信退出码，**断言产物**（存在性 / sha1 / `outputs`）。
- **工具日志落盘**：工具 stdio 归档到 `<workDir>/logs/<序号>-<label>.log`，错误消息带 `log=<路径>` + 有界摘录（`TOOL_LOG_EXCERPT_MAX`）。UI 现用 `.maxLines(1)` + ellipsis ⇒ 用户看不到全貌（仅展示层问题，登记见 [`../../00-current/已知限制与待解.md`](../../00-current/已知限制与待解.md) §J3）。
- **`NeoForge patched client jar` 落共享库区且失败不回滚**：`PATCHED`（打补丁后的 client jar）由 profile `data` 的 maven 坐标展开、落**共享 `libraries/`**，而安装失败不回滚（与 HMCL 同款：靠幂等续跑）⇒ 半完成安装理论上会留下陈旧产物被后续 processor 复用（登记见 [`../../00-current/已知限制与待解.md`](../../00-current/已知限制与待解.md) §E）。
- **工具 JVM 缺失平台伪装 = 必崩**：见 [`决策与不变量.md`](决策与不变量.md) §25 与 [`环境与载体.md`](环境与载体.md) §3。
- **"存在即跳过" + 多数件不复验 sha1** ⇒ 坏库可能被永久复用；可选增强 = 采纳 HMCL 的"异常退出留标记 ⇒ 下次补坏件"（登记）。

## 7. 服务内登记（指向）

- 未决 / 受限项：[`../../00-current/已知限制与待解.md`](../../00-current/已知限制与待解.md) §E（mod loader 机制）、§J（安装 / 启动链功能缺口：`mergeModules` 按名补库未接、`DOWNLOAD_MOJMAPS` 不可镜像、processor 失败诊断被截断、独立 OptiFine 范围外）。
