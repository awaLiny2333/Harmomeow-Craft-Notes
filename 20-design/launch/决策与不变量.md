## 0. 总纲：硬约束与关键定案

### 0.1 硬约束（决定一切取舍）

1. **不改 MC**：不修改 / 不插桩 Minecraft 客户端。华为"游戏加速套件"全部要求在引擎内部集成 ⇒ 整类能力对本工程结构性不可用（[`../../00-current/已知限制与待解.md`](../../00-current/已知限制与待解.md) §D）。
2. **官方件优先**：尽量直接用官方 / 上游件并**就地收编**，不重造上游（随包 JRE = 官方 OpenJDK 26 件原地改 `.dynstr` + 自编 `libjli`/`libjvm`/`libc6.so`）。
3. **净室自研（去 GPL / Pojav / HMCL）**：桥、lwjgl GLFW overlay、启动器类加载逻辑均按"契约 / 行为"独立实现，不复刻源码。
4. **HMCL 双向兼容**：目标不是"只读" —— HMCL 产出的游戏目录我们能**用**，我们产出 / 写入的东西 HMCL **也认、也不受影响**；判据三条 = ① HMCL 产出的实例我们能用；② 我们装 / 出的实例 HMCL 也能玩；③ **不得静默破坏或挪用**别的启动器 / 上游拥有的文件。**"写进游戏目录"本身不禁**（安装器写它本应拥有的文件即可，含写进用户已有游戏目录）；**我们私有的状态**一律放自己的命名空间 `<gameRoot>/versions/<id>/.hmmcraft/`。详见 [`../../00-current/工程与规范.md`](../../00-current/工程与规范.md) §二.3 推论①②③④。

### 0.2 关键定案（含"为什么"）

| 主题 | 定案 | 为什么 |
|---|---|---|
| 启动主类 | **一律直启版本 json 的 `mainClass`，恒不设 `-Djava.system.class.loader`** | 无自研 system class loader 后，各加载器主类各自的参数契约可原样透传；自研 system CL 会与加载器自带的类加载体系冲突（见 §0.4）。legacy（launchwrapper）在 Java 8 档下 `(URLClassLoader) getClassLoader()` 强转原生成立 ⇒ 也不需要换 CL |
| classpath 形态 | **三态**：`flat`（平铺 `<cacheDir>/mc-cp/<key>-<id>/*`）/ `real-tree`（真 maven 树绝对路径）/ `ordered`（显式有序绝对路径列表）。判据 = **启动形态主类** | 由加载器"能否按自身 jar 位置反推 maven 根 / 是否需要可信有序条目集合 / 通配是否丢顺序语义"决定，与 loader 名或版本号无关（见 §0.3 与 [`启动链-总览.md`](启动链-总览.md)） |
| 平台伪装 | 见 §25（不变量） | JDK 8 按 `os.name` 精确匹配；另起 JVM 不带伪装在 legacy 套上必炸 |
| 随包 ASM 覆盖 | 判据 = ModLauncher ≥10 **且**其声明的 ASM 读不懂当前 JRE 的 class major（典型 = Forge 1.19.x） | 老 ASM 无法解析 JDK 26 的类文件；覆盖面与落点见 [`环境与载体.md`](环境与载体.md) §5 |
| Forge 支持面 | **截至 MC 1.20.1**（≥1.20.2 交 NeoForge） | **政策选择**，非技术必然：直启加载器主类后随包桩件不进 classpath、模块化撞包已消除（见 §0.4） |
| Forge / NeoForge 安装链 | **两套独立实现、互不调用**（方案 B）；载体机理共享 | **隔离风险**：NeoForge 会持续演进、可能改行为，挂一条链会把变动传染给另一条（见 [`安装链-总览.md`](安装链-总览.md)） |
| JRE 家族 | 两套：现代 OpenJDK 26 + legacy Java 8；由 `JavaPolicy` 按 (MC 版本 × loader) 择一 | legacy 段（LaunchWrapper）需 `java.util.jar.Pack200`（JDK 14 删）与可用 `SecurityManager`（JDK 24 禁）⇒ 上限 8（见 [`环境与载体.md`](环境与载体.md)） |

### 0.3 三态 classpath 的机制不变量

- **真树（`real-tree`）**要求：条目按**清单顺序**逐条绝对路径 + 实例 jar；`real-tree` 的**充要性**来自加载器按"ASM jar 的物理位置"反推 maven 根（Forge 1.13–1.16.5 平铺必失败）。
- **有序（`ordered`）**用于 legacy：平铺 `<dir>/*` 的展开序 = 文件系统 `readdir`（JDK 8 无排序语义）⇒ OptiFine 的 `TRSRTransformation` 空壳可能先于 Forge 本体命中 ⇒ `NoSuchMethodError`。
- **去重按绝对路径，不按 artifact 名**：否则会误合并"同一包的普通 jar + natives 载荷"。
- 机制 / 收益 / 代价与被否决的"暂不统一"理由见 [`../../90-archive/classpath形态-真树与平铺-决策情报.md`](../../90-archive/classpath形态-真树与平铺-决策情报.md)。

### 0.4 已作废 / 被否决（一句话）

- **自研 system class loader + 把"启动器族"摘出平铺**（`MeowClassLoader` / `LOADER_FAMILY_PATH_SEGMENTS` / `isLoaderFamilyJar`）：整套作废（`MeowLauncher` 退役后不再需要；legacy 改走 `ordered`）。
- **随包 `launcher.jar` / `gson-for-launcher.jar` 桩件**：退役，不再进任何 classpath（这也让 Forge ③ 代的"模块化 classpath 撞包"失去前提 —— 见 §0.2 与 [`../../00-current/已知限制与待解.md`](../../00-current/已知限制与待解.md) §E）。
- **独立 OptiFine（无 Forge / 无 LiteLoader）**：范围外（用户裁决）。`launchWrapperOptifineOrder` 的"丢 `optifine:launchwrapper-of`"只在"Forge / LiteLoader 与 OptiFine 共存"前提下成立。
- **`-Dos.name` 只给游戏路径、不给工具 JVM**：错（见 §25）。
- **描述符集环复用（F72）**：容量墙（归还内存必须 `vkResetDescriptorPool`，而 reset 使池内待复用 set 全部失效）⇒ 定案不做；记录见 [`../perf/Vulkan后端-性能瓶颈清单与实验计划.md`](../perf/Vulkan后端-性能瓶颈清单与实验计划.md)。

## 1. .minecraft 目录管理（GameDirsTools + GameDirsView）

### 需求语义

- 用户可以添加电脑上的文件夹路径，作为游戏目录（`.minecraft` 根）来源。
- 鸿蒙文件访问权限限制高：App 重启后临时授权失效 ⇒ **目录 URI 记忆持久化，授权状态经 `ohos.fileshare` 持久化**（见下）。

### 数据结构（`@ObservedV2`）

```ts
@ObservedV2 class GameDir { @Trace uri; @Trace name; }
```

- 持久化到**应用沙箱** `<filesDir>/meow-settings/app-settings.json` 的 `dirs`：JSON `[{uri,name}]`（**不用 Preferences**）。
- **序列化坑**：`@Trace` 属性以访问器实现，`JSON.stringify` 无法直接序列化 class 实例，必须先 map 成普通对象 `{uri,name}` 再写入。
- 默认昵称 `defaultName(uri)`：取 URI 尾部文件夹名并 `decodeURIComponent`。

### 持久化：不用 Preferences（决策）

- 目录 / 账户 / 全局设置一律存**应用沙箱** `<filesDir>/meow-settings/{app-settings,accounts}.json`（`app-settings.json` 含 `global` 段）；**不用 `@kit.ArkData`**。见 [`实例设置存储-方案.md`](实例设置存储-方案.md) §3.2/§3.3。
- **通用坑（任何 JSON 持久化都适用）**：① `@Trace` 属性以访问器实现 ⇒ 先 map 成普通对象再写；② 同步接口会抛异常，需 `try/catch`；③ 不支持 `field!: T` ⇒ 用可空 + 惰性 getter。

### Picker 选择目录（`@kit.CoreFileKit`）

- 添加：`picker.DocumentSelectOptions` + `selectMode = DocumentSelectMode.FOLDER` → `DocumentViewPicker.select()`。Picker 本身无需权限，返回临时授权 URI。
- **激活指定目录**（关键）：`authMode = true` + `defaultFilePathUri = <目录URI>`，拉起"授权 Picker"，用户只能对该目录授权、无法浏览其他目录。该参数在 2in1/PC 设备生效（恰好是本工程的 `deviceTypes`）。

### 授权持久化

- **机制**（`ohos.fileshare`，API 11+）：Picker 拿临时授权 → `fileShare.persistPermission([{uri, operationMode: READ|WRITE}])` 落库 → **每次启动** `fileShare.activatePermission(...)` 激活；移除目录 `revokePermission`。
- **前置**：能力 `canIUse('SystemCapability.FileManagement.AppFileService.FolderAuthorization')` + 权限 `ohos.permission.FILE_ACCESS_PERSIST`（`module.json5` 声明即可，系统授权）。
- **落地**：`common/access/FileAccess.ets`（`folderAuthorizationSupported` / `persistDirectory` / `activateDirectory` / `revokeDirectory`）；`GameDirsView`：`activate()` 授权成功后 `persistDirectory`；`aboutToAppear` 调 `autoActivate()` 对已记住目录逐个 `activateDirectory`；`removeDir()` 顺带 `revokeDirectory`；**添加即激活**（普通 Picker 已给临时读授权 ⇒ 成功后直接置"已激活"并 `persistDirectory`）。
- **退化**：设备不支持 / 失败 → 维持"未激活"，用户手动走 Picker。
- **注意**：`persistPermission` 只能对**已拿到临时授权**的 URI 调用。

## 3. ArkTS / 编译踩坑速查

- `arkts-no-any-unknown`：禁用 any/unknown；空类型用 `| null`。
- `arkts-no-untyped-obj-literals`：对象字面量需对应显式接口/类型，如 `(d): SelectOption => ({ value: d.name })`。
- `arkts-no-definite-assignment`：不支持 `field!: T`，用可空 + 惰性 getter。
- "Only UI component syntax can be written here"：`Repeat.each` / 渲染函数体内不能写 `const` 中间变量等普通语句。
- 新增目录后 `check_ets_files` 可能因 LSP 缓存误报 "no exported member"：重启 arkts MCP server（`deveco-mcp_restart`）后重查。
- `Select.value` / `SelectOption.value` 支持 `ResourceStr`：空态提示用 `$r(...)`；与动态字符串三元混用时类型是 `string | Resource` 联合，可借 `?? ''` 补 string 分支。
- **`Repeat` 全量模式（未开 `.virtualScroll()`）仅按 key 判刷新**（官方原文"更新前后键值相同，即使数据改变也不刷新"）：普通 `interface` 数据项（非 `@ObservedV2`/`@Trace`）改字段但不改 id 时，卡片内容不会重渲染。修法 = 把会变的字段 / 一个 `revision` 计数并入 `.key()`。

## 4. 跨组件共享状态（AppStorageV2）

**问题**：目录管理区（GameDirsView）与版本列表区（GameVersionsView）是两个独立组件，但共享"当前选中目录、已授权集合、识别版本"—— `@Local` 副本无法让另一组件感知变化。

**方案**：`common/state/LauncherState.ets`

```ts
@ObservedV2 class LauncherState {
  @Trace dirs: GameDir[] = [];
  @Trace selected: string = '';
  @Trace activated: string[] = [];
  @Trace versions: GameVersion[] = [];
  isSelectedActivated(): boolean {...}
  refreshVersions(): void {...}   // 共享调度入口
}
function getLauncherState(): LauncherState {
  return AppStorageV2.connect<LauncherState>(LauncherState, () => new LauncherState())!;
}
```

- 每个组件 `@Local state = getLauncherState()`，拿到同一实例；`@Trace` 改动全局刷新。
- 变更方（目录区 select/activate/remove）调用 `state.refreshVersions()`；版本区挂载与刷新按钮也调用同一方法。
- 授权状态 `activated` 是运行时数据，不持久化。

**循环依赖坑**：`LauncherState` 引 `VersionScanner`（`scanVersions`），`VersionScanner` 又需要 URI→path 转换函数 ⇒ 转换函数放 `VersionScanner` 本地实现，`LauncherState` 不再反向引用。

**URI→path 转换（重要）**：禁止手剥 `file://docs` 前缀 —— 转换规则是系统约定的，手写会随系统演进失效。落地 = `new fileUri.FileUri(uri).path`（`fileUri` 从 `@kit.CoreFileKit` 导入）。获得授权的用户文件 URI 同样适用。

## 5. 游戏版本识别（VersionScanner）

参考同类实现 `loadVersions`：扫 `<gameRoot>/versions/<v>/<v>.json`。

- **目录即根**：用户选中的目录**就是游戏根（等价 `.minecraft`）**，不识别"父目录 / 子 `.minecraft`"等布局；空目录同样有效（安装时 `ensureParent` 按需创建 `versions/libraries/assets`）。`scanVersions` 直接扫 `<所选目录>/versions/`。
- 用 `fileIo.listFileSync / statSync / readTextSync / accessSync`，容错单版本损坏。
- Picker URI → fileIo 物理路径：`new fileUri.FileUri(uri).path`。**`listFile` 只接受路径不接受 URI**。`userFileUriToPath` 带 `try/catch`：非法/空 URI 返回 `''`（`resolveGameRoot` 不抛；`root.length===0` 兜底恢复有效）。
- `GameVersion`：普通 class（`id/type/jsonPath/mainClass/javaVersion/releaseTime`），整体替换数组刷新，无需 `@Trace`。
- **实例身份 = 目录名（对齐 HMCL）**：`GameVersion.id` 取 `versions/<目录名>`，**不是 json 内容里的 `id`**（json `id` 仅要求存在）。启动（`gameRootOf`）、删除（`deleteVersionDir`）、隔离 `versionDir`、`${version_name}`（`LaunchOptions.versionId`）全据此派生 ⇒ 目录名≠json id（重命名/整合包）不再启动失败或误删。依据：HMCL 加载即 `manifest.withId(目录名)`（`DefaultGameRepository.java`）。
- **排序语义化**：按 `.` 分段，纯数字段按数值比较，否则字典序（`compareVersionIds`）⇒ `1.7.10 < 1.10.2 < 1.16.5 < 1.17`；已安装列表**降序**展示（新版本在前）。

## 10. LWJGL（单代 3.4.3 + legacy LWJGL2）与 OpenAL 1.24.3

### 10.1 版图

| 段 | LWJGL | native |
|---|---|---|
| **1.6.x–1.12.2 legacy** | MC 自带 LWJGL2 jar | 自编 `liblwjgl.so`（JNI_VERSION=19，一份服务 2.9.0–2.9.4） |
| **1.13 起（现代）** | 随包**单代 `lwjgl-3.4.3.jar`**（服务 1.13–1.21.x 与 ≥1.22） | 自编 / 重打包 `liblwjgl_343{,_opengl,_stb}.so` |

- **现代只剩一代**：`1.13.2–1.21.11` 的缺失成员由 overlay `deltas/overlay-3.4.3/` 的 **5 个 3.4.x 兼容 shim** 补齐，staging **不再"选代"**。代选择 = **就近归并**：`MinecraftLauncher.lwjglGeneration` 用有序世代表取"声明版本 ≥ 门槛"的**最高**代 ⇒ **永不指向未随包的世代**；某版本真缺 API ⇒ 运行期显式 `NoSuchMethodError`（= "该加一代"的信号）。
- **natives 必须随包**（平台对随包 native 打 fs-verity；运行时写入数据区的文件 `dlopen` 一律 `EINVAL`）；且 hvigor **只打包 `libs/<abi>/` 顶层 `.so`**（子目录 / 非 `.so` 一律丢弃）⇒ 各代 native **同放一个扁平目录**，靠**世代号紧跟基名**消歧：`liblwjgl_343{,_opengl,_stb}.so`。
- **选名机制**：LWJGL 官方钩子 `org.lwjgl.system.bundledLibrary.nameMapper`（接受自定义 `Function<String,String>` 类，反射实例化；core/opengl/stb 都经 `Platform.mapLibraryNameBundled`）；overlay 净室类 `org/lwjgl/system/MeowBundledNameMapper.java`；启动设 `-Dorg.lwjgl.system.bundledLibrary.nameMapper=…` + `-Dmeow.lwjgl.gen=<tag>`。**命名与查名两处锁步**（`install_natives.sh` 铺名 / `MeowBundledNameMapper` 查名 —— 改一处必同步另一处）。
- **目录治理**：`tools/lwjgl/install_natives.sh <tag>` 按命名规则摆进扁平目录并维护 `natives.manifest`（tag → 文件名 + sha256）；`--clean` / `--list` 管生命周期；**勿手工增删 / 改名**。
- **缺件只在构建期拦**（发包可掌控 ⇒ 不加 runtime 防护）：`pack_extras.py --require <member>` 断言 tar 成员齐 + `install_natives.sh --verify` 断言 manifest 每项在盘 + sha 匹配。
- **overlay 分层**：公共 `deltas/overlay/`（版本无关 13 文件）+ `deltas/overlay-<gen>/`（仅 `opengl/GLCapabilities.java` + `glfw/GLFW.java`）；`build_lwjgl_jar.sh` 支持重复 `--overlay`，且**若 `deltas/overlay-<VERSION>` 存在却未传则报错**（构建期拦漏传）。
- **`GLCapabilities` 是版本钉死的机器生成文件**：字段顺序 = C 侧 `tlsGetFunction(index)` 地址槽位，必须与 natives 同版本（3.4.3 = **2270** 槽）。由 `tools/lwjgl/gen_glcap.py` 从官方文件生成（注入 `RendererInit.onCreateCapabilities`、**版本守卫运行时条件化**、去短路运算符、能力屏蔽包装）—— 能**逐字节重建**现 overlay。见 [`../render/1.21.1-崩溃-两条链与随包规避.md`](../render/1.21.1-崩溃-两条链与随包规避.md) §1。
- **`overlay-3.4.3/glfw/GLFW.java`** = 3.3.3 版 + 3.4.x 独有 **IME/preedit** 三方法（`glfwSetPreeditCallback` / `glfwSetIMEStatusCallback` / `glfwSetPreeditCursorRectangle`；MC 的 `InputConstants` / `TextInputManager` 用到）—— **Java-only 实现，桥零改动**；preedit 回调仅**注册不投递**、cursor-rect 为 **no-op**。
- **`libffi` 3.8.0**：LWJGL ≥3.4.x 链 libffi 并调 `ffi_call_plan_*`（3.4.4 **不兼容**）；LWJGL 只带 headers ⇒ `tools/lwjgl/build_libffi.sh` 交叉编。
- **打包**：`tools/lwjgl/pack_extras.py`（多件 jar、确定性 tar）；`EXTRAS_VERSION` 递增触发重抽。

### 10.2 改随包 tar / JRE 数据必须升令牌（不变量）

- **改 `meowcraft_extras.tar.gz` 内容 → 升 `EXTRAS_VERSION`**。运行时 `ClasspathStager` 的 done 标记 = 「**令牌 + 随包 tar 字节数**」**双条件** ⇒ 即使忘升令牌，tar 字节数变化也会自动重抽（双重保险）。
- **改随包 JRE 数据（模块集 / `lib/patch/jdk.zipfs` / 文件）→ 升 `JRE_DATA_TOKEN`**（native `jre_launcher.h::kJreDataToken` 与 ArkTS `Paths.ets::JRE_DATA_TOKEN` 两处同值）。JRE 数据门**只靠"令牌相等"判新鲜**（无 tar 字节数等价防线）⇒ 不升令牌会**静默沿用旧数据**（"新 el1 `.so` + 旧数据"混合）。**只换 el1 `.so`（数据不变）⇒ 令牌不动**。
- 升级语义：`Install` 发现「有数据但令牌不符/缺失」→ **清目录重解压**；并扫 `filesDir/meow-jres/` 删**非当前 id** 的兄弟目录（幂等、失败仅告警）。

### 10.3 OpenAL Soft 1.24.3（`ALC_SOFT_system_events`）

- 现代 MC 的 `CallbackDeviceTracker` 需要 OpenAL **1.24.0** 起的 `ALC_SOFT_system_events` ⇒ 随包 **1.24.3**（见 [`../../40-adaptation/ohaudio-backend.md`](../../40-adaptation/ohaudio-backend.md) §6）。
- 三补丁器：`patch_openal_ohos.py`（OpenSL，版本容错）、`patch_openal_ohaudio.py`（OHAudio 后端，源按 1.24 API）、`patch_openal_events_export.py`。
- **导出双闸门（勿漏）**：1.24.x 链接 `-Wl,--version-script=libopenal.version`（`local: *` 裁未列符号）+ 编译期 `ALC_API=__attribute__((visibility("default")))`。三个 events 函数上游**两处都缺** ⇒ 默认被裁（扩展串却照播）⇒ MC `dlsym` 落空。故补 `ALC_API` + 列入 version script（导出 30→**33**）。
- 后端宏 1.24 移到 `config_backends.h.in`（`#cmakedefine01`）；OpenSL 的 `processC` 变**内联 lambda**；`SL_IID_ANDROIDCONFIGURATION` 进 dynload 表（OHOS 无此头 → 移除）。

### 10.4 hvigor：`libs` 增删不追踪（构建铁律）

- 向 `libs/**/libs/<abi>/` **增删 `.so`** 后，`devecocli build` 虽报 `DoNativeStrip`/`ProcessLibs`，但 **HSP 可能不重打**（共享缓存未感知）→ 设备 `... not found`。

## 11. 版本隔离与逐版本设置

### 需求

游戏数据（存档 / 选项 / 日志 / 资源包）按版本各落一处，互不干扰；**语义对齐主流启动器**（HMCL / PCL / HomoLauncher），以便直接沿用它们已在本机 `.minecraft` 里留下的布局。

### 决策：只切"运行目录"**一个变量**

各家的"版本隔离"**都不是一份目录迁移清单**，而是**把 `--gameDir` 从 `.minecraft` 根切到 `versions/<id>`**；`assets/` + `libraries/` 永远共享（从不复制 / 软链）。所谓"隔离了存档/选项/日志"只是"切了运行目录"的推论（[`../../10-research/启动器目录模型与版本隔离.md`](../../10-research/启动器目录模型与版本隔离.md) §6）。

在我们的启动链里，这个变量恰好是唯一一处 `-Duser.dir`：`GameDirs.profile = System.getProperty("user.dir")` → `ArgBuilder` 用它做 `${game_directory}` 宏 → MC 的 `--gameDir`；`options.txt` 也由它派生。

### 实现

| 层 | 内容 |
|---|---|
| 常量 | `Paths.MC_VERSIONS_DIR` + `Paths.versionDir(gameRoot, id)`；实例文件 = `<gameRoot>/versions/<id>/.hmmcraft/instance-settings.json`（plain JSON + `format: 1`） |
| 持久化 | `InstanceSettings.readInstanceSettings() / writeInstanceSettings()`（`common/data/InstanceSettings.ets`），存各实例目录内（**稀疏**：只写脏字段；临时文件 + `renameSync` 原子替换） |
| 启动 | `MinecraftLauncher` 的 `LaunchOptions.gameDir` → `-Duser.dir` 与 `${game_directory}` 取它；`GameLauncher` 按开关算出 `versions/<id>` 后传入 |
| UI | `GameVersionsView`：行内"编辑"按钮为**两态**（`编辑` ↔ `完成`），展开面板内是逐实例开关（隔离 / 渲染后端 / 线程化渲染） |

- **跨进程**：主进程（版本区 UI）与游戏进程（`:game` 的 `GameLauncher`）**读同一个实例文件**（`<gameRoot>/versions/<id>/.hmmcraft/`）—— 不走 Preferences。
- **三态语义**：**无设置文件 = 默认开**（UI 对无文件实例显示为开）；新安装的版本在安装完成后自动开启隔离（对齐 HMCL 安装期 `enableIsolation()`）；既有版本不变，用户仍可手动开关。

### 关键点（改动时勿破坏）

- **`-DMEOWCRAFT_GAME_DIR` / `assets_root` / `-Dmeowcraft.path.minecraft` 必须保持不变**（仍指共享根）。隔离只动运行目录；`versions/` `libraries/` `assets/` 不随隔离移动（与主流一致）。
- `-Duser.home` 保持 `.minecraft` 根（账户走 `MEOWCRAFT_HOME`，与隔离无关）。
- natives 不受影响：本就不放版本目录（随包 el1 + 沙箱 `mc-run/<key>-<id>/natives` 兜底）。
- **`Repeat` 的 `.key` 里带了 `editingId`**：`Repeat` 同 key 复用行时**不重跑 item builder**，展开/收起必须让该行重建才会重新求值面板的 `if`（见 §3）。
- 兼容性：PCL / HomoLauncher 已在本机 `.minecraft/versions/<id>/` 留过 saves/logs/options，打开开关即直接沿用（同布局）。

### 边界

- **世界迁移提示**：切换隔离后，原先落在根 `saves/` 的世界"看起来丢了"（HMCL/PCL 都有同类提示文案）；本工程不做迁移提示。

### 11.1 删除版本

- **入口**：版本卡片的「编辑」面板内「删除版本」按钮（危险色 `app.color.danger`）。
- **语义**（对齐主流启动器）：删除 `<gameRoot>/versions/<id>/` **整个实例目录**。`assets/` 与 `libraries/` 是共享池，**不随版本删除**。**若该版本启用了「版本隔离」，其存档/选项/日志就在这个目录里 → 会一并删除**。
- **二次确认**：`UIContext.showAlertDialog`（`AlertDialog.show` 已废弃，API 18 起改 `showAlertDialog`）；已启用隔离时用专门文案额外告警"存档/选项/日志会一并清除"。
- **安全约束**：`state.gameRunning` 为真时按钮禁用（避免删正在使用的实例）。
- **原子化实现**：`common/data/VersionTools.ets` 的 `deleteVersionDir(root,id)` —— `fs.renameSync` 先把 `versions/<id>` 移到 **`<gameRoot>/.meow-trash/<id>-<时间戳>`**（**`versions/` 之外**，同文件系统可原子 rename；改名失败即返回 false、实例原样保留），成功后再 best-effort 递归清删该临时目录（`fs.rmdirSync` **无递归参数**，用 `fileIo.listFileSync(dir,{recursion:true})` 按路径长度降序先深后浅逐条 `rmdir`/`unlink`）。这样"删到一半"绝不留下**可见**的半损实例；残留放在 `versions/` 之外，扫描器无需按名字后缀排除。
- 逐版本设置随 `<id>` 目录一起删 ⇒ 无孤儿键。
- **不做**：删除前的"占用检测"（被占用时改名失败即拒绝、实例保留已足够）；回收站 / 撤销（鸿蒙沙箱内不现实）。

## 12. 输入：按键先到输入法 → 用 `onKeyPreIme` 在输入法之前转发

- **现象**：MC 菜单（含**按键绑定**）按字母/数字/符号无反应；F/方向键正常；游戏内打字正常。
- **根因**：菜单态**自动激活隐形 IME** → ArkUI 按键派发顺序 ①`onKeyPreIme` → ②**输入法消费** → ③`onKeyEvent`，故可打印键被输入法吃掉：`handleImeKey` 与 **native 窗口 filter 都看不到**。
- **修法**：隐形 TextInput 挂 **`onKeyPreIme`** —— 转发可打印键（`sendKey`）并 **`return false`**（输入法仍收字符做文本）→ **绑定与中文 IME 兼得**。
- **弯路（勿重蹈）**：改 `handleImeKey` 抑制逻辑**无效**；native `OH_NativeWindowManager_RegisterKeyEventFilter` 实测**从未被调用**（已删）。
- 全文：[`../input/输入-总览.md`](../input/输入-总览.md) §2.2。

## 13. 游戏全屏（MC 原生）

- **需求**：让 MC 自带的全屏（F11 / 视频设置里的"全屏"）真正生效。
- **链路（三层）**：`GLFW.glfwSetWindowMonitor` → `CallbackBridge.nativeSetFullscreen(bool,x,y,w,h)`（`meowcraftbridge` JNI 存请求）→ ArkTS `GameWindow` 每 100ms 轮询 `meowjrebridge.takeFullscreenRequest()` → 命中则驱动真实 `GameAbility` 窗口：
  - 进入 = `win.maximize(window.MaximizePresentation.ENTER_IMMERSIVE_DISABLE_TITLE_AND_DOCK_HOVER)` + `setTitleAndDockHoverShown(false, false)`（铺满整屏 + 隐藏 dock/标题栏/状态栏，Hover 热区也不弹出）；退出 = `recover()`。
  - `mGLFWWindowMonitor` 改为 1/0 → `glfwGetWindowMonitor` 正确反映全屏态；真实窗口尺寸变化经既有 surface resize → `internalWindowSizeChanged` 回给 MC 自适应。
- **★ 坑**：`meowjre` HSP 的 native 是经 `meowcraftlib/Index.ets` **逐个 re-export**（`export const x = bridge.x;`）。**新增 native 函数必须同步加一行**，否则 entry 侧 `bridge.x === undefined` → 轮询静默 no-op。
- 状态与实机证据见 [`../../00-current/现状基线.md`](../../00-current/现状基线.md) §5 第 20 条。

### 13.1 SDL 路径（MC 26.3）

- **背景**：26.3 走 SDL，全屏经 `SDL_SetWindowFullscreen`（进=`SDL_SetWindowFullscreenMode(NULL)`+`SetWindowFullscreen(true)`；出=`SetWindowFullscreen(false)`+`SetWindowSize/Position`）。驱动若没实现 `SetWindowFullscreen` ⇒ SDL 退化用 `SetWindowSize`（no-op）→ F11 无效。
- **接入（复用既有 ArkTS 链路，ArkTS 零改动）**：
  1. `input_bridge.c` 加**纯 C** `meowSetFullscreenRequest(want,x,y,w,h)`（写既有 `g_fs*` 请求槽；JNI `nativeSetFullscreen` 改为委托它；ABI 不变）。
  2. SDL 驱动 `OHOS_SetWindowFullscreen`（`tools/sdl/src/video/ohos/SDL_ohoswindow.c`）`dlsym("meowSetFullscreenRequest")` → 转发进/出 → 返回 `SDL_FULLSCREEN_SUCCEEDED`（让 SDL 核心置 `SDL_WINDOW_FULLSCREEN` + 发 `ENTER/LEAVE_FULLSCREEN`）。
  3. `SDL_ohosvideo.c` 挂 `device->SetWindowFullscreen` + `device_caps |= VIDEO_DEVICE_CAPS_SENDS_FULLSCREEN_DIMENSIONS`（尺寸仍以 `OHOS_SyncSurfaceSize` 为唯一来源）。
- ArkTS 既有 `pollFullscreen()`（100ms）→ `takeFullscreenRequest` → `maximize()/recover()` 原样复用。
- **边界**：独占真全屏需非空 mode 列表（当前空 → 静默退化 borderless）。

## 16. 显示缩放：低分辨率渲染 + 上采样

- **需求**：高 DPI（2K/3K/4K）屏渲染压力大，而 MC 是方块游戏不需全分辨率 → 高级选项加「显示缩放」（**渲染分辨率 = 窗口 / N**，N ∈ {1, 1.5, 2, 3, 4}）。
- **落地 = 方案 B（纯 ArkTS + 一处 native filter 修正）**，**无 FBO、不改 MC jar**：
  - `GameWindow.build()`：`XComponent(SURFACE)` 按 **1/S 布局**（`width(`${100/S}%`)`）+ **`.scale({x:S,y:S,centerX:0,centerY:0})`** 放大回满窗；父 Column 贴左上。
  - 为什么成立：`.scale` 作用于 SURFACE 的**子渲染节点**（非只动布局盒）；`onSurfaceChanged` 报**布局尺寸**（不含 transform）→ 场景真缩小；**S=1 时 `100%`+`scale(1)` 与原状逐位等价（零回归）**。
- **选项 / 持久化**：`renderScale`（存应用级 `app-settings.json` 的 `global.runtime` 组，**应用级全局唯一、不随游戏目录迁移**；主进程写、游戏进程读）；`RENDER_SCALE_OPTIONS=[1,1.5,2,3,4]`；`AdvancedOptionsView` 下拉；`SettingsTools.renderScale()/setRenderScale()`。
- **★ hover 频闪根因与修复**：非 grab 的窗口级 native mouse filter 原 `local = displayPx − originPx`（**只有偏移**）。`.scale(S)` 后 `displayX = 原点 + S·event.x`，而 `pushMouseMap` 仍用 `(displayX − event.x)` 反算原点 → **原点随指针漂移**，filter 每 ~100ms 刷新 → **频闪**。
  **修**：① native filter 改 `local = (displayPx − origin) / S`（`input_bridge.c` 加 `g_filterScale`；`meowMouseFilterStart` 增 `scale` 参）；② ArkTS 原点改 `(displayX − S·event.x)·sx`（`GameInputController.pushMouseMap`）。**S=1 逐位退化**。
- **固有代价**：GUI/HUD 也在低分 buffer 内 → 文字整体变糊。
- **文件**：`GameWindow.ets`、`AdvancedOptionsView.ets`、`common/constants/Constants.ets`、`common/data/SettingsTools.ets`、`common/input/GameInputController.ets`、`common/state/JvmLauncher.ets`、`libs/meowcraftlib/src/main/cpp/{meowcraftbridge/input_bridge.c,meowjrebridge/meowjrebridge.cpp,types/libmeowjrebridge/Index.d.ts}`。

## 18. JRE 数据门：令牌校验 + 「须升级/升级」UI

- **动机**：随包 JRE 的 **el1 `.so`**（HSP）与 **`filesDir` 数据**（`java.home`）是两处；app **原地更新**时 HSP 会换、而 `filesDir` 保留 ⇒ 数据变了却沿用旧数据就会「新 `.so` + 旧数据」混合。参照 `EXTRAS_VERSION` 引入**数据令牌**。
- **令牌**：`Install` 解压成功后写 `<filesDir>/meow-jres/<id>/meow_jre_data` = 数据令牌。就绪 = `lib/modules`（现代套）/ `lib/rt.jar`（legacy 套）存在 **且** 令牌一致。两个 id 各自独立令牌。
- **升级语义**：`Install` 发现「有数据但令牌不符/缺失」→ **清目录重解压**（`RemoveAll`，手写递归删，避 OHOS libc++ 的 `std::__fs::filesystem`）。
- **版本中性命名**：HSP 模块名 `meowjre` / `meowjrelegacy` 与 JRE id `meow_jre` / `meow_jre_legacy` **不带版本号**，JRE 版本仅由**数据令牌**承载 ⇒ 每套 JRE 升级不再留下旧版号 HSP（模块名不变，系统按新版本原地替换）。
- **UI（防迷惑）**：`JavaEnvScanner.JavaEnvInfo` 增 `needsUpgrade` / `extractedToken`；`JavaEnvView` 显示 **「须升级」+「升级」按钮 + 副行「令牌 旧 → 新」**。**阻止启动**：须升级时 `LauncherState.jreReady=false` → 启动按钮**全部禁用** + 提示 `versions_jre_need_upgrade`。
- **⚠️ 维护铁律**：**改随包 JRE 数据的任何内容**（模块集 / `release` / 文件）→ **必须同步升令牌**（native + ArkTS 两处），否则用户会沿用旧数据；**只换 el1 `.so`（数据不变）→ 令牌不动**。见 §10.2。
- **清旧版号模块的姿势**：历史遗留的 `meowjre25` / `meowjre26` 是**挂在 app bundle 内的模块**（`moduleType: 3`），**不是独立 bundle** ⇒ 须用 `hdc shell bm uninstall -n meow.liny.craft.awa -m meowjre25`；**卸载模块会杀掉 app 进程，之后要重新 `aa start`**。见 [`../../00-current/工程与规范.md`](../../00-current/工程与规范.md) §二 3.1。
- **文件**：`entry/src/main/cpp/meowassets/jre_launcher.{h,cpp}`、`common/{constants/Paths,data/JavaEnvScanner,data/JavaRuntime,state/LauncherState}.ets`、`components/{JavaEnvView,GameVersionsView}.ets`、`resources/base/element/string.json`。配方见 主仓 `tools/jre26/README.md`、`tools/jre8/README.md`。

## 21. 随包 jar 的 MANIFEST 必须自洽（不变量）

- **规则**：凡打包时**剥掉 `META-INF/versions/**`**，**必须同时去掉 MANIFEST 的 `Multi-Release: true`** —— 否则产出「声称多版本 jar、却没有 `META-INF/versions/**`」的**坏件**。
- **踩法**：`build_lwjgl_jar.sh` 把上游 LWJGL 的 MANIFEST **原样拷来**（含 `Multi-Release: true`），而脚本后段又把 `META-INF/**`（除 MANIFEST）全剥 ⇒ 两者矛盾。
- **炸点**：`bootstraplauncher 1.1.2`（NeoForge **1.20.2** 用）在 `main` 里对**每个** classpath 条目先 `SecureJar.from(path)`；`securejarhandler 2.1.24` 的 `readMultiReleaseInfo()` 见 MANIFEST 声明 `Multi-Release` 就 `Files.walk("META-INF/versions")` → union 文件系统抛 `NoSuchFileException` → 启动即崩。**2.0.2（1.21.1 用）对这一步有防护**，所以同一份坏件只在 1.20.2 上暴露（教训：老加载器对新加载器的宽容度不同，别用"在高版本上没事"推断无缺陷）。
- **根治**：三处一起 —— **主仓** `tools/lwjgl/build_lwjgl_jar.sh`（拷完 MANIFEST 后剥离）、**主仓** `tools/relocate_gson.py`（字节级按 `splitlines(keepends=True)` 处理，CRLF/LF 都覆盖、无该属性时原样返回）、**主仓**共用打包器 `tools/oshi/pack_jar.py`（统一守卫 + 告警）；并重打 `meowcraft_extras.tar.gz`、升 `EXTRAS_VERSION`。
- **验证方式**：逐条目比对（除 MANIFEST 外全部逐字节一致）；整链 `base tar → relocate_gson.py → pack_extras.py` 重跑**逐字节可复现**。

## 22. 杂项（零散的平台接口对接与窗口行为）

> 本节收纳**不属于任何大功能**的零散对接：单个平台接口 / 窗口行为的一次性实现与决策。与 §13 区分：那节只讲全屏本身。

### 22.1 失焦自动暂停（26.3/SDL + ≤26.2/GLFW）

**要解决的问题**：Windows/Linux 上游戏窗失焦会自动暂停（MC 自带，受 `options.txt: pauseOnLostFocus` 控制），本平台原来从不暂停。

**MC 怎么判焦**：
- **26.3（SDL）**：`Window.handleEvent` 的 `switch(event.type())`：**526 → `onFocus(true)`、527 → `onFocus(false)`**（即 `SDL_EVENT_WINDOW_FOCUS_GAINED/LOST`）→ `Window.focused`；`Minecraft.pauseIfInactive()`（每 tick 调）= `!window.isFocused() && options.pauseOnLostFocus`，且**连续失焦 >500 ms** 才 `pauseGame(false)`。
- **≤26.2（GLFW）**：MC 自己注册 `glfwSetWindowFocusCallback(handle, this::onFocus)`；同一个 `pauseIfInactive`。
- 两版**都不轮询**（不看 `glfwGetWindowAttrib` / `SDL_GetWindowFlags`）⇒ 只吃「事件 / 回调」。

**做法**：平台信号 = **窗口级** `windowStage.getMainWindowSync().on('windowEvent')`（`WINDOW_ACTIVE(2)` → 获焦、`WINDOW_INACTIVE(3)` / `WINDOW_HIDDEN(4)` → 失焦，其它窗口事件**只记诊断、不改状态**）。链路 = `GameAbility.onWindowStageCreate` 订阅 → `notifyWindowActive()`（`JvmLauncher.ets`）→ NAPI `setWindowActive` → 桥 `meowSetWindowActive()` 写共享块 → 两条消费端：
- **26.3（SDL 驱动）**：`OHOS_PumpEvents` 检测到变化后调 `SDL_SetKeyboardFocus(win / NULL)`（**SDL 核心自己会发 526/527**）+ 失焦时 `SDL_ResetKeyboard()`（避免切回时按键卡住）；
- **≤26.2（GLFW stub）**：`glfwPollEvents()` 末尾轮询共享块（同一字段），变化时以**注册回调时的窗口句柄**派发该回调（MC 的 `Window.onFocus` 会校验句柄），并用 `GLFW_FOCUSED` 属性充当"上次状态"⇒ 恰好派发一次。桥侧新增 JNI 取值入口 `CallbackBridge.nativeWindowUnfocused()`。

- **共享块新增 `windowUnfocused`（0x27204，占用原 `reserved_tail`，总大小不变）**。**语义故意是「1=失焦 / 0=获焦」，零值 = 老行为**：该字段落在旧 `reserved_tail` 上，**旧 HSP 永远不写它（保持 0）⇒ 自动退化为「始终获焦」**，绝不会出现「旧组合一启动就暂停」。
- 失焦时**记住当时有焦点的那个 SDL 窗口**，获焦时原样恢复（驱动有多个窗口共用同一 native surface，盲目取窗口链头会指错窗）。
- **为何窗口级而非 stage 级**：手机把游戏变**悬浮窗（小窗）**后，stage 级 `windowStage.on('windowStageEvent')`（只认 `ACTIVE` 为获焦）在悬浮窗态下系统只反复发 `INACTIVE`、永不再发 `ACTIVE` ⇒ 共享块永久 = 失焦 ⇒ MC 反复重新暂停（观感"回不去游戏"）。窗口级 `on('windowEvent')` 是**焦点单一来源**。官方文档依据：`window-lifecycle`「对于 WindowStage 获焦失焦状态推荐使用 `on('windowEvent')`」+ `window-focus-guide`（焦点是窗口粒度属性）。
- **保留的低频诊断**：`[focus] winEvent type=%d -> %s`（首见 / 变化去重）；判读 = 悬浮窗出现 `type=3 -> unfocused`，点小窗应出现 `type=2 -> focused`。
- **一处"不设防"（明确接受）**：jar 装在 entry HAP、桥在 meowjre HSP，理论上可分属不同版本；按"app 整体分发"决定不为不存在的错配给该 JNI 调用加 `UnsatisfiedLinkError` 兜底。

### 22.2 游戏内剪贴板（复制）与"打开网址"

**MC 侧机制**
- **剪贴板两代都是库调用**：26.3 `ClipboardManager` → `SDLClipboard.SDL_Set/GetClipboardText`；≤26.2 `glfwSetClipboardString` ⇒ 我方 stub/JNI 与 SDL 驱动 hook 两代通吃。
- **打开网址两代路径不同**：26.3 `Blaze3D` → **`SDLMisc.SDL_OpenURL`**（经库 ⇒ 有插入点）；**≤26.2 MC 绕过所有库、直接用 JDK `Runtime.exec("xdg-open", uri)`** ⇒ 无库级插入点（**不做**，登记见 [`../../00-current/已知限制与待解.md`](../../00-current/已知限制与待解.md) §G1）。

**实现**
- **剪贴板（只写）**：平台剪贴板 NDK（`libpasteboard.so` + `libudmf.so`）**运行期 dlopen**（刻意不链接 ⇒ 守住 `build_sdl_meow.sh` 的 `DT_NEEDED` 白名单）；桥侧 `meowpasteboard.c` 供 ≤26.2（补上原先**空的** `nativeClipboard` JNI），SDL 侧 `SDL_ohosclipboard.c` 挂 `SetClipboardText`。**读取（粘贴）不做**：需 `ohos.permission.READ_PASTEBOARD`（弹授权），而无提示路线（粘贴控件）只在 ArkTS UI 可用。
- **打开网址（26.3）**：新增 `tools/sdl/src/misc/ohos/SDL_sysurl.c`；patcher 给 `src/misc/unix/SDL_sysurl.c` 加 `#if !defined(__OHOS__)` 守卫（否则两个 `SDL_SYS_OpenURL` 重复定义）并 glob 我们的版本。`SDL_SYS_OpenURL` 只把 URL **原子写入 app files 目录（`$HOME`）下的 `meow-open-url.txt`**（`HOME` = filesDir，桥在 `JLI_Launch` 前 setenv；**`MEOWCRAFT_HOME` 只是 JVM `-D` 属性、不在 env**），由 ArkTS **1 s 轮询**取走并 `startAbility(Want{action:'ohos.want.action.viewData', uri})` 拉起浏览器。
- **为什么是"请求 + 轮询"而非 native 直接开**：**OHOS native 侧没有"打开链接 / 拉起第三方应用"的 API**（全 SDK 符号扫描：无 `*StartAbility*`（非 Self）/ `*OpenLink*` / `*OpenURL*`；`OH_AbilityRuntime_StartSelfUIAbility` 只能拉**本应用自己**的 Ability）⇒ 只有 ArkTS 能做。上游 SDL 的 OHOS 端口同样把 URL 回调进 ArkTS；我们选了更轻的"请求通道 + 复用既有轮询"。
- **已知小瑕（登记）**：剪贴板实现里三个 NDK setter 的返回码未判；空串（MC 主动清空剪贴板）写成空文本而非 `OH_Pasteboard_ClearData`。

## 23. grab 内「只有 MOVE 事件可写光标槽」不变量

**不变量**：grab（相对模式）下，**只有 `UI_MOUSE_EVENT_ACTION_MOVE` 事件才允许产生 / 写入光标增量**；任何 DOWN/UP 等非 MOVE 坐标一律不得进入抓取差分。

- **症状**：grab 内**每点一次左键**视角微转并累计漂移（点 N 次漂 N 个 1px）—— **棘轮**。
- **根因**：平台鼠标事件经 ArkUI 节点接收器 `NODE_ON_MOUSE`（`libs/meowcraftlib/src/main/cpp/meowjrebridge/meowjrebridge.cpp` 的 `MeowNodeEventReceiver`）把**包括 DOWN/UP 在内**的坐标写进光标槽 → `OHOS_PumpEvents` 的 grab 差分（`tools/sdl/src/video/ohos/SDL_ohosevents.c`）当成真实位移转发 ⇒ 转视角；按键事件坐标与虚拟光标**系统性差 1px 且被采纳**。
- **修法**：节点接收器加守卫 `if (OH_ArkUI_MouseEvent_GetMouseAction(ev) != UI_MOUSE_EVENT_ACTION_MOVE) return;` —— **非 MOVE 事件不产出增量**。按键语义不受影响（按钮走 ArkTS `sendMouseButton`→ring→SDL）；grab 内转向（MOVE）不受影响。
- **★ 被否掉的落点（登记，别再试）**：在 `input_bridge.c` 的 `critical_send_cursor_pos` 加 `grabbing` 守卫会**冻死相机** —— 该槽位是 SDL 在 grab 内**唯一**的相对位移源。
- **★ 「相对模式不写光标槽」方案已废（登记，别再试）**：在 SDL `OHOS_WarpMouse` 加"相对模式不写 `cursorX/Y`" ⇒ 三症状全无效；原因：**SDL 核心在相对模式内根本不调用 warp**（`SDL_mouse.c` 早退 / 要求 `!relative_mode`）。已撤销。

## 24. 游戏发起的指针移动在鸿蒙不可实现 ⇒ 一律 no-op（不变量）

**不变量**：**鸿蒙平台无法移动用户的鼠标指针**（无 warp / 光标归中 API，见 [`../../00-current/已知限制与待解.md`](../../00-current/已知限制与待解.md) §A2）⇒ **一切"游戏发起的指针移动 / 归中"都不实现，一律 no-op**；**指针位置的真值只来自用户输入**（鼠标事件 / 触点）。

- **落地**：`OHOS_WarpMouse`、`glfwSetCursorPos`、`meowGrabReset` 三处**均改为 no-op**（**不写我方光标槽、不发 motion**）。
- **踩坑（勿重蹈"假装移动"）**：此前把这些实现成"假装移动"（把我们的指针概念拖到窗口中心）⇒ MC 的指针概念与真实指针背离 ⇒ 表现为 **ESC 后按钮不高亮、直接点击"猛抬"**。假实现不是"更接近桌面"，而是引入了平台不存在的语义。
- **接受残留（用户决定）**：菜单里移动鼠标后返回游戏，视角仍被 MC 原版行为带一点 —— 真因是 MC `MouseHandler` 把菜单内位移累加进 `accumulatedDX/DY`（grab/release 都不清零），恢复后由 `turnPlayer` 应用。**动它需要改 MC ⇒ 违反"不改 MC"硬约束，故不动**；登记见 [`../../00-current/已知限制与待解.md`](../../00-current/已知限制与待解.md) §B7。

## 25. 「另起 JVM」必须带平台伪装（不变量）

**不变量**：本仓**任何"另起 JVM"的路径**（安装期工具 JVM、各子进程、将来的其它载体）的 argv 都必须带**与游戏同源**的平台伪装（`-Dos.name` / `-Dos.version`；同源常量 = `common/constants/LaunchDefaults.ets` 的 `TOOL_JVM_PLATFORM_SPOOF_ARGS`）。"游戏路径带了"**不等于**工具路径带了。

- **为什么**：JDK 8 的 `sun.nio.fs.DefaultFileSystemProvider.create()` 按 `os.name` **精确匹配**（`Linux` / `SunOS` / `Darwin` / …），而本机真 `os.name` 是 `HarmonyOS` ⇒ 匹配不上直接 `AssertionError: Platform not recognized`（发生在**类初始化期**，连主类都加载不到，`JLI` 退 1）。现代套 26 对未知 `os.name` 宽容回退，**别依赖**这一点。
- **适用范围**：只要链路上可能落到 legacy（Java 8）套，缺它就必炸；游戏路径的"固定 JVM 参数"段也 push 同一对 `-Dos.*`。机制 / 取证见 [`../../90-archive/Forge-1.13至1.20.1-安装实施方案.md`](../../90-archive/Forge-1.13至1.20.1-安装实施方案.md) §4.1。
- 工具 JVM 载体、JRE 择一与 ASM 覆盖见 [`环境与载体.md`](环境与载体.md)。

## 26. 建目录必须幂等：判据是「目录最终可用」（不变量）

**不变量**：`fileIo.mkdirSync(dir, true)` 对**已存在**的目录同样抛 `File exists`（13900015）⇒ **绝不能把"抛错"当成"建不出来"**。凡"确保某目录可用于后续写入"的地方，判据只能是**目录最终是否可用**（`accessSync` 复核），与 mkdir 是否抛错无关。

- **为什么**：把 `File exists` 当失败，症状是**第一次启动正常、第二次启动起静默失效**——日志目录判空 ⇒ 不注入 `-XX:ErrorFile` ⇒ `hs_err_pid*.log` 落回**游戏目录**（进程 cwd），正是 §0.1 铁律要消除的污染；且每级兜底都踩同一个坑时，兜底形同不存在。
- **落地**：`InstanceSettings.ensureDirUsable(dir)` 是唯一判据（先 `accessSync` 探测、需要才建、建完再复核）；`ensureInstanceLogsDir`（实例内 `.hmmcraft/logs`）与 `GameLauncher` 的 `logs-fallback` 兜底都经它。**其余** `mkdirSync` 调用点一律"**catch 后忽略**"（是否真的建出来，由后续写入或 `accessSync` 暴露），**不得在 catch 里下"失败"结论**。
- **如何观测**：启动日志**不应**出现 `logs dir unusable:` / `fallback logs dir unavailable:`——出现即"实例内 + 沙箱兜底"两级都不可用，此时没有 `-XX:ErrorFile`，hs_err 会落在游戏目录。落点与自证命令见 [`环境与载体.md`](环境与载体.md) §7.7。
