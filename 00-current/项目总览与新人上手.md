## 1. 这个项目在干嘛，以及「为什么难」

**一句话定义**： **Harmomeow Craft Launcher** 是**在鸿蒙 PC（2in1）上原生运行 Minecraft Java 版**的工程：
一个 ArkTS 启动器 + 一套把 JVM / LWJGL / 桌面 OpenGL 搬到 HarmonyOS 的桥（[`README.md`](../README.md):3、[`现状基线.md`](现状基线.md):4-6）。

**三条硬约束**（决定了一切设计取舍）：

1. **不改 MC**：不能修改 Minecraft 客户端、不能在 MC 内部插桩。华为「游戏加速套件」全部要求
   **在游戏引擎内部集成**，与该约束冲突 ⇒ 整类能力对本工程结构性不可用
   （[`已知限制与待解.md`](已知限制与待解.md) §D 基准模型，及 [`平台加速能力-调研.md`](../20-design/perf/平台加速能力-调研.md)）。
2. **官方件优先**：尽量直接用官方/上游件并**就地收编**，不自己重造上游；典型 = 随包 JRE 用
   **官方 OpenJDK 26.0.2.1（glibc）件原地改 `.dynstr`** + 自编 `libjli`/`libjvm`/`libc6.so`
   （[`现状基线.md`](现状基线.md):81，[`已知限制与待解.md`](已知限制与待解.md):39）。构建输入一律
   来自 `ref/` 下上游源码仓（主仓 `tools/README.md` §1）。
3. **净室自研（去 GPL / Pojav / HMCL）**：`launcher.jar`（**2026-10-01 已退役**）、`libmeowcraftbridge.so`、lwjgl GLFW overlay
   均已净室重写，只按「契约/行为」独立实现，不复刻源码
   （[`launcher净室-设计.md`](../90-archive/launcher净室-设计.md):4-8、
   [`GLFW净室桥-设计.md`](../20-design/render/GLFW净室桥-设计.md):4-5、
   [`现状基线.md`](现状基线.md):77）。

**三个难点**（每一条都在 notes 里有实机/取证出处）：

1. **el1 随包 native 才能 `dlopen`**：`filesDir`（el2 数据区）**禁止** `dlopen`/执行代码，只有随包
   `bundle`（el1）可执行；且平台只对随包 native 打 fs-verity，运行时写入数据区的文件 `dlopen` 一律
   `EINVAL`。⇒ 所有 native 必须随包，JRE 的 `.so` 与数据（`java.home`）被迫**分体**放两处，靠
   `OHOS_JAVA_HOME`/`OHOS_DL_DIR` 串起来（[`../20-design/launch/决策与不变量.md`](../20-design/launch/决策与不变量.md):229-232、:246-258，
   [`现状基线.md`](现状基线.md):79）。
2. **系统只有桌面 GL，且底层是 Mesa Zink**：鸿蒙提供系统 `libGLv4.so`，但**不是**桌面原生 GL —— 实测
   `GL_VERSION = 4.2 (Core Profile) Mesa 25.0.1`、renderer `zink Vulkan 1.2(Maleoon 916)`，是
   **OpenGL-on-Vulkan 翻译层**，自带「可能渲染错误」告警与偶发 20–70ms 尖刺；≤1.16 的固定管线还得
   另走自编 gl4es（[`版本支持边界.md`](版本支持边界.md):35-38、
   [`../20-design/render/渲染链-结论.md`](../20-design/render/渲染链-结论.md):60、[`现状基线.md`](现状基线.md):72）；
   MC ≥26.2 另有**原生 Vulkan 后端**（界面可选，经自研 loader shim，见
   [`../20-design/render/渲染链-结论.md`](../20-design/render/渲染链-结论.md) §2.2）。
3. **OS 按应用类仲裁刷新率，华为游戏套件要求引擎内集成**：实测 60Hz 是**系统显示/合成档位**，
   应用侧 90 请求（DisplaySync/VSync/节点帧率）全 `rc=0` 但无效；OpenGTX/超帧/ABR/XEngine 全部要
   「引擎内部调用」或 2in1 不在设备面 ⇒ 应用层拿不到。这是「不改 MC」硬约束的直接后果
   （[`已知限制与待解.md`](已知限制与待解.md):11-17、:62-64、[`现状基线.md`](现状基线.md):85-88）。

> 字样出现（[`已知限制与待解.md`](已知限制与待解.md):61），第 2/3 条是分散实测结论的归纳，非原文短语。

### 2.3 跨层精确时序

> **已移入证据层**（本页只留结论）：`launchJvm` 精确先后 / 线程归属 / surface×JVM 顺序 / want 字段 / glguard 转发链 ⇒
> [`../90-archive/渲染迁移评估/06-cross-layer-timing-evidence.md`](../90-archive/渲染迁移评估/06-cross-layer-timing-evidence.md)（含逐行证据）。
> **结论级要点**：NAPI 收参后**立即 spawn detached 线程并返回**，`JLI_Launch` 跑在该新线程；
> surface 注入与 JVM 启动在**同一回调内串行、surface 先**（`gameRoot` 就绪即启；1.5s 兜底只挂"尺寸未知"分支）；
> `want` 只有 3 字段（`gameRoot` / `jsonPath` / `versionId`），**窗口几何走 `startAbility` 的 StartOptions、账户与运行选项走沙箱文件**；
> glguard 的转发链 = **guard → `libGLv4.so` → Zink → Vulkan**（前两跳 guard 代码可证）。

## 4. 术语表（每条一句话）

- **HSP**：Harmony Shared Package，运行时共享包（本项目 `meowjre`，`libIsolation:true` 独立 namespace），
  跨 HAP 共用同一份随包 native/资源（[`现状基线.md`](现状基线.md):20-35）。
- **HAR**：Harmony Archive，编译期静态库（本项目 `meowcraftlib`/`meowlwjgls`）。
- **HSP 静态并入**：把 HAR 的 native/源码**静态合并**进 HSP（`meowcraftlib` → `meowjre`），entry 只
  `import('meowjre')`（[`现状基线.md`](现状基线.md):35）。
- **`startJvm` / `launchJvm`**：**两层、非同物**——**`startJvm` 定义于 `common/state/JvmLauncher.ets`，
  由 `GameLauncher` 调用；其内调 native NAPI `launchJvm`**（`libmeowjrebridge.so`）。
- **el1**：随包只读可执行区（`bundleCodeDir` / `resources`），**允许 `dlopen`**；JRE 的 `.so` 必须落这里
  （[`../20-design/launch/决策与不变量.md`](../20-design/launch/决策与不变量.md):229-232）。
- **el2**：`filesDir` 应用数据区，**禁止 `dlopen`/执行代码**；JRE 的**数据**（`java.home`）落这里。
- **`devecocli`**：DevEco 命令行工具（`build` / `run` / `device` / `docs` / 静态检查），本项目主力构建入口
  （[`工程与规范.md`](工程与规范.md) §二.3；主仓 `tools/README.md` §3）。
- **hdc**：HarmonyOS Device Connector；**裸 `hdc` 可用**（`/data/app/bin/hdc`）；`list targets` 空时用
  `hdc tconn 127.0.0.1:$(param get persist.hdc.port)` 连本地 TCP，**端口 = 系统参数 `persist.hdc.port`、会变勿写死**
  （[`工程与规范.md`](工程与规范.md) §二.3）。
- **Zink**：Mesa 的 OpenGL-on-Vulkan 翻译层；本机桌面 GL 即 Zink over Vulkan → Maleoon 916
  （[`版本支持边界.md`](版本支持边界.md):35-38）。
- **Mesa**：本机桌面 GL 实现的来源（实测 Mesa 25.0.1；底层 `libgallium`）（[`MC26.x渲染栈-差异分析.md`](../20-design/render/MC26.x渲染栈-差异分析.md):75）。
- **glthread**：Mesa 的 threaded context（GPU 调用交独立线程），开关 = `GALLIUM_THREAD`
  （[`运行时环境变量.md`](运行时环境变量.md):53）。
- **GL guard**：`libmeowglguard.so`，作 LWJGL 的 OpenGL 库，透传 `libGLv4` 并对**贴图上传家族 8 个入口**
  后置同步，规避 Mesa glthread UAF（[`现状基线.md`](现状基线.md):33、[`运行时环境变量.md`](运行时环境变量.md):31）。
- **`GALLIUM_THREAD`**：Mesa glthread 开关（`1` 开 / `0` 关），由「编辑版本 → 线程化渲染」逐版本控制、
  默认开（桌面 GL 与 GL4ES 后端）（[`运行时环境变量.md`](运行时环境变量.md):53）。
- **`MEOW_*`**：本仓新增的实验性 env 开关总称，全走「额外渲染环境变量」，默认关、未设即 no-op
  （[`运行时环境变量.md`](运行时环境变量.md):20-29）。
- **`OHOS_DL_DIR`**：华为 JLI 移植读的变量，指定 JVM `.so` 的 dlopen 平铺目录
  （[`../20-design/launch/决策与不变量.md`](../20-design/launch/决策与不变量.md):254-258）。
- **`OHOS_JAVA_HOME`**：覆盖华为 JLI 由 `dladdr` 推断的 `java.home`（指向 el2 的 JRE 数据）
  （[`../20-design/launch/决策与不变量.md`](../20-design/launch/决策与不变量.md):255-257）。
- **命名换算（旧 → 现）**：`jrelib` → `meowjre`；`libjrebridge.so` → `libmeowjrebridge.so`；
  `jre_bridge.cpp` → `meowjrebridge.cpp`；自研 `libpojavexec.so` → `libmeowcraftbridge.so`；
  `meowlwjgl3` → `meowlwjgls`；`meowjre25`（旧版号模块）→ 版本中性 `meowjre`；native 命名由后缀式
  `liblwjgl_opengl_343.so` → 世代号紧跟基名 `liblwjgl_343_opengl.so`（[`现状基线.md`](现状基线.md):46-60）。
- **HWC**：硬件合成器；本项目上屏走 HWC 直通（hitrace `DrawImage=0`）（[`现状基线.md`](现状基线.md):73）。
- **Fabric 双形态**：**形态① = 官方 `inheritsFrom` 嵌套版本**（Fabric 官方 profile json，子版本靠
  `inheritsFrom` 合并父版本）；**形态② = HMCL `patches[]` 补丁式单实例**（HMCL 归档时把补丁扁平化到
  顶层、并为实例复制 `<id>.jar`）。二者判定见 [`../20-design/launch/启动链-总览.md`](../20-design/launch/启动链-总览.md) §4；
  当前形态②已实机、形态①未实机搁置。
- **NeoForge / Forge / Quilt / Legacy Fabric**：其它 mod loader。**NeoForge（仅 MC 1.20.2+）已支持并实机验证（用户 2026-09-16 确认，三形态）**；**Fabric**（含 Legacy Fabric 识别）早已支持；**Forge = 支持面 MC 1.7–1.20.1 的启动侧 + 应用内安装均已支持**（≤1.12.2：零 JVM 安装 + legacy 直启 + 强制 Java 8 套，**新装（无 `config/splash.properties`）实例 splash 打开也能干净进游戏**，2026-09-29 实机；**1.13–1.20.1：应用内 processor 链安装 + 真 maven 树/有序 classpath 直启**，2026-09-30 起）；**≥1.20.2 交 NeoForge**；**Quilt / 其它未实现**（详见 [`现状基线.md`](现状基线.md) §5 第 28 条、[`已知限制与待解.md`](已知限制与待解.md) §E）。

## 5. 「从零到跑起来」最短路径

### 5.1 环境前置

1. **设备/工具链**：一台 2in1 鸿蒙 PC（开发机 = 运行机 = 目标设备），SDK `6.1.0(23)`（设备 API 26）
   （[`工程与规范.md`](工程与规范.md) §二.3）。
2. **`hdc` 连接 / `devecocli` 的可用范围** ⇒ 见 [`工程与规范.md`](工程与规范.md) §二.3
   （要点：裸 `hdc` 可用；`list targets` 空时按 `persist.hdc.port` 连本地 TCP；部署优先 `devecocli run`，回退 `hdc`；**agent 可构建 / 安装 / 启动，但不抓日志、不操作设备**）。
3. **javac 只能人跑**：任何 `.jar` 步骤（改 lwjgl jar 等）由人在有 JDK 的 shell 执行
   （主仓 `tools/README.md` §3 约定；另见 [`工程与规范.md`](工程与规范.md) §二.3）。

### 5.2 构建与部署

**上机的是 3 个包** —— `meowjre` HSP（现代 JRE）+ `meowjrelegacy` HSP（Java 8 / legacy）+ `entry` HAP（`meowcraftlib` / `meowlwjgls` 是 HAR，编译期静态并入两个 HSP）。
**命令、安装顺序（同版本 ⇒ 先 HSP 后 HAP；升 `versionCode` ⇒ 先 HAP 后 HSP，否则报 `9568284`）、验证、以及附属动作
（`EXTRAS_VERSION` / `JRE_DATA_TOKEN` / 清旧版号模块）** ⇒ 见 [`工程与规范.md`](工程与规范.md) §二 3.1。

### 5.3 最常用的动作

- **连设备 / 构建 / 安装 / 启动 / 核对已装版本** ⇒ 见 [`工程与规范.md`](工程与规范.md) §二.3 + §二 3.1
  （`hdc` 姿势、完整 build+install 流程、产物路径、核对命令都在那里；**核对已装版本属"装"的范围，抓日志与点 UI 不属**）。
- **改 Java 件**（lwjgl jar / `meowcraft_extras.tar.gz`）⇒ **由人**跑
  `sh tools/lwjgl/build_lwjgl_jar.sh` 等脚本（主仓 `tools/README.md` §3）；**从零重建全部自编随包件**同处。
- **跑起来之后卡住了** ⇒ §5.4。

（命令出处：主仓 `tools/README.md` §3；设备侧姿势见 [`工程与规范.md`](工程与规范.md) §二.3。）

   [`glthread崩溃-Bug报告.md`](../20-design/perf/glthread崩溃-Bug报告.md)。
