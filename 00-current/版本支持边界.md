## 支持矩阵

| 版本段 | 状态 | 卡点（机制） | 典型症状 |
|---|---|---|---|
| **1.6.x – 1.12.2**（legacy 格式） | 可玩 | 无 `arguments.jvm` ⇒ **启动器自补 `-cp`**（否则 VM 初始化失败）；依赖 **LWJGL 2** ⇒ **自编 `liblwjgl.so`**（**JNI_VERSION=19 一份通吃 2.9.0/2.9.1/2.9.2/2.9.4**；MC 自带 `lwjgl-2.9.x.jar` 保留，与 LWJGL3 的 native 不冲突）；GL 走 **gl4es**（同 ≤1.16）；须 `org.lwjgl.util.Debug=false`（否则 gl4es 良性错误经 swap 前 `checkGLError` 变致命 `1282`） | 命令里**完全没有 `-cp`** → `Error occurred during initialization of VM`；`UnsatisfiedLinkError liblwjgl.so` / `NoClassDefFoundError org/lwjgl/*` |
| **1.13 – 1.16.x** | 可玩 | 老版本用**固定管线 GL** ⇒ 改走**自编 gl4es（桌面 GL→原生 GLES 翻译层）**；GLES 后端须原生 `/system/lib64/libGLESv3.so`、NOEGL 下必须 `set_getprocaddress()`（否则全黑）、`initialize_gl4es()` 在 context current 之后调 | 桌面 GL compat ⇒ 画面错乱；gl4es 缺 proc-address ⇒ 渲染全黑 |
| **1.17 – 1.21.x** | 可玩 | 走**系统桌面 GL（core profile）**；LWJGL 用随包**单代 3.4.3**（该 jar 服务 1.13–1.21.x，`1.13.2–1.21.11` 缺失成员由 overlay 的 5 个 3.4.x shim 补齐）；现代 shader 管线，不需要固定管线函数 | — |
| **≥ 1.22** | 可玩 | 两道坎：① LWJGL **3.3.3 缺 3.4.x API** ⇒ 收敛为**单代 3.4.3**；② OpenAL **1.23.1 缺 `ALC_SOFT_system_events`** ⇒ 升 **1.24.3** | `NoSuchMethodError`（`glfw*`）；`NullPointerException` at `alcEventIsSupportedSOFT` |
| **≥ 26.3** | 可玩 | 弃 GLFW 改 **SDL3**：**真 SDL3 fork**（钉 `release-3.4.14`）+ 自研 **`ohos` 驱动**；jar 补 `lwjgl-sdl/vma/spvc/shaderc`；随包 `libSDL3.so`/`libshaderc.so`/`libspirv-cross.so`；新后端层 `renderpearl` | `NoClassDefFoundError org/lwjgl/sdl/SDL` → `UnsatisfiedLinkError libshaderc.so` → GL backend 被否 |

## MC 版本 × LWJGL 代 × GL 后端（三条轴，切点不同）

- **LWJGL 轴切在 `1.13`**：`1.6.x–1.12.2` 走 LWJGL2；**`1.13` 起**统一现代**单代 3.4.3**。
- **GL 后端轴切在 `1.17`**：**`≤1.16` 走 gl4es / GL（Compat）**；**`≥1.17` 走系统桌面 GL（core）**，**无系统桌面 GL 的设备改走 gl4es 的 core 后端**（见下「GLES 3.2 后端」条）。
- **`26.3` 起**窗口/渲染层改 **SDL3**。
- ⚠️ **legacy（`1.6.x–1.12.2`）⊂ `≤1.16`，二者不是互斥段**：legacy 只是"另需自编 LWJGL2"的那一段，GL 后端同为 gl4es。
- **Vulkan 后端（可选，独立于上述三轴）**：**MC ≥26.2** 可在逐版本「渲染后端」里选 **Vulkan**；GL 侧库/环境不变（MC 自身 `graphicsBackend` 机制，失败可回退 GL），经自研 loader shim `libmeowvulkan.so`。见 [`../20-design/render/渲染链-结论.md`](../20-design/render/渲染链-结论.md) §2.2；**26.3 已验证**（2026-09-19 用户实机，默认地形 70–80 FPS；WSI 由我方 SDL `ohos` 驱动提供，见 [`../20-design/render/SDL3适配-复盘.md`](../20-design/render/SDL3适配-复盘.md) §七）。
- **GLES 3.2 后端（2026-09-22 起已实现，独立于上述三轴）**：一份 `libgl4es.so` 同时服务 ≤1.16/legacy（FPE）与 1.17–1.21.x（"GL 3.2/3.3 core → 原生 GLES 3.2"core 后端，core 后端由 `MEOW_GL3` 开启），用于**没有系统桌面 GL 的设备**。**状态与逐版本 / 逐设备实测见 [`现状基线.md`](现状基线.md) §5 第 26 条**；方案 / r6→r9 根因与修法见 [`../20-design/render/GL33到GLES32-后端-方案.md`](../20-design/render/GL33到GLES32-后端-方案.md) §15–§18。**2026-09-22 记录（用户 = 项目拥有者）**：1.21.9/1.21.10 这一档（**GL 3.3 core 需求**）在 2in1（MateBook Fold）已实测可玩（r9）。**逐版本 / 逐设备实测矩阵与当前基准见 [`现状基线.md`](现状基线.md) §5 第 26 条。**

| 版本区间 | LWJGL | GL 后端 | 关键坑 |
|---|---|---|---|
| 1.6.x – 1.12.2 | **LWJGL2**（自编 `liblwjgl.so`） | gl4es | 自补 `-cp`；`org.lwjgl.util.Debug=false` |
| 1.13 – 1.16.x | **LWJGL3 单代 3.4.3** | gl4es / 系统桌面 GL（compat） | 原生 `libGLESv3.so`；`set_getprocaddress()` |
| 1.17 – 1.21.x | **LWJGL3 单代 3.4.3** | **系统桌面 GL（core）**：`libmeowglguard` → `libGLv4.so`（Zink/Vulkan）；**无系统桌面 GL 的设备走 gl4es core 后端（`MEOW_GL3`）** | 5 个 3.4.x 兼容 shim |
| ≥1.22（含 26.2） | **LWJGL3 单代 3.4.3** | 系统桌面 GL（core） | OpenAL ≥1.24.3；26.2 另见下节 |
| ≥26.3 | LWJGL3 3.4.3 + `lwjgl-sdl` | 系统桌面 GL（core）+ **SDL3** 窗口层 | 弃 GLFW；随包补 SDL3/shaderc/spirv-cross |

## GL profile / 版本策略

- **core 路径（≥1.17）**：请求 **4.2 core**，失败回落 **3.2 core**。系统桌面 GL 上限 **=4.2**。
  **保留 4.2** 的理由：无副作用（`GL_INVALID=0`、无异常）且**抬高特性上限**（多暴露扩展 ⇒ MC/库可能启用可选快路径）；
  **版本号本身不改吞吐**（吞吐收益未证）。
- **legacy 路径（≤1.16）**：请求 **3.2 compatibility profile**（系统接受 ⇒ **能启动**）；但 **Zink 的 compat/固定管线模拟不完整** ⇒ 贴图/字模错乱。
- **单一事实源**：`common/data/RendererPolicy.rendererForVersion(mcVersion, backend)`（<1.17 ⇒ `compat`，否则 `core`；同时据 legacy 选库 gl4es / 桌面 GL）。
  ⚠️ **`mcVersion` = 版本 json 的**内部 `id`**（真 MC 版本号）**，由 `GameLauncher` 经 `readVersionId(jsonPath)` 读出后传入；
  **不能用实例名/目录名**（实例名可被玩家任取，对齐 HMCL）。
- **链路**：`startJvm(...)`（ArkTS 封装；底层 NAPI `launchJvm(...)`）第 7 参 → `meowjrebridge setenv("MEOWCRAFT_GL_PROFILE")` → 桥 `egl_gl.c` 按 env 选 profile。
  桥日志：`created desktop OpenGL 4.2 (core) context` / `created desktop OpenGL 3.2 COMPATIBILITY-profile context` / 回落链。

## 设备 GL 画像

- **提供给 MC 的 OpenGL** = 系统 `libGLv4.so`（`RENDERER_LIB`，**非自编**，el1 系统路径）：`Mesa 25.0.1` 的 **Zink**（OpenGL-on-Vulkan），
  renderer 串 `zink Vulkan 1.2(Maleoon 916 (ARM_PROPRIETARY))`，**GLSL 4.20**。
- 设备对 **core 与 compatibility 都提供 OpenGL 4.2**（`4.2 (Core Profile)` / `4.2 (Compatibility Profile)`）。
- **Zink 自身告警（决定性）**：`… doesn't support base Zink requirements: have_EXT_custom_border_color have_EXT_line_rasterization`
  ⇒ 底层 Vulkan 驱动缺 Zink 必需扩展 ⇒ **Zink 明说"可能渲染错误"**。
- EGL 默认 `EGL_CLIENT_APIS=OpenGL_ES`；须 `NEED_OPENGL=1`（app 的 `appEnvironments`）才暴露桌面 `OpenGL`（app 进程同理）。

## 下界根因（≤1.16.x，含 1.6.x–1.12.2）

- 老版本用**固定管线 GL**（`glFogfv`/`glMatrixMode`/`glEnableClientState`/`glAlphaFunc`/`glOrtho`…；1.16.5 jar 常量池实证）。
- **机制 = "profile 语义"，不是"指针为空"**：这些函数在 core 上下文里**指针非空**（Mesa 导出全部符号），但**调用返回 `GL_INVALID_OPERATION`**；
  在 compatibility 上下文里 `glMatrixMode`/`glEnableClientState` 返回 `GL_NO_ERROR`（被接受）。
- **为什么能启动**：`RendererPolicy` 对 <1.17（按 json 内部 id 判定）请求 **compatibility profile** ⇒ 固定管线调用被接受 ⇒ 不再 abort。
- **为什么仍渲染错乱**：真正渲染走 **Zink** ——(a) 底层 Vulkan 驱动缺 Zink 必需扩展（见「设备 GL 画像」）；(b) Zink 的 **compat/固定管线模拟不完整**。
- **解 = 自编 gl4es**（弃黑盒 ng_gl4es）+ 桥 GLES 路径；**同一 gl4es 也服务 1.6.x–1.12.2 legacy**（叠加自编 LWJGL2）。
- **版本号不是瓶颈**：4.2 远超 MC ≤1.16 所需的 GL 2.1；问题在"Zink 翻译实现 + compat 固定管线"这一层。

### gl4es 三个关键坑（改这一层必读）
① GLES 后端必须用**原生 `/system/lib64/libGLESv3.so`**（`ndk/libGLESv2.so` 那条会崩）；
② **NOEGL 下必须 `set_getprocaddress()`**（否则 gl4es 跳过硬件探测 ⇒ 渲染全黑）；
③ `NO_INIT_CONSTRUCTOR` + **必须 context 已 current 后再 init**。
逐版本「渲染后端」下拉（推荐 / OpenGLv4 / **GL4ES（兼容性）** / Vulkan（26.2+，实验））已落地（四档选择链见 [`../20-design/render/渲染链-结论.md`](../20-design/render/渲染链-结论.md) §2）；**「GL4ES（兼容性）」按 MC 版本自动分流 ≤1.16 FPE / ≥1.17 core**。

## 上界（26.3）：两个坎与总表

1. **LWJGL 代差**：26.x 声明 LWJGL 3.4.x API（`glfwPlatformSupported` 等）⇒ 现代**只随包单代 `lwjgl-3.4.3.jar`**（服务 1.13–1.21.x 与 ≥1.22）；
   staging 不再选代；natives 用**世代号紧跟基名（`liblwjgl_343{,_opengl,_stb}.so`）+ LWJGL 官方
   `org.lwjgl.system.bundledLibrary.nameMapper` 钩子**加载（`install_natives.sh` 铺名 / `MeowBundledNameMapper` 查名**两处锁步**；natives 必须随包）。
2. **OpenAL 扩展**：26.x 的 `CallbackDeviceTracker` 需要 **`ALC_SOFT_system_events`**（OpenAL Soft 1.24.0 起）⇒ **升 1.24.3**。
- **未知/更老的 lwjgl 就近归并**：`lwjglGeneration` 用**有序世代表**取「≥门槛的最高代」；低于所有门槛（含无该依赖）落到**现代唯一代 3.4.3**
  ⇒ **永不指向未随包世代**（若某版本真缺 API ⇒ 运行期显式 `NoSuchMethodError` = 该加 shim）。
- 3.4.3 的 GLFW overlay 补 3.4.x 独有 **IME/preedit** 三方法（**Java-only 实现，桥零改动**）；
  `GLCapabilities` 由 `tools/lwjgl/gen_glcap.py` 按版本生成（**槽位须与 natives 同版本**）。

## 1.6.x – 1.12.2（legacy 格式）实现要点

- **classpath**：legacy 用 `minecraftArguments`（单字符串）、**无 `arguments.jvm`** ⇒ `MinecraftLauncher` 只从 `arguments.jvm` 取 `-cp` ⇒ 缺失。
  **解**：legacy 分支**自补 `-cp`**（`isLegacyLwjgl(...)` 门控）。
- **LWJGL2 native**：随包只有 LWJGL3、且 `ClasspathStager` 跳过 `org/lwjgl/` ⇒ `NoClassDefFoundError`。
  **解**：**自编 `liblwjgl.so`**（上游 legacy `ref/lwjgl` `2df01dd7`；**JNI_VERSION=19 跨 2.9.0–2.9.4** ⇒ 一份服务 1.6.x–1.12.2），
  保留 MC 自带 `lwjgl-2.9.x.jar`（`isLegacyLwjgl()` 按 `org.lwjgl.lwjgl:` 前缀并**遵守 rules** 识别）。
  json 实证：1.6.1 / 1.6.4 = `2.9.0` + `2.9.1-nightly`；1.7.10 = `2.9.1`；1.8.9 / 1.12.2 = `2.9.2 / 2.9.4`。
- **固定管线 GL**：与 ≤1.16 同一堵墙 ⇒ 同一解（gl4es），另须 `org.lwjgl.util.Debug=false`（见上）。
- `javaVersion=jre-legacy/8`：**legacy 香草**（无 loader）当前 JRE（26）可跑、**无需 JRE8**；但 **Forge ≤1.12.2（LaunchWrapper）需要 Java 8**（`java.util.jar.Pack200`〔JDK 14 删〕与可用 `SecurityManager`〔JDK 24 禁〕）⇒ 由 `JavaPolicy` 强制选第二套 `meow_jre_legacy`（见 [`../20-design/launch/环境与载体.md`](../20-design/launch/环境与载体.md)、[`现状基线.md`](现状基线.md) §5 第 28 条）。
- **支持窗口之外**：1.6.x 之前（1.4.x / 1.5.x）同为 legacy 格式、可安装但不作保证。

## 26.2 的额外要求（不是崩溃记录，是必须满足的条件）
- 版本 json `arguments.jvm` 把 JNA/LWJGL/netty 工作目录指向 `${natives_directory}/{java,jna,lwjgl,netty}` **且排在启动器参数之后** ⇒
  我们的 `${natives_directory}` 为让 native 从 el1 加载必须只读 ⇒ `NativeLibrariesBootstrap.createDirectories` 被拒。
  **须在 json 参数之后统一覆盖为可写沙箱**：`java.library.path`、`jna.tmpdir`、`org.lwjgl.system.SharedLibraryExtractPath`、`io.netty.native.workdir`
  （native 仍按名从 el1 加载：`org.lwjgl.librarypath` + `MeowBundledNameMapper`）。
- bootstrap 按序**强载 9 个库**（fail-fast：`GLFW,shaderc,vma,tinyfd,freetype,OpenAL,OpenGL,spvc,STB`）⇒
  ① **按档选 LWJGL Vulkan 库名**：非 Vulkan 档 `-Dorg.lwjgl.vulkan.libname` 指向不存在的占位库（`VK.create()` 失败 ⇒ 跳过 `shaderc/vma/spvc` 组）；
  **Vulkan 档**指向自研 shim `libmeowvulkan.so` 并追加 `--graphicsBackend vulkan`（随包 `liblwjgl_vma.so` 等已就位；见 [`../20-design/render/渲染链-结论.md`](../20-design/render/渲染链-结论.md) §2.2）；② **补 `liblwjgl_tinyfd.so`**（会被 eager 加载；gen-agnostic，manifest tag `common`）。
- 26.2 起 `JLI_Launch` **正常返回**（老版本内部 `exit()` 带走 `:game` 进程）⇒ 桥**必须在返回后 `_exit()`**（短延时让日志上抛），否则游戏窗口/进程残留。
- 工具链：`build_lwjgl_jar.sh` 的默认 `--work` 必须含版本号（否则两代 jar 互相覆盖）。

## 26.3（GLFW → SDL3）实现要点

- 版本 json 去 `lwjgl-glfw`、增 `lwjgl-sdl:3.4.3`；新后端 `renderpearl`（用 `shaderc/spvc/vma`）。
- **做法**：**真 SDL3 fork**（钉 `release-3.4.14` = 官方 `libSDL3.so.git` 修订）+ 自研 **`ohos` 视频/鼠标驱动**接入既有桥（`meow_environ`/OHNativeWindow/EGL/输入环）。
- 全链 14 项问题与解（`glGetError` 指针同一性、`shaderc` 缺件、共享 EGL 面导致黑屏、输入生产者 GLFW-thunk 门控、**鼠标 screenHeight 偏移**、文本 NUL/双发、grab 相对模式）
  见 [`../20-design/render/SDL3适配-复盘.md`](../20-design/render/SDL3适配-复盘.md) §一。

## 触发判断速查（用户报错一眼定位）

| 症状 | 判定 |
|---|---|
| `glFogfv`/`glEnableClientState` 指针 0 / JVM abort / *"essential and/or <1.13"* | 版本 ≤1.16.x（含 legacy）：应走 **gl4es**（后端选「推荐」或「GL4ES（兼容性）」）。误选 OpenGLv4/core ⇒ 固定管线被拒（错乱/崩）。gl4es 全黑 ⇒ 查 `set_getprocaddress` 是否注入、GLES 后端是否原生 `libGLESv3.so` |
| 启动即 `Error occurred during initialization of VM`，且命令里无 `-cp` | **1.6.x–1.12.2**（legacy）：应走 legacy 分支**自补 `-cp`** |
| `UnsatisfiedLinkError: liblwjgl.so` / `NoClassDefFoundError org/lwjgl/*` | **1.6.x–1.12.2**：`liblwjgl.so` 未随包，或改 `libs/` 后未清模块 build 重建（tag `common`）；亦查 `isLegacyLwjgl` 是否漏判（须遵守 rules） |
| `NoSuchMethodError` + `glfw*`（或现代缺失成员） | 现代版本却跑到旧世代 / 缺 3.4.3 兼容 shim（查随包 `lwjgl-3.4.3.jar` + `overlay-3.4.3/` 是否齐） |
| `NullPointerException` at `SOFTSystemEvents.alcEventIsSupportedSOFT` | 版本 ≥1.22 但 OpenAL <1.24（缺 `ALC_SOFT_system_events`） |
| `liblwjgl_343.so not found in org.lwjgl.librarypath` | 改 `libs/<abi>/` 后未清模块 build 重建（hvigor 不追踪 libs 增删） |
| `UnsatisfiedLinkError` meowcraftbridge | 缓存旧 jar（`EXTRAS_VERSION` 未升 / 旧缓存） |
| JRE `could not find libjava.so` | JRE 家族不支持 `OHOS_DL_DIR` 分体（如 BiSheng hnp，见 [`../30-supply-chain/bisheng-hnp-trial.md`](../30-supply-chain/bisheng-hnp-trial.md)） |

## JRE 版本路线（现为两套：26 与 8）

- JRE 数据根 `filesDir/meow-jres/<id>` 已为多版本就位（**现两套**：`meow_jre` = 26、`meow_jre_legacy` = Java 8）；**前提 = `libjli` 含 `OHOS_DL_DIR` / `OHOS_JAVA_HOME`**（分体启动）。按 (MC 版本 × loader) 由 `JavaPolicy` 择一，见 [`../20-design/launch/环境与载体.md`](../20-design/launch/环境与载体.md)。
- 详见 `主仓` 工程目录下 `tools/jre26` 与 `tools/jre8` 的适配流程。
