## 2. launcher.jar 收编战役档案（**Pojav 派生版**，已由净室版取代 —— 踩坑教训，勿重蹈）

> ⚠️ 本节正文的 `41 类` / `a2d449a4…` / `fc342005…` / `20260910-meow-launcher4` 等**均为该轮 Pojav 派生版**的
> 历史值；**现行 clean-room `launcher.jar`**（20 类）及令牌见下"产物/令牌现状"、§3 与 digest v25。

**血统判定**：launcher.jar ≠ Amethyst（Android fork 无 headless 入口）。真身 =
**PojavLauncher_iOS `JavaApp/src/launcher`** @ 钉死 commit `1eeab5c1ee6f80991e09cc411054419374852cff`
（GPL-3.0）。克隆在 `ref/PojavLauncher_iOS`。

**工程链**（`Harmomeow-Craft-Launcher/tools/launcher/`）：
- `rebuild_for_meowcraft.sh`：worktree@pin → 打 deltas(0001-0003) → overlay(MeowUIKit) → javac `--release 17`（**用户跑**：agent 无 JVM）。
- `finalize_for_meowcraft.sh`：pre-shade 组装 + `relocate_gson.py`（打回 `meow.gson`）+ 换 rawfile tar（**agent 可跑**，纯 python）。
- deltas：`0001-pojavlauncher-meow`（删 macOS 块 / cacio 门≤21 / 崩溃接 MeowUIKit / 删 libMoltenVK / 修 forge splash replace bug）、
  `0002-tools-meow`（**DIR_\* getenv→System.getProperty**，OHOS 以 `-D` 传；删 uikit import）、
  `0003-minecraftaccount-meow`（**删 PojavAccountJNI loadLibrary** → token 常量 `88888888-…`）。

**减脂**（`build_launcher_meow.sh` 内置排除）：35 → **23 源编译**（jar 41 类）——剔 `uikit/`、
`value/launcherprofiles/`、`JVersion`、`ForgeInstallProfile`、`JAssets`/`JAssetInfo`、`LWJGLGLFWKeycode`
（对启动链 0 引用）。编译 CP **仅 gson-2.13.1**。`android/util`（AOSP ArrayMap，1617 LOC）**保留**：
HOML `lwjgl.jar` 的 `GLFW` 运行时用它且不自带；待 lwjgl 重建换 `HashMap` 后可连根拔。

**⚠️ 踩坑实录（别再犯）**：
1. **补丁重生成丢 hunk**：某次重做 0002 只保留"删 import"，把 `getenv→getProperty` 弄丢 →
   Tools 变回 `getenv` → OHOS 无此 env → `null/accounts/Meow.json` 崩溃。**教训：补丁改动后必须在 pristine worktree 上全量 apply 验证目标符号消失**（如 `grep getenv Tools.java == 0`）。
2. **不清 classes 目录**：javac 写同一 `out/classes`，旧构建残留 .class 混入打包（"56 类没减下去"假象）。
   **教训：构建脚本先 `rm -rf "$OUT/classes"`**（已修）。
3. **逐字节可复现验证法**：`mine.jar`（拼装） vs `sh rebuild...`+finalize 产物 → `cmp`/sha 全等才算数
   （本轮已证：jar sha `a2d449a4…`、tar `fc342005…` 完全一致）。

**产物/令牌现状**（**该文撰写时基线** digest v25；**现役值以 [`assets-digests.txt`](../30-supply-chain/assets-digests.txt) 为准**）：`meowcraft_extras.tar.gz` `b76f45f7…`（3 jar = lwjgl-3.4.3 + launcher + gson；12,303,958 B）；`EXTRAS_VERSION=20260915-lwjgl-tagname`；

### 候选 C：JRE 收编（去中间人）——✅ 完成（2026-09-12）
> ✅ **重大进展（2026-09-12）：魔改官方 glibc 件跑通，用户实测 MC 可玩**。做法：
> （1）兼容层 `libc6.so`（25 个 glibc 缺失符号，导出 `GLIBC_2.17`）；（2）官方 **26** lib（剔除 MC/JVM 不用的
> `jawt/awt_xawt/jsound/splashscreen/j2pkcs11/attach/j2pcsc`）**原地改 `.dynstr`
> NEEDED**（`libc.so.6`/`ld-linux`→`libc6.so`；`pthread/dl/rt/m`→`libc.so`；`z`/`freetype` 去版本号）；
> （3）**`libjli` 已自编**（`jdk-26.0.2.1-ga` 源〔更新仓 `openjdk/jdk26u` @ `d55edf1cba61…`〕+ `patches/libjli-ohos.patch` 的 OHOS 分体 patch：`GetJDKInstallRoot` 认
> `OHOS_JAVA_HOME`、`GetJVMPath` 认 `OHOS_DL_DIR`、跳过 exec 重入；当时实机通过）；（4）**仅 `libjvm` 仍用现役 OHOS 件**，
> 数据用官方 26.0.2.1。
> **两大坑**：① **禁 patchelf**（`libc.so.6` 的 VERNEED + `--add-needed` 会触发编辑重排、用 `X` 填充 → loader 读坏符号名）；
> 改**原地覆盖 `.dynstr`**（新名更短+补零，尺寸/偏移不变）。② 官方 `libjli` 靠 `/proc/self/exe`+`/lib/`/`/bin/` 标记推
> JRE 路径，OHOS 路径是 `libs/arm64`（`libs`≠`lib`）→ `could not find libjava.so`；故 libjli 必须自编带 patch。
> 取证：OHOS loader 忽略符号版本；ucontext/stat/sigjmp ABI glibc==musl。
> **✅ 全收编完成（2026-09-12）**：`libjvm`（HotSpot）已自编——设备**不能执行编译产物**（可写路径 ELF `EPERM`），
> 故借用户 **openEuler 24.03 aarch64 容器**（挂载宿主工作区 `/mnt/linux_share`）**原生编**：boot JDK = **官方 JDK26
> (glibc/aarch64)**，`configure --with-stdc++lib=static` → `make hotspot`；再本地魔改（`patch_dynstr` + `libc6.so`）
> + 打 **HotSpot 分体 patch**（`java.home` 认 `OHOS_JAVA_HOME`、`dll_dir` 认 `OHOS_DL_DIR`）。
> **关键教训**：① shim 必须**无版本**导出（否则 musl 版本匹配拒绝）；② HotSpot 与 libjli 都要分体 patch。
> **精确对齐官方源（2026-09-13）**：自编件源 = 官方 26.0.2.1 发布同一 commit（更新仓 `jdk26u` `jdk-26.0.2.1-ga` @ `d55edf1cba61…`，`SOURCE_DATE_EPOCH=1784133400`）；**只有自编 `libjvm`/`libjli` 变**，官方 26 lib/`libc6.so`/数据 tar 不变 → **数据令牌 `26.0.2.1+1-7-r1` 未升**（现网无需重解压数据）。
> **工具/配方**：`Harmomeow-Craft-Launcher/tools/jre26/`（`rebuild_for_meowcraft.sh` + `linux_bootstrap.sh`/`linux_build_jvm.sh`
> + `patches/{libjli,os_linux}-ohos.patch`；README 详解）；源码 clone 落位 `ref/jdk26u`，宿主 worktree `stuffs/research/jdk26/jdk26u-src`，scratch `stuffs/research/jdk26/{_inspect,jdk26u-src,out,out-linux}`。

**原始评估（立项时）**：
- 现状：JRE 30 so+数据 = 外部历史件（预编译 JRE 包，OpenJDK 25 OHOS musl；release 文件归因，仓库无源码树/构建配方）。
- 出路：换 **OpenHarmony 官方 OpenJDK 发布物**直取（校验 digest），或源码自编；分体启动前提 =
  `libjli` 含 `OHOS_DL_DIR`/`OHOS_JAVA_HOME`（见 `../30-supply-chain/bisheng-hnp-trial.md`）。
- 工作量：取官方件 < 自编；自编 = 大工程（OpenJDK 全链）。

### 候选 D：SDL3 桥接（解锁 MC 26.3+；平台绑定换代）
> ✅ **已完成（2026-09-11）**：**真 SDL3 fork**（钉 `release-3.4.14`）+ 自研 `ohos` 视频/鼠标驱动 + 随包
> `libSDL3.so`/`libshaderc.so`/`libspirv-cross.so` → **26.3-rc-1 可玩（2026-09-11 实测）**。
> 见 [`render/SDL3桥接-设计.md`](../20-design/render/SDL3桥接-设计.md)、[`render/SDL3适配-复盘.md`](../20-design/render/SDL3适配-复盘.md)。以下为立项时的评估。
> **📄 探测记录见 [`../00-current/版本支持边界.md`](../00-current/版本支持边界.md)「26.3」。**

- **动机**：MC **26.3 起弃用 GLFW、改用 SDL3**（版本 json 无 `lwjgl-glfw`，新增 `org.lwjgl:lwjgl-sdl:3.4.3`；
  MC 侧 `blaze3d.platform.SDLEventHandler/SdlDebug`）。（立项时窗口为 1.17–26.2，26.3+ 不可跑；**现已 1.6.x–26.3，26.3 可跑**。）
- **为何不是"再加个模块"**：LWJGL 的 `lwjgl-sdl` 是**直连绑定**（`mapLibraryNameBundled("SDL3")` → 真 `libSDL3.so`），
  不是 `liblwjgl_sdl.so` 那种 JNI；且**我们的窗口/事件/输入桥是净室 GLFW stub**（`glfw*`），26.3 **不再走它**。
- **要支持需三件事**：① 随包 `lwjgl-sdl` Java 模块（给 3.4.3 加模块，类 tinyfd，见 `meowcraft_lwjgl_selfbuild`）；
  ② OHOS 可用的 **`libSDL3.so`**；③ 为 **SDL3 的窗口/事件/输入**做等价桥接。
- **两条路线**：
  - **(a) 自编 SDL3 for OHOS**（真实 SDL3 + SDL 的 OHOS/自定义 video 后端）。
  - **(b) 净室 SDL stub**：只实现 MC 用到的 SDL 子集（窗口/事件/键盘 scancode/鼠标/剪贴板…），桥到 ArkUI 窗口 + 既有输入链；
    等于把当年 GLFW 桥再来一遍，但 **SDL3 面比 GLFW 大**（scancode 体系、事件模型不同）。
- **风险/未知**：SDL3 是否自带 OHOS video/input 后端；MC 26.3 对 SDL 子集的真实依赖面（需先拿到调用清单）。
- **立项时判定**：大工程，暂不立项；支持窗口冻结 1.17–26.2。→ **已推翻：2026-09-11 落地为真 SDL3 fork，26.3-rc-1 实机可玩**
  （[`render/SDL3桥接-设计.md`](../20-design/render/SDL3桥接-设计.md)、[`render/SDL3适配-复盘.md`](../20-design/render/SDL3适配-复盘.md)）。
