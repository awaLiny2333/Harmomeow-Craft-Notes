## 0. 结论先行

1. **"装一个原版版本" = 往共享池填充 4 类文件 + 落 2 个版本文件**：
   `versions/<id>/<id>.json`、`versions/<id>/<id>.jar`、`libraries/<maven 路径>`、
   `assets/indexes/<assetId>.json` + `assets/objects/<2>/<hash>`。
2. **Mojang 契约极简**：一个 manifest 列版本 → 每版本一个 json → json 给出 client jar / libraries /
   assetIndex 的地址 + sha1。**sha1 是唯一完整性原语**。
3. **HMCL 的 `patches[]`/优先级/`inheritsFrom` 全是为 modloader 服务的**；纯原版用不上 →
   **直接存原始 Mojang json 即可，无需归一化重写**（我们启动器只读 `id/mainClass/javaVersion/arguments/libraries/assetIndex/downloads`）。
4. **★ 安装必须严格复刻 HMCL 的下载行为**（用户决策，2026-09-10）：即使某些件 Meowcraft 自己启动
   不加载，也**照下**（含 natives classifier jar、`org.lwjgl:*` 库等），以保证产物对
   **其他平台 / 其他启动器兼容**。**"我们的启动期不加载下载的 .so" 是运行期选择，与安装无关。**
5. 我们**现有启动链已消费这套目录**（`VersionScanner` 扫 / `ClasspathStager` 平铺 /
   `MinecraftLauncher` 组参 / `GameLauncher` 编排）→ **安装器只需"把文件放进去"**，启动侧几乎零改动。
6. 体量参考（本机实证）：**1.21.10 ≈ 547MB**（client 30.6MB + 115 库 82MB + 资源 4397 个 435MB）；
   26.1.2 client 38.1MB + 107 库 + assetIndex 30。

## 1. 官方目录契约（装完长什么样）

| 概念 | 路径 / 来源 |
|---|---|
| 版本实例 | `versions/<id>/` |
| 版本清单 | `versions/<id>/<id>.json` |
| 主 jar | `versions/<id>/<id>.jar`（来自版本 json 的 `downloads.client`） |
| 共享库 | `libraries/<group 点转斜杠>/<artifact>/<ver>/<artifact>-<ver>[-classifier].<ext>` |
| 资源索引 | `assets/indexes/<assetIndex.id>.json`（来自 `assetIndex.url`） |
| 资源对象 | `assets/objects/<hash 前2位>/<hash>`（内容寻址） |

- 版本 json 的 `arguments.game` 含 `--gameDir ${game_directory} --assetsDir ${assets_root} --assetIndex <id>`；
  `arguments.jvm` 含 `${natives_directory}`/`${library_directory}`/`${classpath}`——**占位符由启动器填**。
- 版本 json **本身与平台/隔离无关**；隔离只切"运行目录"一个变量（Meowcraft 已实现，默认关）。
- `assets/`+`libraries/` 永远共享。

## 2. HMCL 安装机制（写盘序列）

编排 `HMCLCore/.../download/DefaultGameBuilder.java`、`download/game/GameInstallTask.java`；
落盘 `game/DefaultGameRepositoryDraft.java`。

```
newGameBuilder(id) → 拉 Mojang 版本 json → 转 game patch（丢 client jar 引用）
   ├─ 下 client jar（FATAL，进内容寻址缓存）
   └─ 下 assets + libraries（NON-FATAL，失败被刻意吞掉）
→ resolve 成最终清单 → draft.put(manifest) + draft.putPrimaryJar(cachedJar)
→ commit()：建 versions/<id>/ → 写 <id>.json（归一化）→ 拷缓存 jar 为 <id>.jar → 发布快照
```

| 项 | HMCL 做法 | 证据 |
|---|---|---|
| client jar 失败 | **致命** | `GameInstallTask.java:97-105` |
| libraries/assets 失败 | **非致命（设计如此）** | `GameInstallTask.java:97-105`（`withRunAsync` + `relyingOnDependents=false`） |
| 落盘时刻 | 下载期**不写**版本目录；`commit()` 才写 2 个版本文件 | `DefaultGameRepositoryDraft.java:233-340` |
| 共享库/资源 | **在回滚边界之外**，下载即落盘 | `DefaultGameRepositoryDraft.java:43-46` |
| 回滚点 | `<base>/.hmcl/repository-drafts/commit-*` | `:473-481` |
| 幂等 | 存在即跳；校验 jar 内 `checksums.sha1` / 对象 sha1 / 索引 sha1 / client jar 内容缓存 | `GameLibrariesTask.java:89-120`、`GameAssetDownloadTask.java:95-114` |
| natives | **安装期不碰**（HMCL 在启动期解压） | `DefaultLauncher.java:456-492` |
| 存盘 json | 归一化重写（非原始 Mojang） | `GameInstanceManifest.java:592-657` |

> **对原版的启示**：modloader 才有 `patches[]`/优先级/`inheritsFrom`；纯原版 = `resolve` 退化为恒等。
> 但**产物要兼容其他启动器**，故仍按下节**完整**下载。

## 3. HMCL 下载机制

`download/{DownloadProvider,MojangDownloadProvider,BMCLAPIDownloadProvider,AutoDownloadProvider}.java`；
传输 `util/io/FetchTask.java`。**精确 URL 常量以 `ref/HMCL` 源码为准，此处只记结构。**

### 3.1 Provider 与地址模板

HMCL 只有 **两个** provider，其余靠**前缀替换**（URL 注入）把 Mojang json 内嵌地址重写到镜像：

| 产物 | 官方（Mojang） | 镜像（BMCLAPI） |
|---|---|---|
| 版本 manifest | `piston-meta` 的 `mc/game/version_manifest.json`（**v1，非 v2**） | 镜像根 + 同路径 |
| 版本 json | manifest 的 `versions[].url` 原样 | 前缀重写 |
| client jar | `piston-data` 的 `v1/objects/<sha1>/client.jar` | 前缀重写 |
| 库 | `libraries.minecraft.net/<group-path>/...` | 镜像根 + `/libraries/...` |
| 资源索引 | `piston-meta` 的 `v1/packages/<sha1>/<id>.json` | 前缀重写 |
| 资源对象 | `resources.download.minecraft.net/<2>/<hash>` | 镜像根 + `/assets/<2>/<hash>` |

- Provider 顺序（`HMCL/.../setting/DownloadProviders.java:87-97`）：`DEFAULT` = 中国大陆 `[BMCLAPI, Mojang]`／
  其它 `[Mojang, BMCLAPI]`；可选 `OFFICIAL` / `MIRROR`。
- 每文件尝试"候选地址列表"，逐个失败回退（`AutoDownloadProvider` + `FetchTask.java:104-116`）。
- 该 checkout **无测速**；选择是静态持久化设置。

### 3.2 校验（唯一原语 = SHA-1）

| 产物 | 校验 | 证据 |
|---|---|---|
| client jar | ✅ sha1 | `GameDownloadTask.java:71-84` |
| libraries | ✅ sha1（JSON 提供时）+ jar 结构校验 | `LibraryDownloadTask.java:118-123` |
| 资源对象 | ✅ sha1 | `GameAssetDownloadTask.java:97-105` |
| 资源索引 | 有条件 sha1（URL 含 hash 时）+ JSON 可解析 | `GameAssetIndexDownloadTask.java:73-104` |
| manifest / 版本 json | ❌ 不校验 | `GetTask.java:55-57` |
| 不匹配 | 弃临时文件 → **重试**（默认 5 次，间隔 200ms） | `FetchTask.java:474-486` |

### 3.3 传输机制

- 并发：全局线程池 + 信号量，`min(核数×4, 64)`（虚拟线程）。
- 重试 5 次 / 200ms 退避；**断点续传** = `Range` + `If-Range`（需强 ETag/Last-Modified）。
- 连接/读超时 10s；**手动重定向**（≤20）；`accept-encoding: gzip`。
- 缓存：内容寻址 `cache/<ALG>/<2>/<hash>` + ETag 远程缓存；BMCLAPI 额外 `x-bmclapi-hash` 校验通道。
- 进度：每秒更新；可取消。

### 3.4 Java 运行时

**装原版不下 JDK**。版本 json 的 `javaVersion.majorVersion`（1.21.10→21、26.1.2→25）只是运行时要求；
JDK 获取是**启动期独立事项**。我们**随包 JRE 25** 可覆盖 class 65(Java 21) 与 Java 25 版本。

## 4. 原版最小安装/运行集（本机实证）

| 版本 | 库数 | assetIndex | client jar | javaVersion | 备注 |
|---|---|---|---|---|---|
| 1.16.5 | 57 | `1.16` | 17.5MB | 8 | 我们**可启动但渲染错乱**（Zink compat） |
| 1.19.4 | 88 | `3` | 23.5MB | 17 | ✅ |
| **1.21.10** | **115** | **27** | **30.6MB** | 21 | ✅ 可玩；库合计 82MB；资源 4397 个 435MB |
| 26.1.2 | 107 | 30 | 38.1MB | 25 | ✅ 可玩（需 LWJGL 3.4.3） |

**写盘清单（严格对齐 HMCL/官方）**：`versions/<id>/{<id>.json,<id>.jar}` + `libraries/**`（rules 过滤后）

- **legacy `virtual`/`map_to_resources`**：窗口从 1.17 起，基本用不到 → 可延后。
- **log4j 客户端配置**：HMCL 也不下 → 可不下。

| # | 约束 | 事实 / 依据 | 对安装的影响 |
|---|---|---|---|
| P1 | **下载的 `.so` 不可 dlopen** | fs-verity 只签随包 el1 件；数据区写入件 dlopen=EINVAL（[`../20-design/launch/决策与不变量.md`](../20-design/launch/决策与不变量.md):201-204,265-268、[`../30-supply-chain/bisheng-hnp-trial.md`](../30-supply-chain/bisheng-hnp-trial.md):40-50） | **只影响我们启动期**；**不影响安装**（natives 照下） |

| P3 | **用户目录写权限是临时的** | Picker 授权随 App 退出失效；`LauncherState.activated` 不持久化（[`../00-current/工程与规范.md`](../00-current/工程与规范.md)） | **决策：每次当场申请**（不引入持久授权） |

| P5 | 文件哈希 | `@kit.CoreFileKit` `hash.hash(path,'sha1')`（**返回大写 hex**）/ `createHash` 流式 | SHA-1 校验可实现，注意大小写归一 |
| P6 | 大文件/目录 | 大文件下载有 `2300023` FAQ；递归 mkdir 需 `recursion=true` | 需流式/分批 |
| P7 | 运行时伪装约定 | JVM `os.name=Linux`、`os.arch=aarch64`（`LaunchDefaults.ets:13-21`） | 库/资源按 linux-aarch64 过滤 |
| P8 | 版本支持窗口 | 1.6.x–26.3（≤1.16 走 gl4es；legacy 走 LWJGL2）；`lwjglGeneration` 就近归并、现代单代 3.4.3 | **决策：不限制可下载版本**，能否可玩另说（UI 标注） |

## 6. Meowcraft 现状 vs 目标（Gap）

**已有（可复用）**：
- 路径模型 `Paths.MC_VERSIONS_DIR`/`versionDir()`；`assets_root`/`libraries` 约定已固化在 `MinecraftLauncher`。
- `VersionScanner.scanVersions` + `LauncherState.refreshVersions()/versionEpoch`（装完刷一次即可见）。
- 版本 json 解析 / LWJGL 选代 / `collectJarSources`；`ClasspathStager.stageClasspathDir` 平铺 + extras + oshi + 剪枝。
- `fileUri.FileUri(uri).path`；`SettingsTools`/`GameDirsTools` 持久化范式；`AppStorageV2` 共享态；`JavaEnvView.install()` UI 范式。

**缺失（全新）**：① 无任何网络层；② 无版本 manifest 拉取 + 选择 UI；③ 无安装器模块；
④ 无 `libraries/` 写入；⑤ 无 `assets/` 写入；⑥ 无 client jar/版本 json 写入；⑦ 无完整性校验；
⑧ 无进度/取消/错误/半装状态；⑨ 无 TaskPool 并发编排。

> 印证：`架构决策与踩坑.md` §9 把"在线版本下载"列为未实现候选；[`三项目对比-早期快照.md`](三项目对比-早期快照.md)（已归档）表明
> HomoLauncher 靠外部 zip 导入，非在线。

## 7. 装机流程（设计）

```
[前置] 首页选/授权 .minecraft 根目录（现有 GameDirsView）
[1 版本发现] 拉 version_manifest.json（BMCLAPI 优先，Mojang 回退）→ 解析 versions[]
[2 选择+预检] 用户选 id → 拉版本 json → 读 javaVersion/org.lwjgl 代/是否已装 → 标注可玩性
[3 构造清单] 按 rules(linux/aarch64) 过滤 → 产出待下项 {json, client jar, libraries[], assetIndex, objects[]}，每项带 url+sha1(+镜像候选)
[4 下载] 小对象走 http 并发；大文件走 request.agent(≤4)；存在且 sha1 匹配 → 跳；否则下→校验→落盘(临时名→rename)
[5 落盘收尾] 写 versions/<id>/<id>.json（原始）+ <id>.jar；可选半装标记
[6 刷新] LauncherState.refreshVersions() → 列表出现新版本
[7 启动] GameLauncher.launchGame 不变
```

设计要点：原始 json 直存（省掉 merge/patch 引擎）；镜像用"前缀替换表"一套代码支持两源；
全量 sha1 幂等；natives/lwjgl **照下**（跨启动器兼容）。

## 11. 实现进展（2026-09-10 代码落地并通过编译；2026-09-15 实机验证，用户确认）

新增（`entry/src/main/ets/`）：
- `common/constants/DownloadContract.ets`：下载源契约（官方 host / BMCLAPI 前缀替换表 / `candidatesFor` / rules 环境常量 / 超时并发）。

- `common/state/InstallerState.ets`：安装器共享状态（`AppStorageV2`），单任务（`installingId` 占用即拒绝并行），阶段/进度/错误（错误用 **错误种类码** 而非 UI 文案，UI 侧映射资源）。

修改：
- `common/constants/Paths.ets`：`MC_LIBRARIES_DIR`/`MC_ASSETS_DIR`/`MC_ASSETS_INDEXES_DIR`/`MC_ASSETS_OBJECTS_DIR`/`DOWNLOAD_PART_SUFFIX` + `librariesDir/assetsDir/assetsIndexesDir/assetObjectPath/versionJsonPath/versionJarPath`。
- `common/data/VersionScanner.ets`：导出 `resolveGameRoot(dirUri)`（URI→游戏根物理路径；**选中目录即根**，空目录也有效，见下）。

关键实现取舍：
- **选中目录即游戏根（2026-09-12 修）**：早期 `locateGameRoot` 要求目录已存在 `versions/` 才认作有效根，导致"选空文件夹 → 点安装静默无反应"。现以所选目录**直接**为根，空目录由 `ensureParent`（`mkdir -p`）递归创建 `versions/libraries/assets`，`installRemote` 也不再静默（失败给可见错误）。见记忆 `meowcraft_selected_dir_equals_minecraft_root`。
- **安装时设实例名（2026-09-12，对齐 HMCL）**：点远程版本「安装」→ 展开「为 `<版本>` 设置实例名称」面板（TextInput + 「确认安装」+「取消」），默认名 = 版本号。**实例名 = `versions/<实例名>/` 目录名**（承接"身份=目录名"）；`installVersion(gameRoot, remote, source, instanceName, cb…)`。校验 `isValidInstanceName`（**对齐 HMCL**：非空且非纯空白、非 `.`/`..`、不以 `.`/空格结尾、不含 `/` `\` 控制字符及 `: * ? " < > |`；**不设"保留后缀"**）+ `versionDirExists`（命名冲突）→ 非法/冲突则禁止安装并提示。允许同一 MC 版本装成多个实例（不再因"已安装"禁用按钮；**不显示「已安装」标记**——列表放不下，冲突由命名校验兜住）。见记忆 `meowcraft_vanilla_install_plan`。
- **原始 Mojang 版本 json 直存**（不做 HMCL 式归一化）；**最后**才写 `<实例名>.json`，保证扫描器不会识别到半装版本（json 内部 `id` 不改）。
- **严格复刻 HMCL 下载集**：natives classifier jar、`org.lwjgl:*` 库一如下载；rules 按 linux/aarch64 过滤（与 HMCL 当前环境一致）。
- 幂等：目标文件已存在即跳过；新下载做 sha1 校验（`@kit.CoreFileKit` `hash.hash`，返回大写 hex）。
- **★ 资产对象按 hash 去重 + 下载项按 `destPath` 去重**（2026-09-10 修）：老版本（如 **1.7.10**）资产索引里**多个名字指向同一 hash**（实测 686 名字/674 唯一，12 个重复，如 `icons/icon_16x16.png` 与 `minecraft/icons/icon_16x16.png`）。若每个名字生成一个下载项，两条并发任务会写**同一个 `destPath.part`** → 互相 `TRUNC`/截断 → sha1 mismatch（空文件表现为 `DA39A3EE…`，即空串 sha1；且同对象每次哈希不同）。`assetObjectItems` 按 hash 去重 + `runDownloads` 按 `destPath` 防御性去重。
- 失败语义：本版**失败即中止**（比 HMCL 的"libraries/assets 非致命"更严格，便于用户重试；重试幂等）。
- 远程版本列表（可能几百项）用 **`List` + `Repeat<RemoteVersion>().each(ListItem).virtualScroll()`** 懒加载，只渲染可见区；面板列表定高（`DOWNLOAD_LIST_HEIGHT`）。`virtualScroll()` **空参即可**触发懒加载（无需填 `totalCount`）。首版直接铺进 `Column` 会一次性渲染几百项、加载瞬间卡死，已修。
