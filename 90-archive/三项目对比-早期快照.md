# 三项目横向对比与迁移路线建议

> **历史定位（2026-09-10）**：本文是早期路线研究快照。Meowcraft 实装为**净室自研**，
> 未采用 HomoLauncher/Amethyst/HMCL 代码；三者仅作工作区外部参照，不入仓库、不随包。

## 1. 横向对比总表

| 维度 | HomoLauncher | Amethyst | HMCL |
|------|-------------|----------|------|
| 运行平台 | HarmonyOS NEXT | Android / iOS | Win/Mac/Linux/FreeBSD |
| 语言/栈 | ArkTS + HAP/HSP | Java/Kotlin + JNI | Java + JavaFX |
| JVM 来源 | 内置 HSP（jre17/jre25, arm64） | CI 预编译（jre8/17/21/25, 多架构） | 系统 JRE 扫描/下载管理 |
| 渲染 | dl_open + mobileglues/gl4es/GLv4 | 完整 JNI + 同套转换层 | 仅传环境变量（不内嵌） |
| 输入桥 | ArkTS HOMLBridge | input_bridge_v3.c + CriticalNative | 桌面原生输入 |
| 账户 | 微软 OAuth（4 级）+ 离线 | 微软 OAuth + 多账户 | OAuth + Yggdrasil + authlibinjector |
| 版本管理 | 读 versions/*.json + zip 导入 | modloaders 全套 | 最完善（规则引擎 + 多 repository） |
| mod 加载器 | 基础（Forge/Fabric 记录） | Forge/NeoForge/Fabric/OptiFine/BTA/LWJGL3ify | Forge/NeoForge/Fabric/Quilt/OptiFine/LiteLoader/Cleanroom/LegacyFabric |
| 模组包 | 手动 zip 导入 | CurseForge + Modrinth API | CurseForge + Modrinth + MultiMC + MCBBS |
| 代码成熟度 | 早期预览（约 48 个 ets） | 成熟（大量分支） | 教科书级成熟 |
| **对鸿蒙 PC 落地价值** | ★★★★★ 主骨架 | ★★★★ 底层细节参考 | ★★★★ 上层架构参考 |

## 2. 各自"不可替代"的独特价值

- **HomoLauncher**：唯一能在鸿蒙 NEXT 原生运行、且已验证 OpenGL ES 跑通的实现。JRE 的 HSP 化打包、
  `HOMLBridge` 接口、XComponent 渲染绑定这三样是鸿蒙落地的"命门"，只能从这里来。
- **Amethyst**：渲染/JNI 的**完整源码**（HomoLauncher 的原生层被 HAR 包住看不到），`input_bridge_v3.c`、
  `jre_launcher.c`、`ctxbridges`、`environ.h` 是理解/维护鸿蒙底层实现的"翻译对照表"。
- **HMCL**：启动器**业务上层**的教科书（版本解析、依赖下载、账户、参数规则引擎、平台抽象）。
  HomoLauncher 目前这块是"简化版"，HMCL 提供了补齐方向。

## 3. 代码血缘对应关系（便于交叉参考）

| HomoLauncher | Amethyst | 说明 |
|--------------|----------|------|
| `core/HOMLBridge.ets` | `input_bridge_v3.c` + `CallbackBridge` | 输入/渲染桥，接口一一对应 |
| `core/JVMLauncher.jvm_Launcher` | `jre_launcher.c` (JLI_Launch) | JVM 启动 |
| `resfile/game/HMCLTransformerDiscoveryService-1.0.jar` | `minecraft/libraries/HMCLTransformerDiscoveryService` | HMCL 的 transformer 注入（三方交汇点！） |
| `lwjgl3/` 模块的 .so | `assets/components/lwjgl3` | LWJGL 原生库 |
| `app_runtime/caciocavallo*/` | `assets/components/caciocavallo*` | AWT 移植 |
| `auth/MicrosoftService.ets` | `authenticator/microsoft/` + `auth/microsoft/` | 微软 OAuth |
| `model/MinecraftVersion.ets` | `game/GameVersion` | 版本 JSON 模型 |

**三方交汇点**：HomoLauncher 打包了 `HMCLTransformerDiscoveryService-1.0.jar`（来自 HMCL），
这证明 HMCL 的部分组件已被移植/复用到鸿蒙启动器中。

## 4. 推荐落地方案（三条路线）

### 路线 A（推荐）：以 HomoLauncher 为主骨架，吸收另外两者优点

1. **保留** HomoLauncher 的：HSP 化 JRE、HOMLBridge、XComponent 渲染、微软 OAuth。
2. **从 HMCL 借鉴**：把版本解析/依赖下载/参数生成独立成"Core"层；引入规范的
   `CompatibilityRule` 参数规则引擎 + 占位符映射替代手工拼参；加下载镜像源。
3. **从 Amethyst 借鉴**：若需自定义输入桥/渲染驱动，参考其完整 JNI 源码。
4. **重点验证**：在鸿蒙 PC 上优先走 `libGLv4.so`（原生 GL4 驱动）路径，确认麒麟 GPU 表现。

### 路线 B（激进）：全新鸿蒙启动器 + HMCL Core 移植

把 HMCL 的 HMCLCore 逻辑完整移植成 ArkTS（或通过 JVM 复用），只重写 UI 与渲染桥。
工程量大，但启动器上层功能一步到位。

### 路线 C（最小可用）：直接修 HomoLauncher

HomoLauncher 处于早期预览（"暂不接受问题反馈"），其缺口：AWT 尚不可用、JRE8 分支空、
手柄 mods 未实现、xb_components 依赖外部库。若只想尽快在鸿蒙 PC 玩 MC，聚焦修好
"GLv4 渲染 + 键鼠输入 + 版本导入"这条主链路即可。

## 5. 落地优先级建议（技术要点清单）

1. **渲染主线**：确认 `libGLv4.so` 在目标麒麟芯鸿蒙 PC 上可 `dl_open` 成功 → 这是最大风险点。
2. **键鼠输入**：鸿蒙 PC 的物理键鼠 → HOMLBridge.send_key/mouse → GLFW 的完整映射。
3. **JRE 版本匹配**：确认目标 MC 版本需要 jre17 还是 jre25（`VersionSetting.jreVersion` 可切）。
4. **账户登录**：微软 OAuth 能否在鸿蒙 PC 的 web 视图中完成设备码授权。
5. **版本下载**：HomoLauncher 目前靠外部导入 zip，若需在线下载参考 HMCL 的 DependencyManager。
6. **AWT**：如需模组安装器 GUI（Forge installer 等），需补齐 caciocavallo（当前 TODO）。

## 6. 风险提示

- HomoLauncher 的 `launcher.har`（5.4MB）与 HSP 原生实现是黑盒，若要改底层输入/渲染，最终可能
  需要这一块的开源版本或自行实现（届时 Amethyst 的 JNI 源码是唯一参照）。
- 麒麟芯片的 GPU 驱动对 GLES 3 / Vulkan 的支持程度未在源码中明确，需实测。
- `xb_components`（外部 submodule）未随克隆提供，重新构建需先获取该依赖。
