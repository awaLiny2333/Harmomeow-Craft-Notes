# 05 - MC 默认键位：26.3 SDL vs 26.2 GLFW

> 已归档（2026-09-22）：历史档、非现状。原始件 `stuffs/research/touch-controls/mc-keybindings.md`（反编译源码核实）。不写行号，只写符号名。

## 0. 前提（影响全部键码）

- **26.3 走 SDL**：`com/mojang/blaze3d/platform/InputConstants.java` 顶部 `import org.lwjgl.sdl.*`
  （`SDLError` / `SDLKeyboard` / `SDLMouse`）⇒ 默认绑定值是 **SDL scancode**。
- **26.2 走 GLFW**：键码即 GLFW keycode。
- ⇒ **同一份触屏实现要两条链都对**；两者键码与鼠标键号**不能混用**。

## 1. 默认键位表（SDL scancode vs GLFW 码）

| 项 | 绑定名 | 类型 | **26.3 实际值（SDL）** | 物理键 | GLFW 等价码 |
|---|---|---|---|---|---|
| 攻击 / 开始破坏 | `key.attack` | MOUSE | `1` | 鼠标左键 | `0` |
| 交互 / 使用 | `key.use` | MOUSE | `3` | 鼠标右键 | `1` |
| 跳跃 | `key.jump` | KEYBOARD | `44` | 空格 | `32` |
| 潜行 / 蹲 | `key.sneak` | KEYBOARD | `225` | 左 Shift | `340` |
| 前进 | `key.forward` | KEYBOARD | `26` | W | `87` |
| 后退 | `key.back` | KEYBOARD | `22` | S | `83` |
| 左移 | `key.left` | KEYBOARD | `4` | A | `65` |
| 右移 | `key.right` | KEYBOARD | `7` | D | `68` |
| 暂停菜单 | **无 KeyMapping**（硬编码 ESC） | KEYBOARD | `41`（`isEscape()`） | Escape | `256` |
| 打开聊天 | `key.chat` | KEYBOARD | `23` | T | `84` |
| 打开背包 | `key.inventory` | KEYBOARD | `8` | E | `69` |

附加参考（同一处定义）：`keySwapOffhand`=F(9)、`keyDrop`=Q(20)、`keyPickItem`=鼠标中键
（SDL 2 / GLFW 2）、快捷栏 1–9 = SDL 30–38。

**鼠标键号注意**：**SDL = left 1 / middle 2 / right 3**；**GLFW = left 0 / right 1 / middle 2**。

## 2. 暂停键的特殊性

- 26.3 全树**没有** `keyPause` / `key.pause` 对应的 `KeyMapping`；暂停是 `KeyboardHandler` 硬编码判
  `event.isEscape()`，`isEscape()` 即 `input() == 41`（41 = SDL `KEY_ESCAPE`）。

## 3. 按键状态怎么被读（只改 buffer 不够）

- `KeyMapping.isDown()` **不查任何 buffer**，只返回内存字段 `isDown`；该字段平时**只由输入事件回调**
  `KeyMapping.set(...)` 写入（键盘 `KeyboardHandler.keyPress`、鼠标 `MouseHandler.onButton`）。
- 唯一的「buffer → isDown」通道 `KeyMapping.setAll()` 只在 `grabMouse()`、且
  `InputQuirks.RESTORE_KEY_STATE_AFTER_MOUSE_GRAB`（= `!ON_OSX`）为真时调用一次，**不是每 tick**。
- 26.3 的 `InputConstants.isKeyDown` 走 `SDLKeyboard.SDL_GetKeyboardState()`；26.2 走
  `GLFW.glfwGetKey(window, key) == 1` —— 原理相同。
- **鼠标按钮没有 buffer 轮询路径**：`key.attack` / `key.use` 完全靠事件，塞 mouse buffer **一定无效**。
- ⇒ 要投递**输入事件**（`handle != 0 && handle == window.handle()`）；且需窗口有焦点 / 被激活；
  `KeyEvent.key` 字段就是 **scancode**，用错键码空间会匹配不上。

## 4. 破坏方块的触发

- **每 tick 轮询**：单击开始 = `consumeClick()` 驱动 `startAttack()`；按住持续破坏 = 每 tick
  `keyAttack.isDown()` 决定 `continueAttack(true)`（还要 `isMouseGrabbed()`）。⇒ 是 **polling**，不是持续回调。

## 5. 与虚拟按键的关系

- 虚拟按键走既有桥原语（`meowSendKey` / `meowSendMouseButton` / `meowSendScroll`），与物理输入同一套。
- **未查到（勿编）**：`mc-keybindings.md` 明确警告「26.3=SDL scancode，26.2=GLFW 键码，不能混用」，
  而 `ui-report.md` 记录虚拟按键 UI 用的是 **GLFW 数值空间**（并导出 `GLFW_KEY_SPACE=32` /
  `GLFW_KEY_ESCAPE=256` / `GLFW_KEY_T=84` / `GLFW_MOUSE_BUTTON_1=0` / `GLFW_MOUSE_BUTTON_2=1`）。
  桥 / 遮罩是否在 **26.3（SDL）** 上把 GLFW 码转换成 SDL scancode，**原件未给出说明，未查到**。

## 6. 原件未决（`mc-keybindings.md` 自认）
