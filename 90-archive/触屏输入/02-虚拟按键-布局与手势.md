> 已归档（2026-09-22）：历史档、非现状。现行结论见 [`../../20-design/input/输入-总览.md`](../../20-design/input/输入-总览.md) §2.4。
> 原始件：主 `stuffs/research/touch-controls/ui-report.md`（布局 / 几何最全）；映射见 [README](README.md)。不写行号，只写符号名。

## 0. 开关与归属

- 独立开关 **`touchControls`，默认关**，与「触屏当鼠标」（`touchAsMouse`）**互相独立**。
- 实现文件：`entry/src/main/ets/components/TouchControlsView.ets`（覆盖层）；`GameWindow.ets` 在
  `touchControls === true` 时挂载它；按键经 `GameInputController.pressVirtual` / `scrollVirtual`
  走**既有桥原语**（`meowSendKey` / `meowSendMouseButton` / `meowSendScroll`），与物理输入同一套。

## 1. 覆盖层布局

```
 顶部：                       [ ESC ] [ 输入 ] [ TAB ]
 左下（8 向，3×3、中心空）：        右下（3×3，缺左上两格）：
      ↖   ↑   ↗                     ┌───┬────┬────┐
      ←   ·   →                     │   │攻击│交互│
      ↙   ↓   ↘                     ├───┼────┼────┤
                                    │   │ 跳 │ 蹲 │
                                    ├───┼────┼────┤
                                    │ 包 │ 左 │ 右 │
                                    └───┴────┴────┘
```

- **左下 = 8 向方向键**（3×3、中心格空）：上 / 下 / 左 / 右 + 四个斜向组合键。
- **右下 = 3×3 缺左上两格**：攻击（鼠标左键）/ 交互（鼠标右键）/ 跳 / 蹲 + **包**（物品栏）+
  **左 / 右**（物品栏前后切换 = 鼠标滚轮等价）。
- **顶部 = ESC / 输入 / TAB**（ESC = Escape，输入 = 聊天 T）。
- **按下高亮**。
- 按键的**具体键码**（GLFW 数值空间）与组合方式见 [05](05-MC默认键位-26.3-SDL-vs-26.2-GLFW.md)。
- **仅 grab 显示**：左下方向键簇与右下动作/物品栏簇**仅 grab（游戏内锁视角）时渲染**；顶部 ESC / 输入 / TAB **常显**（不在门控内）。grab 状态链（**未新开定时器**）：`GameInputController.pollGrabbing` → `grabNative` → 新增公开 `isGrabbing()` → `GameWindow` 既有 100 ms 定时器内 `syncGrabActive()` → `@Local grabActive` → 覆盖层 `@Param grabbing` → `@Monitor('grabbing')` 触发 `syncGatedRegionVisibility()`。

### 布局演进（带日期记录）

- 曾为「右下 3 行 × 2 列 + 背包在顶排」，2026-09-22 改为「右下 3×3 骨架（上两行左格空）+ 背包移入右下第三行左格、顶排只剩 ESC / 输入」，同时把物品栏「左 / 右」两键的发射值对调以修正滚动方向。
- 曾有三套尺寸（方向 / 动作 / 顶部各异），后收敛为**单一对**尺寸常量（见 §2），左右两簇与顶排自此同尺寸同间隔。

## 2. 几何与尺寸来源

- 尺寸只有**两个常量**（`common/constants/Constants.ets`）：
  - 单键边长 `TOUCH_CONTROL_BUTTON_SIZE`；
  - 间隔 `TOUCH_CONTROL_GAP`；
  - 再加一个缩放默认值 `TOUCH_CONTROLS_SCALE_DEFAULT_PERCENT`（=100）。
- 布局几何在 `TouchControlsView.aboutToAppear` 内由「常量 × 缩放比」派生：
  `buttonSize = TOUCH_CONTROL_BUTTON_SIZE × factor`、`gap = TOUCH_CONTROL_GAP × factor`；
  方向网格 `stride = buttonSize + gap`、`size = buttonSize*3 + gap*2`、`center = size/2`、
  死区 `= buttonSize/4`。无写死数字散落。
- **四边距独立可调**：`touchControlsInsetTop/Right/Bottom/Left`（vp，默认 12，≥0，0 合法），
  来自设置层；根容器按四边各自 `padding`。
- **固定 vp + 分区锚定**：按钮一律固定 vp 尺寸，容器占满 100%，窗口变化只改变**空闲空间分布**、
  按钮物理大小与形状恒定，仅随锚点重新贴合边角 ⇒ **抗窗口 resize / 折叠屏动态切换**。
- 缩放语义：实际单键 = `TOUCH_CONTROL_BUTTON_SIZE × scale/100`，实际间隔 = `TOUCH_CONTROL_GAP × scale/100`；
  **只缩放这两者**，四边距保持独立不变。缩放钳制 `[50, 200]`（见 [04](04-设置与存储拆分.md)）。

## 3. 方向判定四条

| # | 语义 | 实现要点 |
|---|---|---|
| ① | **网格内按格** | 按组件坐标 `floor(x/stride)` / `floor(y/stride)` 查 3×3 方向表 |
| ② | **网格外按极角量化** | 用「中心→手指」向量 `(x−center, y−center)` 的极角 `atan2`，量化到最近 8 向（45° 扇区） |
| ③ | **中心格 / 无效 ⇒ 保持** | 解析出「无方向」时**不切换**，保留当前方向（走路不中断） |
| ④ | **仅 `UP` / `CANCEL` 释放** | 网格容器 `Up`/`Cancel` 无条件清方向——这是唯一停止方式 |

- ②的量化：屏幕坐标 y 向下，`atan2` 正角为顺时针，八向表从**正右**起顺时针排列
  （正右 → 右下 → 正下 → 左下 → 正左 → 左上 → 正上 → 右上）。
- 抖动抑制：量化用就近取整，并叠加 **5° 滞回**（`DIR_ANGLE_HYSTERESIS = π/36`）——当最近扇区与当前方向不同、
  但角差仍在余量内时保持当前方向，抑制边界反复横跳。
- 死区：`DIR_CENTER_DEADZONE = buttonSize/4`，用于触点极贴近中心、极角数值不稳定时保持当前方向。
- 因此：**手指可按住在格间游走换向，也可滑出网格继续走**；方向只在抬手 / 取消时释放。
- 防粘键：方向键的抬手释放只走 `Up`/`Cancel → 清方向`这一条路径，`switchDir` 内部先把当前方向的所有键逐一抬起。

## 4. 高亮

- 方向键（3×3）：由 `activeDir` 驱动，用**内容相等**比较（模块级 `sameDir`，因 V2 `@Local` 读回可能是代理，
  引用比较不可靠）；手指在格间游走 → `activeDir` 跟走 → 高亮跟走；中心格 / 网格外抬手 ⇒ 无方向 ⇒ 全灭。
- 右下 4 键 + 物品栏 3 键 + 顶部 2 键：由 `pressedCodes` 记录，各按自身键码独立置位 / 复位。
- **不粘高亮**：`Down` 幂等置位，`Up` 与 `Cancel` 都幂等复位；ArkUI 中手指滑出后抬手仍把 `Up` 投给起始组件。
- 视觉手段：仅换 `backgroundColor` —— 按下 / 命中 = 主题色 `brand`；常态 = `TOUCH_CONTROL_BG`。

## 5. 多指

- 方向键只需服务「**按在网格上的那根手指**」：以 **finger id 跟踪**（`dirFingerId`），遍历 `event.touches`
  取落在网格矩形内的触点；滑出后若无界内触点则按 §3 ③ 处理。
- 其余按钮各自 `onTouch`，互不影响。
- 覆盖层的按钮矩形会作为**排除区**上报 native，按在按钮上的手指**整段跳过触屏当鼠标**（见 [03](03-排除区与native桥.md)）。

## 6. 不确定 / 未实测（原件自认）

- `Area.globalPosition` 单位按 ArkUI 惯例取 vp；若个别设备返回 px，会整体偏一个 `vp2px` 系数（由排除区自证日志暴露）。
- 首次触摸标定窗口原点前存在**一次漏排除**（此时偏移尚为 0）。
- 高亮色叠加在游戏画面上是否足够醒目、缩放钳制上下界手感、顶排方块化的实际显示，均**未实机验证**。

## 7. grab 门控：卸载前必先释放按键（陷阱）

- **门控区**：排除区共 **5** 个 region（0 方向键网格 / 1 右下动作簇 / 2 ESC / 3 输入 / 4 TAB）；被门控的两簇（0/1）**不可见时必须立即置 `valid=false` 并重报**，否则会排除一片没有按钮的区域（菜单下半屏点不动）。
- **陷阱**：**摘除被门控的簇之前必须先释放所有按住的虚拟键** —— 否则 ① 节点消失后 `Up` 不再回来 ⇒ **原生键卡死**（角色一直朝那个方向走）；② `scheduleReport` 的"手势中延后"守卫（`dirFingerId >= 0 || pressedCodes.length > 0`）**永远为真** ⇒ **重报永不发出** ⇒ 刚失效的 region **永不重报** ⇒ **菜单下半屏持续被排除**。
- **正确顺序**：先 `releaseAll()` → 再置 `valid=false` → 再 `scheduleReport()`（不可换序：不先释放，守卫不放行）。
- 同一处补了 `glfwToHmKey` 的 **258（TAB）** ⇒ `releaseAllKeysUp()` 能兜住被按住的 TAB。
