## 1. 两轮复核的组织方式

- 两轮均按**互斥域**各派 **4 个功能域 + 1 个横切审计**：
  - A = native input bridge；B = ArkTS 输入 / 启动层；C = 虚拟按键 UI 覆盖层；D = 设置存储 / 高级选项；
  - E = **横切审计**（爆炸半径 / 接线完整性 / claims 审计 / 流程卫生）。
- 每份报告要求：`VERDICT` + 逐条 `SEVERITY + 文件:行号 + 为什么 + 建议修法` + `VERIFIED OK` + `UNCERTAIN`。
- 第 1 轮 → `review-A/B/C/D/E`；修复 → `fixes-1-ui` / `fixes-2-native` / `fixes-3-arkts` / `fixes-4-settings`；
  第 2 轮 → `review2-A/B/C/D/E`。

## 2. 第 1 轮抓到的缺陷类别

- **接线缺一处**：`touchFilterStop` 六处只齐五处（缺调用点）。
- **native 共享状态隐患**：触屏与鼠标共用 origin / scale。
- **UI 手势收尾**：取错手指、收尾不释放、另一格手指 Up 清方向等。
- **设置层**：缓存归一化、导出 / 备份含新文件等。
- **记录不可信**：子 agent 报告多处以过期断言描述当前代码（E 的 claims 审计）。

## 3. 那次回归的成因与治本（本专题最该留下的一条）

- 第 1 轮的修复**引入回归**：把「复位手势状态」放进 `meowTouchFilterStart` 的**开头**。
  - `meowTouchFilterStart` 会被 ArkTS **每次触摸**调用（刷新原点 / 缩放 / 灵敏度）⇒ 复位放里面
    ⇒ 手势进行中每 ~100ms 清零一次（`g_tLastX/Y` 归零 ⇒ 下一个 MOVE 从 0 算增量）⇒
    实机症状 **划视角乱飞 + 按虚拟键同时动视角**。
  - 同机理：在「重设排除矩形」时清 finger 表 ⇒ ArkTS 手势中途重推排除区（首触标定、IME / 旋转 / resize）
    ⇒ 按住的手指被**中途解封**。
- **处置**：**整体撤销**并另取治本，随后第 2 轮复核。
- **治本现状**：
  1. `meowTouchFilterStart` 中：**同窗口参数刷新早退、不复位**；复位（`meow_touch_reset_gesture`）只在
     **会话边界**（窗口变了 / `Stop`）。
  2. 重设排除区快照**不碰 finger 表**；finger 表只由 `UP` / `CANCEL` 与会话边界维护，且只允许 filter 线程触碰。
  3. `meow_touch_grab_delta` 的系数 = `g_touchSens × g_grabSensitivity`（**两个因子都要留**，删因子会导致手感突变）。

> ⚠️ 原始件 `fixes-2-native.md` 的 **N1 / N2 / N3** 后来被证明**会把回归当修复 / 或直接引入回归**，
> 该文件顶部已有**事后更正**块，**不可照做**。全量过期断言见 `stuffs/research/touch-controls/CORRECTIONS.md`。

## 5. 五类坑（最该留下的东西）

1. **网关接线六处**：新增桥方法必须齐 —— native 实现 / NAPI `desc[]` / `.d.ts` / `Index.ets` 导出 /
   `JvmLauncher.ets` 类型 / 调用点。
   - **漏 `Index.ets` 导出 ⇒ 运行期 `?.` 静默失效**（现象「日志里一条都没有」，极易误判成「底层机制不生效」）。
2. **高频 / 手势中途路径顺手收拾状态 ✗**：`touchFilterStart` 每次触摸都被调；复位若放里面 ⇒ 手势中途每 ~100ms 清零
   ⇒ 划视角乱飞 + 按虚拟键同时动视角。同理「重设排除区快照时清 finger 表」会中途解封按住的手指。
   **治本** = 复位只在会话边界；排除区快照不碰 finger 表。
3. **公式因子被删 ✗**：转视角系数从 `g_touchSens × g_grabSensitivity` 改成只留前者 ⇒ 手感突变。**两个因子都要留**。
4. **用闸门挡真输入 ✗**：曾用 `onTouch` 计数屏蔽 `onMouse` ⇒ **真鼠标左键全失效**
   （官方文档：单指可响应的触摸事件**均可由鼠标左键操作响应** ⇒ 鼠标点击也会触发 `onTouch`，无法据此区分）。
5. **卸载被门控的簇前不先释放按键 ✗**：grab 翻转把左下 / 右下两簇从渲染树摘除（`if (this.grabbing)`）时，
   若未先释放进行中的虚拟键 —— ① 节点消失后 `Up` 不再回来 ⇒ **原生键卡死**（角色一直朝那个方向走）；
   ② `scheduleReport` 的"手势中延后"守卫（`dirFingerId >= 0 || pressedCodes.length > 0`）**永远为真** ⇒
   **重报永不发出** ⇒ 刚置 `valid=false` 的排除区**永不重报** ⇒ **菜单下半屏持续被排除**。
   **正确顺序**：先 `releaseAll()` → 再置 `valid=false` → 再 `scheduleReport()`（不可换序：不先释放，守卫不放行）；
   同处补 `glfwToHmKey` 的 258（TAB）⇒ `releaseAllKeysUp()` 能兜住被按住的 TAB。
