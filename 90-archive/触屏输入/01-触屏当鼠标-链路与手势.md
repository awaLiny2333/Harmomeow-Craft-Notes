## 0. 前置事实（两条链都要对）

- MC **26.3 走 SDL**（`InputConstants` 内 `import org.lwjgl.sdl.*`），**26.2 走 GLFW**。
  ⇒ 同一份触屏实现必须**两条链都对**（键位 / 鼠标键号对照见 [05](05-MC默认键位-26.3-SDL-vs-26.2-GLFW.md)）。
- 触屏实现**复用既有桥原语**：`meowSendKey` / `meowSendMouseButton` / `meowSendScroll`，以及 native 侧
  `critical_send_cursor_pos` / `critical_send_mouse_button` —— 与物理输入**同一套**，不另起一套投递。

## 1. 链路（窗口级 touch filter）

与已用的 **mouse filter 同族**，都用 `OH_NativeWindowManager_RegisterTouchEventFilter`（API 15 提供）：

1. ArkTS：`GameWindow.ets` 上挂 `.onTouch(handleTouchMap)`；`GameInputController.handleTouchMap` /
   `ensureTouchFilter` 负责在首触 / 窗口参数变化时把 filter 注册进平台（另在鼠标路径兜底刷新）。
2. 桥：`GameInputController` → `libs/meowcraftlib/Index.ets` 导出的 `touchFilterStart` / `touchFilterStop`
   → `meowjrebridge.cpp` NAPI → native `meowTouchFilterStart` / `meowTouchFilterStop`。
3. native：`meowTouchFilterStart` 用窗口 id 注册回调 `meow_touch_filter`；`meow_touch_filter` 读平台
   `OH_Input` 触摸坐标，换算成 `dx,dy`（display px），再按 grab / 非 grab 分流：
   - **非 grab**：合成鼠标事件（光标位置 / 左键 / 右键）走既有 `critical_send_*`；
   - **grab（游戏内）**：拖动转视角，走 `meow_touch_grab_delta`（转视角增量）。

> **易踩点**：`meowTouchFilterStart` 会被 ArkTS **每次触摸**调用（用于刷新原点 / 缩放 / 灵敏度），
> 因此**不能在它里面复位手势状态**（详见 [06](06-两轮独立复核与修复复盘.md) 坑 2）。

## 2. 手势语义表（开关 `touchAsMouse`，默认开）

| 手势 | 行为 |
|---|---|
| 单指按下 | 光标**跳到触点** + **左键按下** |
| 拖动 | 光标**跟随** |
| 抬起 | **左键释放** |
| 双指点按 | **右键** |
| 游戏内（grab）单指 | **故意不发左键**（那里拖动 = 转视角；发了会「一转就挖」） |
| 双指滚动 | **不做**（MC 里可滚动处都有滚动条） |

- 游戏内**破坏 / 攻击**：**单指手势不承担**（有意不发左键 ⇒ 转视角永不误挖）⇒ **要挖按覆盖层的「攻击」键**（鼠标键 0）；**只有"触屏当鼠标开、覆盖层关"时无挖的途径**。手势方案（长按 / 按住不动 / 只靠按钮）**尚未选**。
- 触屏与鼠标的 native 原点 / 缩放已**分离**（触屏专属 `g_touchOriginX/Y/g_touchScale` 对鼠标的
  `g_filterOriginX/Y/Scale`），互不覆写。这是第 1 轮复核发现「共用 origin / scale」隐患后的修复。

### 系统返回手势 / 返回键 ⇒ 一次 ESC（页面级，非 touch filter）

- **语义**：游戏窗内「返回」等效按一次 **ESC**；对本工程 MC，ESC 语义天然统一 —— grab 里 = 开菜单、菜单里 = 关菜单。
- **实现（加法式，未新增桥 / pipeline）**：
  - `pages/GameWindow.ets`（`@Entry` 页面）新增 `onBackPress(): boolean` ⇒ 调 `this.input?.sendEscapeTap()` ⇒ **返回 `true`**（消费系统返回、应用不退出）。
  - `GameInputController` 新增公开 `sendEscapeTap()` ⇒ 内部 `pressVirtual(256, false, true)` 紧接 `pressVirtual(256, false, false)`（= ESC 按下 + 抬起各一次），与顶部虚拟 ESC 键**同一条路**；256 = `GLFW_KEY_ESCAPE`。
- **不加 grab 门控**（有意）：返回手势在 grab 与菜单里都发 ESC。
- 未动：顶部 ESC 按钮 / native / 设置层。
- **平台事实**：**OHOS 全屏游戏窗口下，系统的「边缘返回手势」确实会派发到 `@Entry` 页面的 `onBackPress()`** —— 返回 `true` = 页面自处理、消费掉、应用不退出。官方 FAQ `faqs-arkui-531` / `faqs-arkui-553` 佐证「仅 `@Entry` 组件生效；返回 true = 页面自处理、不路由」⇒ 全屏应用要拦返回有据可依。

## 3. 与既有 mouse filter 的关系

- **同族同 API**：touch filter 与 mouse filter 都用 `OH_NativeWindowManager_Register*EventFilter`（API 15），
  各自注册、各自回调。
- **共享与分离**：原生坐标 / 缩放状态最初共用 `g_filterOriginX/Y/Scale`，后拆出触屏专属
  `g_touchOriginX/Y/g_touchScale`；`meow_mouse_filter` / `meowMouseFilterStart` 继续用原一组。
- **共用去重**：ArkTS 侧 `pushMouseMap` 的「算原点 → 去重 → `mouseFilterStart`」逻辑保留，触屏路径
  **末尾追加**了 touch filter 的刷新，不改鼠标主逻辑。
- **共同原语**：两者最终都落到同一套 `critical_send_*` / 桥发送函数。

## 4. 两条渲染链的差别（同一份触屏实现为何要「两条都对」）

- 键位数值空间不同：26.3 = **SDL scancode**（W=26、S=22、A=4、D=7、SPACE=44、LSHIFT=225、ESCAPE=41 …），
  26.2 = **GLFW keycode**（W=87、S=83、A=65、D=68、SPACE=32、LSHIFT=340、ESCAPE=256 …）。
- 鼠标键号不同：**SDL = left 1 / middle 2 / right 3**；**GLFW = left 0 / right 1 / middle 2**。
- 读取方式：26.3 的 `InputConstants.isKeyDown` 走 `SDLKeyboard.SDL_GetKeyboardState()`；
  26.2 走 `GLFW.glfwGetKey(...) == 1` —— 但 `KeyMapping.isDown()` 读的都是内存字段 `isDown`，
  只由**输入事件回调**写入（仅改 buffer 不够）。详见 [05](05-MC默认键位-26.3-SDL-vs-26.2-GLFW.md) §3。
