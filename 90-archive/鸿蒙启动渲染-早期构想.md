# 鸿蒙启动 + 渲染可行设计构想

> 目标平台：ARM 麒麟鸿蒙 PC（2in1/free-form window）。目标游戏：原版 release **1.21.10**，
> 渲染用 **OpenGL** 路径。原则：参考 Amethyst/HomoLauncher，但**不被 HomoLauncher 框死**——
> 目标是找到可裁剪、可重编、可理解的最简可行解。
>
> **历史定位（2026-09-10）**：本文是**早期设计构想快照**（最终落地走"系统 OpenGL"路线 3）。
> 文中"移植 Amethyst"均为当时设想；实装 launcher/GLFW overlay/桥**净室自研**，
> Pojav/Amethyst/HOML 代码**已全部清除、无残留**。`ref/*` 仅作工作区外部参照，不入仓库、不随包。

## 1. 需求收敛（先砍掉一切非必需）

只跑"原版 1.21.10 + OpenGL + 键鼠"时可以明确**不要**：
- ❌ Forge/NeoForge/Fabric 生态 → 不需要 MioLibPatcher/MioLaunchWrapper/HMCLTransformerDiscovery/pro-grade
- ❌ AWT（1.21.10 原版游戏流程不用）→ Cacio 全套可砍（但见 §5 前提）
- ❌ 老版本 MC（<1.17）→ jre17 HSP 可砍、lwjgl2/lwjgl3ify 不需要、老版 input 直接模式不需要
- ❌ 虚拟手柄/触控布局（xb_components 大块）→ PC 键鼠不需要
- ❌ Artdeell 披风/arc_dns_injector、OAuth 登录（先离线跑通）
- ❌ 微软登录/皮肤下载（首版可离线 uuid）

## 2. 三层必须解决的事（无可回避）

```
A. JRE：arm64 鸿蒙能跑的 OpenJDK 21+（class 65）
B. GLFW stub：把"真 libglfw.so + 窗口/事件"换成本地实现
C. 桌面 OpenGL → 鸿蒙 GPU（GLES/Vulkan）翻译
```
A/B/C 之下，**鸿蒙 UI 只需两个输出/输入通道**：
- 输出：XComponent(TEXTURE) → native EGLSurface（游戏画面）；
- 输入：ArkUI 键鼠事件 → native → Java GLFW stub 回调。

## 3. 路线对比

### 路线 1：完整复刻 HomoLauncher（Pojav 血统，最重）（当时设想；未采用）
ArkTS UI + HSP JRE + launcher.jar(PojavLauncher/PojavClassLoader) + pojavexec stub + mobileglues。
- 优点：有现成鸿蒙产物（jre25 HSP、launcher.har、渲染库 .so）可拼。
- 缺点：native 全黑盒（launcher.har/xb_components 无源码），无法裁剪/修改/学习；
  依赖外部 submodule；体积大；一旦渲染/输入出问题无从下手。

### 路线 2：基于 Amethyst 源码自建"鸿蒙薄层"（当时设想；未采用，最终走净室自研 + 路线 3）
（当时设想，未采用）把 Amethyst 的完整源码（JNI stub、egl_bridge、input_bridge、Java GLFW stub、merged LWJGL jar）
作为**参照实现**，鸿蒙侧只新写最薄的一层：
- 替换 Android 进程模型：ArkTS UI 进程 + N-API 桥（代替 ART 侧的 CallbackBridge 输入）；
- XComponent surface 替代 SurfaceView（native 侧 OH_NativeWindow↔EGL，代码量小）；
- 复用 Amethyst 的 `jre_lwjgl3glfw` 源码直接**编译鸿蒙版**（它含 Java GLFW stub + merged 模块 jar 的
  gradle 构建，可重编、可裁剪）；
- 复用其 JNI 输入桥思路，但事件源改成 ArkTS（鸿蒙 KeyEvent/MouseEvent）。
- 优点：**全链路源码在手**、可裁剪（砍 Cacio/lwjgl2/老版本）、可学习、可修 bug。
- 缺点：（当时设想）需要把 Amethyst 的 JNI/渲染桥移植到鸿蒙 NDK（OHOS 是 musl 而非 Android bionic，
  但渲染库 gl4es/mobileglues 已在 HomoLauncher 的 arm64 musl 产物中存在，证明可行）。

### 路线 3：利用系统原生 OpenGL（✅ 已证实为最优，见《关键发现_系统OpenGL_路线更新》）
问题本质：1.21.10 要求桌面 OpenGL。官方文档证实：**鸿蒙 PC 原生提供 OpenGL 3.0/4.2
（系统 libGLv4.so，API22+）**，只需在 app.json5 配 `NEED_OPENGL` 并按
`OH_Graphics_QueryGL` 确认设备能力。渲染链 = LWJGL-opengl → 系统 libGLv4（桌面 GL 直通）→ GPU，
**无需 gl4es/mobileglues 翻译层**。此路线使鸿蒙渲染与桌面 Linux 基本一致，为首选。
- 备选（仅当目标设备无桌面 GL）：mobileglues / ANGLE（GLES→Vulkan）。

### 路线 4：混合（务实推荐起点）
1. JRE：直接用/复刻 HomoLauncher 的 jre25 HSP 产物（OpenJDK 25 aarch64 musl，能跑 Java21 字节码）；
2. 游戏主类与参数：**不自研**——完整实现 rules/参数引擎工作量不小，首版可用 HMCL 思路或
   直接读官方 manifest 生成（1.21.10 分支简单：无条件库+linux natives 固定集合，见 07-1 §1.1）；
3. 渲染：先按**路线 2 移植 Amethyst 的 stub+渲染桥**，渲染驱动尝试顺序：
   libGLv4（若系统有）→ mobileglues → ng_gl4es；保留 ANGLE 备用；
4. UI：ArkTS 极简（现有项目已有目录/版本管理），XComponent + 键鼠事件桥。

## 4. 推荐的鸿蒙组件拓扑（不依赖 launcher.har 黑盒）

```
┌─ ArkTS (UI) ──────────────────────────────┐
│ 页面/目录/版本/设置    输出: 布局           │
│ XComponent(TEXTURE) ← 游戏画面 (EGLSurface) │
│ 键鼠事件 → N-API send_* (仿 Amethyst bridge)│
└──────────────┬─────────────────────────────┘
        N-API 桥 (鸿蒙新写，替代 ART 侧)
┌──────────────▼─────────────────────────────┐
│ Native (C, 移植自 Amethyst jni/ 但鸿蒙化)    │
│  pojav_environ 事件缓冲 / 回调指针           │
│  egl_bridge: XComponent surfaceId→EGLSurface│
│  dl_open 渲染驱动 (gl4es/mobileglues/GLv4)  │
│  dlopen libjli.so → JLI_Launch (JVM 拉起)   │
└──────────────┬─────────────────────────────┘
        OpenJDK(arm64, Java21+) — 独立 VM
┌──────────────▼─────────────────────────────┐
│ Java (游戏侧, 复用 Amethyst jre_lwjgl3glfw)  │
│  org.lwjgl.glfw.GLFW (Java stub, 可裁剪)    │
│  net.minecraft.client.main.Main (1.21.10)   │
│  (不启用 PojavClassLoader → 更简单)          │
└────────────────────────────────────────────┘
```

## 5. "更简单"突破口（逐个核实，可能减工作量）

1. **直接跑 mainClass 而非 PojavLauncher/PojavClassLoader**
   Amethyst v3 已证明可行（无自定义 classloader）。若不需要 launcher.jar 的包装，
   JVM 参数可直接由 ArkTS/启动逻辑生成 → **去掉 Java 侧"启动器进程内再做一遍解析"**。
2. **砍 Cacio**：前提是确认 1.21.10 全程无 AWT 触碰（需实机日志验证）；若 MC 启动早期
   触碰 AWT（如 Mojang splash 或字体），仍需轻量 headless AWT。→ 最小化：只带
   `-Djava.awt.headless=true` 试试，不行再上 Cacio。
3. **离线账户先行**：auth 只影响 --uuid/--accessToken 占位；原版离线可进主菜单与单机。
4. **natives 不再解压 extract**：1.21.10 的 natives 是独立 classifier jar（.so 直接拷出），
   比老版（extract exclude 规则）简单。
5. **渲染驱动**：优先确认 libGLv4（若鸿蒙 PC 自带桌面 GL 路径则整层翻译可省）。
6. **合并 LWJGL 模块**：Amethyst 已有 merged-modules 构建；鸿蒙只需 lwjgl.jar（Java stub 全覆盖）
   + lwjgl3 原生 .so（liblwjgl*/libglfw 替代物），模块裁剪空间大。

## 6. 关键风险与待验证项

| 风险 | 说明 | 验证方式 |
|------|------|---------|
| libGLv4 真实身份 | ~~未知~~ **已查明**：系统库（`/system/lib64/ndk`），底层 = **Mesa Zink over Vulkan → Maleoon 916**（见 `../00-current/渲染链与迁移结论.md`、`../90-archive/输入延迟调查证据.md` §7.14） | 无需再验 |
| MobileGlues/gl4es 在鸿蒙 musl 上的稳定性 | HomoLauncher 证明能跑，但 1.21.10 具体 GL 调用集未验 | 移植后实机跑 1.21.10 |
| JRE musl 兼容 | HomoLauncher 用 musl OpenJDK；鸿蒙 libc 是 musl → 方向对 | 复刻其 jre25 |
| 事件模型差异 | Android PointerCapture vs 鸿蒙 LOCK_WINDOW_CURSOR | 已确认鸿蒙有该权限，可锁光标拿相对位移 |
| EGL surface 生命周期 | XComponent surface 重建时机需处理（Amethyst 有 1x1 pbuffer 兜底思路） | 移植时照做 |
| log4j2 输出路径 | 鸿蒙沙箱限制日志写目录 | 复刻 security/log4j-rce-patch 内鸿蒙路径做法 |

## 7. 建议下一步（落地顺序）

0. **工程侧准备**（本阶段即可做，无需真机）：
   - app.json5 加 `"appEnvironments": [{ "name": "NEED_OPENGL", "value": "1" }]`；
   - 建 native (C++) 模块：CMake 链 `libGLv4.so`/`libEGL.so`；
   - 写最小 XComponent(TEXTURE) + OH_ArkUI_SurfaceHolder → EGLRender，
     用 `OH_Graphics_QueryGL` 打日志确认 PC 走 GL 分支——先跑通"鸿蒙 surface 出桌面 GL 上下文 + 清屏色"。
1. JRE：评估复用 HomoLauncher 的 jre25 HSP 产物（OpenJDK 25 aarch64 musl），
   先验证 HSP 加载与 `JLI_Launch` 拉起 JVM（可先跑 `java -version` 或最小 Java 类）。
2. Java 侧渲染：用测试 lwjgl 集打通"JVM 起来 + 桌面 GL context + 简单三角形画上 XComponent"，
   确认 LWJGL-opengl → libGLv4 直通。
3. 输入桥：ArkTS 键鼠 → 输入缓冲 → Java GLFW stub（参考 Amethyst input_bridge_v3 思路）。
4. 游戏启动：直接跑 1.21.10 的 `net.minecraft.client.main.Main`（不启用 PojavClassLoader），
   参数生成参考 HMCL（1.21.10 linux natives 集合已实证固定）。
5. 账户离线 → 微软 OAuth 后置。

> 一句话结论：最简可行解 ≈ **自备 JRE(复用 jre25 思路) + 系统桌面 OpenGL(libGLv4, NEED_OPENGL) +
> Amethyst 系 Java GLFW stub + 自写鸿蒙 N-API/XComponent 薄层**，并大胆砍掉
> gl4es/mobileglues/PojavClassLoader/Cacio/Forge/老版本/手柄登录等一切非 1.21.10 原版所需。
