## 核心问题

在 **ARM 麒麟芯片的鸿蒙 PC** 上运行 Minecraft: Java Edition，意味着需要同时解决三个难题：

1. **JVM 问题**：MC 需要完整的 Java 运行时（JRE）。而 MC 的官方 JRE 只有 x86/x64 + Win/Mac/Linux 版本，
   没有 ARM 鸿蒙版本，更无法直接作为动态库嵌入。
2. **渲染问题**：MC 通过 LWJGL（Lightweight Java Game Library）调用 OpenGL 渲染。
   鸿蒙 PC 的原生图形接口是 OpenGL ES（不是桌面 OpenGL），需要通过 gl4es / mobileglues / ANGLE 等
   转换层把 OpenGL 调用翻译成 OpenGL ES 调用。
3. **启动器问题**：版本清单拉取、依赖库下载、账户鉴权（微软 OAuth）、JVM 参数拼接、mod 加载器
   （Forge/Fabric）安装、模组包导入等一系列"业务上层"逻辑。

## 项目如何各自解决

| 难题 | HomoLauncher | Amethyst | HMCL |
|------|-------------|----------|------|
| JVM | 内置 jre17/jre25 两个 HSP 模块（`libs/jre*/`），内含 arm64 的 `libjvm.so` 等全套，运行时解压 `jre*-ohos-arm64.tar.xz` | CI 预编译 jre8/17/21/25，多架构 | 独立下载/管理系统 JRE，`JavaRepository` 扫描 |
| 渲染 | `HOMLBridge` + `dl_open(renderer)` 动态加载 `libgl4es.so`/`libmobileglues.so`/`libGLv4.so` | 完整 JNI 层（ctxbridges/egl_bridge/awt_bridge）+ 同套 gl4es/mobileglues | 仅负责传 `-Dorg.lwjgl.*` 与 mesa 环境变量，不内嵌渲染层 |
| 启动器上层 | 简化版（读 versions/*.json、手动导入 zip、离线+微软账户） | 中等（modloaders、profiles、modpacks、多账户） | **最完善**（版本清单、全套 modloader、模组包、多账户、参数规则引擎） |

## 关键洞察

- **鸿蒙 PC 已跑通 OpenGL ES** 这一事实，来自 HomoLauncher 的 `JVMLauncher.initEnv()`：设置
  `POJAV_RENDERER=opengles_mobileglues`（旧名）、`LIBGL_ES=3` 等环境变量，说明 mobileglues 这条转换链
  在鸿蒙 arm 上可行。
- **渲染层三选一**（见 `../90-archive/鸿蒙OpenGL渲染-早期研究.md`）：
  - `libng_gl4es.so` → `POJAV_RENDERER=opengles3`（旧名；gl4es，老牌 OpenGL→GLES 翻译）
  - `libmobileglues.so` → `POJAV_RENDERER=opengles_mobileglues`（旧名；MobileGlues，默认/推荐）
  - `libGLv4.so` → `POJAV_RENDERER=openglv4`（旧名；**仅鸿蒙 PC 或平板可用的原生图形驱动**）
- **AWT 移植**：MC 的部分 GUI（模组安装器、部分设置界面）依赖 Java AWT/Swing。HomoLauncher 与 Amethyst
  都用 **Caciocavallo**（cacio-ctc/cacio-tta）这套 AWT 在无 X11 环境下的移植，配合
  `-Djava.system.class.loader=...CTCPreloadClassLoader` 与一堆 `--add-exports` 注入。
