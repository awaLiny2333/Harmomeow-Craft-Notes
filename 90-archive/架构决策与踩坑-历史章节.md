## 6. Native 渲染骨架（Step0 时期的历史决策；那套代码已清理）

> 当时用 `GLPreviewView` / `egl_render` / `bindNode` 做首个 GL 验证，**这些文件已全部清理**；
> entry native 现为 `libmeowassets.so`（仅 `installJre` / `extractRawTar`）。**仍适用的决策与 API 坑**：

- **必需**：`AppScope/app.json5` 的 `appEnvironments` 加 `NEED_OPENGL=1`（否则无桌面 GL 环境）；
  `entry/build-profile.json5` 的 `buildOption.externalNativeOptions.path` **必须显式声明**（否则 hvigor 不编 cpp）。
- **★surface 就绪时机（关键决策）**：`onAttach` **早于** surface 创建 ⇒ 窗口必须由 `XComponentController` 的
  `onSurfaceCreated/Changed/Destroyed` 驱动；native 用 `OH_NativeWindow_CreateNativeWindowFromSurfaceId(surfaceId,&window)`
  取窗口（CMake 需链 `libnative_window.so`）。
- **API 坑**：① `XComponentController` 是**全局内置类型**（不在 `@kit.ArkUI` 导出，**勿 import**）；
  ② `SurfaceRect` 字段名是 `surfaceWidth/surfaceHeight`；③ `napi_get_value_uint32` 需 `uint32_t*`（surfaceId 为 uint64 时先转 uint32）；
  ④ `EGLNativeWindowType` 需 `reinterpret_cast`；⑤ `LOG_DOMAIN` 需先 `#undef` 再 `#define`（`hilog/log.h` 有默认值）。
- **引用 so 三件套**（现仍适用于 `libmeowassets.so`）：`src/main/cpp/types/<so>/Index.d.ts` + 同目录 `oh-package.json5`
  + `entry/oh-package.json5` 的 `dependencies` 指向该目录。
- 原始情报：[`鸿蒙OpenGL渲染-早期研究.md`](鸿蒙OpenGL渲染-早期研究.md)、
  [`渲染迁移评估/03-sdk-header-facts.md`](渲染迁移评估/03-sdk-header-facts.md)、
  [`清理杂项-2026-09-07.md`](清理杂项-2026-09-07.md)。

## 8. JRE 内嵌与 JLI_Launch（Step1 的历史决策；现行见 [`../00-current/现状基线.md`](../00-current/现状基线.md) §5 第 11 条）

> 当时用外部预编译 `jre25` + `jrelib` 命名；**现行** = 版本中性 `meowjre` + 官方 OpenJDK 26.0.2.1 分体收编。本节只留**仍然成立的决策与坑**。

- **el2（`filesDir`）禁止 dlopen / 执行代码；el1（`bundle`）可执行** ⇒ JRE 的 `.so` **必须随包**
  （HSP 平铺 `libs/arm64-v8a`），数据（`modules` 等）走 `filesDir`。
- **华为 JLI 移植的两个环境变量是平铺布局的钥匙**（反汇编 libjli.so 确认）：`OHOS_JAVA_HOME` 覆盖
  `dladdr` 推断的 `java.home`（否则 `jvm.cfg` 路径空/错）；`OHOS_DL_DIR` 指定 JVM `.so` 的 dlopen 目录。桥在 `JLI_Launch` 前 setenv。
- **`JLI_Launch` 会 `exit()` 带走进程**（main 跑完/失败均 exit）⇒ app 进程消失属正常；26.2+ 起改为正常返回
  ⇒ 桥必须在返回后 `_exit()`（见 [`../00-current/现状基线.md`](../00-current/现状基线.md) §5 第 22 条）。
- **坑**：`bm uninstall` **不清 `filesDir` 数据**；安装完成标记 = `<filesDir>/…/lib/libjli.so`
  ⇒ 更新 rawfile 资产须**删该标记**（或卸载重装）才会重解压。
- `jdk.compiler` / `jshell` 不在 JRE 模块集（非 JDK）⇒ source-file 模式报 "Module jdk.compiler not in boot Layer" 属预期；MC 用 `-jar` 不受影响。
- 溯源与实证：[`../30-supply-chain/README.md`](../30-supply-chain/README.md)（JRE 溯源 / per-so 名录）、`stuffs/research/misc/jli.asm`（反汇编速查）。

## 19. 性能实验台 + `GALLIUM_THREAD`（glthread）（决策与负项）

- **实验台（长期保留）**：高级选项两格 → **A/B 零重编**：
  - **额外渲染环境变量**（`K=V`，换行 / `;` 分隔）→ `meowjrebridge.cpp` setenv 块（**预 dlopen 渲染器之前**，Mesa 在 screen init 读 env）；
  - **额外 JVM 参数**（空格 / 换行分隔）→ `MinecraftLauncher.buildLaunchArgv`（放固定参数之前，允许被覆盖）。
  落**应用级全局设置** `app-settings.json` 的 `global.runtime`（见 [`../20-design/launch/实例设置存储-方案.md`](../20-design/launch/实例设置存储-方案.md) §3.2），游戏进程启动时读；**改完下次开游戏生效**。
- **glthread 的取舍（已被 GL guard 取代）**：`GALLIUM_THREAD=1` 确有**显著帧数提升**，但曾在加载屏随机崩
  （崩溃现场 = `<HM_GPU> Create/Get pipeline cache` ⇒ Mesa glthread → Zink → 驱动的**管线缓存路径**）。
  根因在系统库侧 ⇒ 由 **GL guard** 应用侧修复（现行见 [`../20-design/perf/glthread-GL-guard-方案.md`](../20-design/perf/glthread-GL-guard-方案.md) 与 [`../00-current/现状基线.md`](../00-current/现状基线.md) §5 第 16 条）。
- **保留改动**：实验台；`egl_drop_surface()` 的 glthread drain（`glFinish`，仅 glthread 时触发；关闭时 no-op 零开销）；`GALLIUM_THREAD` 行警示注释。
- **基准（供以后比）**：26.2 + Fabric + Sodium ｜ 16 视距 / 6 模拟 ｜ 2x 缩放 ｜ 最大化固定场景；`帧时 ≈ 8ms 固定 + 7.5ms/MP`（**固定成本是大头**）。
