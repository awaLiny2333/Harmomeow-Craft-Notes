# 标准桌面平台启动链路（以原版 release 1.21.10 为准）

> 已归档（2026-10-01；因为桌面启动基线结论已并入现役档（启动链-总览 §0.4）；现役口径见 [`启动链-总览.md`](../20-design/launch/启动链-总览.md)）。

> 参考：HMCL（DefaultLauncher / game 模型）+ 本机真实 `1.21.10.json`（实证）。
> 目的：建立"桌面正常启动长什么样"的基线，才能判断鸿蒙方案缺什么、能砍什么。
> 本文为决策记录 / 证据存档，**不复述现状**；当前状态见 [现状基线.md §5](../00-current/现状基线.md)。

## 0. 启动本质一句话

桌面启动 = `java -cp <版本jar+全部libraries> <mainClass> <游戏参数>`，游戏进程内
**真实 GLFW + 桌面 OpenGL 上下文**，无任何代理。

## 1. 1.21.10 版本 JSON 实证（本机文件）

路径：`.minecraft/versions/1.21.10/1.21.10.json`

| 字段 | 值 | 意义 |
|------|-----|------|
| id / type | `1.21.10` / `release` | |
| mainClass | `net.minecraft.client.main.Main` | 直接进原版主类（无 wrapper） |
| javaVersion | `{ component: java-runtime-delta, majorVersion: 21 }` | 需要 **Java 21** 运行时 |
| assets / assetIndex | `27` / `27` | 资源索引版本 |
| minimumLauncherVersion | 21 | 启动器最低要求 |
| logging | log4j2-xml | 用 log4j2 客户端配置 |
| 库总数 | 115（含全部 OS 变体） | 见下 |

### 1.1 libraries 组织（重要）

115 个库 = 纯 Java artifact（60 个无条件）+ 各 OS/架构的 natives/分类库。

**Linux（=鸿蒙伪装对象）实际要的 10 个 native jar：**
```
com.mojang:jtracy:1.0.36:natives-linux
io.netty:netty-transport-native-epoll:4.1.118.Final:linux-aarch_64
org.lwjgl:lwjgl:3.3.3:natives-linux
org.lwjgl:lwjgl-glfw:3.3.3:natives-linux
org.lwjgl:lwjgl-opengl:3.3.3:natives-linux
org.lwjgl:lwjgl-openal:3.3.3:natives-linux
org.lwjgl:lwjgl-freetype:3.3.3:natives-linux
org.lwjgl:lwjgl-stb:3.3.3:natives-linux
org.lwjgl:lwjgl-jemalloc:3.3.3:natives-linux
org.lwjgl:lwjgl-tinyfd:3.3.3:natives-linux
```
每个 jar 内含该模块的 `.so`（lwjgl-glfw 含 libglfw.so 等）。

**现代 manifest 特点**：natives 不再走 `extract`+zip 解压（老版方式），而是**独立 classifier artifact**
（`natives-linux` / `linux-aarch_64`），下载即一个 jar，把 .so 拷到 natives 目录即可。

### 1.2 OS 规则（rules）

- `rules` 决定"此库在哪个 OS 启用"：桌面按真实 OS 过滤（linux/osx/windows）。
- **关键**：鸿蒙 JVM 会把 `os.name` 伪装成 `Linux`（见 07 设计），因此 1.21.10 会按 linux
  分支拉取上述 10 个 native jar + aarch64 的 netty epoll——架构由 `os.arch=aarch64` 决定。

## 2. 桌面启动器职责（HMCL 视角）

```
下载器（DependencyManager/DefaultGameBuilder）
  1. 拉 version manifest（versions/<id>/<id>.json）
  2. 按 OS/架构 rules 过滤出实际 libraries → 下载到 <root>/libraries/<maven path>
  3. 下载 natives（classifier jar）→ 解出 .so 到 natives 目录
  4. 下载 client jar（versions/<id>/<id>.jar）与 assetIndex
  5. 按 assetIndex 下载 assets 到 assets/objects（虚拟映射 assets/indexes/<id>.json）

参数生成（DefaultLauncher.generateCommandLine）
  1. java 可执行 + -Xmx/-Xms + JVM 调优（G1GC 等）+ 编码/代理
  2. 解析 manifest 的 arguments.jvm（字符串 + 规则项）+ 占位符替换
     ${classpath} ${library_directory} ${natives_directory} ${version_name} ...
  3. -cp <client.jar + 全部 java libraries>（natives 不进 cp，走 java.library.path）
  4. manifest.mainClass（1.21.10 = net.minecraft.client.main.Main）
  5. arguments.game（--username --gameDir --assetsDir ... + 带 rules 项按 features 过滤）
  6. ProcessBuilder 启动，StreamPump 收日志

游戏运行期
  - LWJGL3 通过 java.library.path 找 liblwjgl*.so / libglfw.so
  - GLFW 真窗口 + 桌面 OpenGL 3.2 core 上下文
  - 每帧：pollEvents → render → swapBuffers
```

## 3. 桌面渲染链（真 OpenGL）

```
MC (Java, RenderSystem/Window)
  → LWJGL3 org.lwjgl.opengl（liblwjgl_opengl.so 的 JNI）
  → GLFW 真窗口（libglfw.so）→ 系统创建 OpenGL 3.2+ context
  → 桌面 GL 驱动直接上 GPU
```

## 4. 对鸿蒙移植的核心含义

1. **游戏主类/参数/库解析全部与平台无关**——只要 JVM 能跑 + os.name 伪装 Linux，
   1.21.10 的纯 Java 部分可原样跑。
2. **被"卡住"的只有三处**：
   - JRE（需 arm64 + 能跑 class v65 即 Java 21）；
   - GLFW（桌面 libglfw.so 无法用，需要"假 GLFW"把窗口/事件 stub 掉）；
   - 桌面 OpenGL（鸿蒙只有 GLES/Vulkan，需要把桌面 GL 调用翻译过去）。
3. 好消息：**1.21.10 的 10 个 native jar 中，lwjgl-glfw 的 libglfw.so 是唯一"窗口系统绑定"的**；
   其余（opengl/openal/stb/freetype/jemalloc）是纯计算库，仍可加载。
   这意味着"stub 掉 GLFW 显示/事件层"是主要工作量。

## 5. 桌面参数/资产要求速查（鸿蒙设计须满足）

- Java 21（class 65）；`-Djava.library.path` 指向 natives 目录（.so 抽取处）。
- 需要 `log4j2` 客户端配置（manifest logging.file → 下载 .xml 并 -Dlog4j.configurationFile）。
- 需要 assetIndex 27 的 assets 完整下载。
- 需要 auth（--uuid --accessToken --xuid --clientId）——可先离线（uuid=offline、token 空/占位）。
- game args 里 `has_custom_resolution` feature 会注入 --width/--height（鸿蒙用它设定 glfwstub 尺寸）。
