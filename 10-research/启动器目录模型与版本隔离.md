# 各启动器的 .minecraft 目录模型、版本隔离与安装流程

> 日期：2026-09-10 ｜ 性质：**外部参考研究**（`ref/HMCL` 源码 + `stuffs/.minecraft` 实证 + 官方文档）
> 上游：[`hmcl-存储模型.md`](hmcl-存储模型.md)（HMCL 总览 + 持久化模型）、[`homolauncher.md`](homolauncher.md)、[`amethyst.md`](amethyst.md)
> 持久化模型（HMCL 配置文件 / 已添加文件夹 / 账户 / 每实例设置 / 迁移怎么落盘）另见 [`hmcl-存储模型.md`](hmcl-存储模型.md)。
> 本文只聚焦三件事：**游戏目录怎么组织 / 版本隔离怎么实现 / 装新版本写哪些文件**。
>
> ⚠️ `ref/HMCL` 是**新版重构**（`GameInstance` / `GameRepositoryLayout` / `GameInstancePatch`），
> 与 [`../90-archive/hmcl.md`](../90-archive/hmcl.md) 里描述的旧类名（`Version` / `DefaultLauncher` 那套）**不是同一套代码**。

## 0. 结论先行（TL;DR）

1. **官方启动器没有"版本隔离"概念**：一个 profile 一个 `gameDir`，每个 gameDir 本身就是一份完整 `.minecraft`。"隔离"是第三方启动器（HMCL/PCL/HomoLauncher）引入的。
2. **"版本隔离" = 把运行目录（`--gameDir`）从 `.minecraft/` 切到 `.minecraft/versions/<id>/`**。
   `assets/` 与 `libraries/` **永远共享** —— 这是所有实现的一致做法（没有任何一家复制或软链它们）。
3. **HMCL 新版**：隔离 = 「**三值策略 + 实例级开关**」，实现上**只是"运行目录取哪一个"**；
   **没有 `run/` 子目录、没有 symlink、没有"逐目录迁移清单"**（这三点是本文最容易搞错的地方）。
4. **PCL**：**逐版本 opt-in**；实证 `--gameDir=versions/<id>`、`--assetsDir=共享`、natives 在 `versions/<id>/<id>-natives/`。
5. **装新版本**的核心流程各家一致：拉 version json → 并行下 libraries + assets → 下 client jar →
   写 `versions/<id>/{<id>.json,<id>.jar}`。**modloader 版本用"增量 patch / 继承"表达，不复制整份 json**。
6. **本项目现状**：`game_directory` 原本固定为 `.minecraft` 根（共享）；
   **2026-09-10 已补上逐版本隔离开关（默认关）**，实现 = 只改 `-Duser.dir`（见 §7）。
   这与 HMCL 默认策略（`MODDED`）不同，见 §6 的取舍分析。

## 1. 官方（Mojang）基线 —— 目录契约本身

**版本 JSON 是唯一权威**（本机实证：`stuffs/.minecraft/versions/1.21.10/1.21.10.json`）：

- `arguments.game` 里带 `--gameDir ${game_directory} --assetsDir ${assets_root} --assetIndex <id>`
  —— **游戏目录不是启动器硬编码的，而是由启动器填进这个占位符**。这就是"隔离"唯一的切入点。
- `arguments.jvm` 引用 `${natives_directory}` / `${library_directory}` / `${classpath}` / `${classpath_separator}`，全部由启动器提供。
- `assetIndex.id` 决定读 `assets/indexes/<id>.json`；`assets` 字段是它的旧式别名。

**`launcher_profiles.json`**（`stuffs/.minecraft/launcher_profiles.json`）：

```json
{ "profiles": { "PCL": { "icon":"Grass","name":"PCL","lastVersionId":"latest-release",
    "type":"latest-release","lastUsed":"2025-07-04T01:18:07+08:00" } },
  "selectedProfile": "PCL", "clientToken": "…",
  "authenticationDatabase": { … }, "selectedUser": { … } }
```

- profile **可以**带 `gameDir`；**不带**时默认 `.minecraft` 根。
- 官方模型是"**多个互相独立的 gameDir**"，不是"一个根 + 每版本子目录"。
- Pojav/Amethyst 的 `MinecraftProfile.gameDir` 字段就是照抄这个 schema
  （`ref/PojavLauncher_iOS/JavaApp/src/launcher/net/kdt/pojavlaunch/value/launcherprofiles/MinecraftProfile.java:11`）。

## 2. HMCL（`ref/HMCL`，源码级）

### 2.1 目录契约：`GameRepositoryLayout`

`HMCLCore` 用一个**纯路径解析器**（不做 I/O）描述"一份仓库长什么样"：
`ref/HMCL/HMCLCore/src/main/java/org/jackhuang/hmcl/game/GameRepositoryLayout.java`
→ 官方布局实现 `ref/HMCL/HMCLCore/src/main/java/org/jackhuang/hmcl/game/DefaultGameRepositoryLayout.java`：

| 概念 | 路径 | 行 |
|---|---|---|
| 实例根（instance root） | `versions/<id>/` | `:53-55` |
| 实例清单 | `versions/<id>/<id>.json` | `:61-63` |
| 主 jar | `versions/<id>/<id>.jar` | `:69-71` |
| HMCL 整合包标记 | `versions/<id>/modpack.cfg` | `:73-75` |
| 实例自带库（仅 `local` hint） | `versions/<id>/libraries/…` | `:87-97` |
| **共享库** | `libraries/<group>/<artifact>/<version>/<artifact>-<version>[-<classifier>].<ext>` | `:81-83` |
| **共享资源** | `assets/` | `:103-105` |
| 资源索引 | `assets/indexes/<assetId>.json` | `:109-111` |
| 资源对象 | `assets/objects/<hash 前 2 位>/<hash>` | `:115-117` |
| 日志配置 | `assets/log_configs/<id>` | `:124-126` |

HMCL 另在实例根加自己的私有目录（`ref/HMCL/HMCL/src/main/java/org/jackhuang/hmcl/game/HMCLGameRepositoryLayout.java`）：
`.hmcl/`、`.hmcl/config/`、`.hmcl/state/`、`.hmcl/config/instance-game-settings.json`。

**实例级可变数据**（`ref/HMCL/HMCLCore/src/main/java/org/jackhuang/hmcl/game/GameInstance.java`）：

```java
getModsDirectory()          = getRunDirectory().resolve("mods")
getResourcePackDirectory()  = getRunDirectory().resolve("resourcepacks")
getSavesDirectory()         = getRunDirectory().resolve("saves")
getBackupsDirectory()       = getRunDirectory().resolve("backups")
getSchematicsDirectory()    = getRunDirectory().resolve("schematics")
getNativeDirectory(pf)      = getInstanceRoot().resolve("natives-" + platform)   // ← 注意：实例根，不是 run dir
```

→ **除 natives 外，全部游戏数据都挂在 `runDirectory` 之下**。这就是"隔离"的全部机制面。

### 2.2 版本隔离：只有三值策略 + 一个"运行目录"开关

**策略枚举**（`ref/HMCL/HMCL/src/main/java/org/jackhuang/hmcl/setting/DefaultIsolationType.java`）：

| 值 | 含义 | UI 文案（`I18N_zh_CN`） |
|---|---|---|
| `ALWAYS` | 所有新实例都隔离 | `settings.game.default_isolation.always` = 隔离所有实例 |
| `MODDED` | **仅装了 modloader 的新实例隔离（默认）** | `settings.game.default_isolation.modded` = 隔离模组实例 |
| `NEVER` | 都不隔离 | `settings.game.default_isolation.never` = 不隔离实例 |

判定（`ref/HMCL/HMCL/src/main/java/org/jackhuang/hmcl/game/HMCLGameRepository.java`）：

```java
DefaultIsolationType type = …preset.defaultIsolationTypeProperty().getValue() ?? MODDED;
return switch (type) { case NEVER -> false; case ALWAYS -> true; case MODDED -> modded; };
```

**运行目录 = 隔离开关本体**（同文件 `:225-262`，本次已核对）：

```java
Path computeRunDirectory(id, modpack, localSetting) {
    Path instanceRoot = layout.getInstanceRoot(id);
    if (modpack) return instanceRoot;                       // 整合包：强制隔离
    boolean hasOverride = localSetting != null
        && localSetting.getOverrideProperties().contains(PROPERTY_RUNNING_DIRECTORY);
    String dir = selectedRunningDirectory(localSetting, hasOverride);   // 实例值 > 预设值
    if (StringUtils.isBlank(dir))
        return hasOverride ? instanceRoot : getBaseDirectory();         // 空串 = 隔离到实例根；无 override 且空 = 共享根
    return Path.of(dir);                                                // 自定义绝对路径
}
```

要点：

- **"隔离"= 运行目录取 `versions/<id>/`**；自定义路径也走同一个字段（`settings.game.running_directory` = 游戏运行路径）。
- **没有 `run/` 子目录**。全仓 grep 只有 Gradle 任务和测试夹具里出现过 `run`。
- **没有 symlink 隔离**。symlink 只用在别处：非 ASCII natives 路径 workaround（`DefaultLauncher.java:304-309`）、Java 安装（`JavaInstallTask.java:87`）。
- 删除实例的告警文案直接反映语义：`instance.manage.remove.confirm.independent` =「…启用了…版本隔离…删除该实例将导致该游戏的世界等数据一同被删除！」

### 2.3 启动期：`--gameDir` 从哪来

- `${game_directory}` = `instance.getRunDirectory()`（`ref/HMCL/HMCLCore/src/main/java/org/jackhuang/hmcl/launch/DefaultLauncher.java`）。
- 进程 CWD = run dir：`new ProcessBuilder(cmd).directory(runDirectory)`（`DefaultLauncher.java:688-698`）。
- **HMCL 不显式发字面 `--gameDir`**，走 JSON 模板替换。
- ⚠️ `LaunchOptions.gameDir` 是**另一个**东西：它是**仓库根**，只用于 `-Duser.home=<父目录>` / `APPDATA=<父目录>`（`DefaultLauncher.java:164-165`、`:702-703`），**与隔离无关**。

### 2.4 安装新版本：整条流水线

编排（`ref/HMCL/HMCLCore/src/main/java/org/jackhuang/hmcl/download/DefaultGameBuilder.java`）：

```
newGameBuilder(id)                       // 空 manifest(root=true) + 独占 draft
 ├─ 组件链：GAME 先 → 各 loader 按 GameComponentType 枚举序 thenCompose 串行
 │    GAME → LEGACY_FABRIC → FABRIC → FORGE → CLEANROOM → NEO_FORGE → LITELOADER → OPTIFINE → QUILT …
 └─ 收尾：draft.getBaseSnapshot().resolve(manifest)      // 合并成最终清单
          → GameDownloadTask                            // client jar
          → draft.put(resolved.withPatches(...)) + draft.putPrimaryJar(...)
          → draft.commit()                              // 真正落盘
```

单版本下载（`ref/HMCL/HMCLCore/src/main/java/org/jackhuang/hmcl/download/game/GameInstallTask.java`）：

```java
patch = GameInstancePatch.fromManifest(<version json>, "game", ver, PRIORITY_MC).withJar(null);
dependencies = Task.allOf(
    GameDownloadTask,                                   // client jar（必需）
    Task.allOf(assetTask, librariesTask).withRunAsync(() -> {})   // ← assets/libraries 失败"故意不致命"
);
```

- **并行**：assets 与 libraries 并发；每个对象再各自 fan-out 一个下载任务。
- **幂等/跳过**：libraries 校验 jar 内 `checksums.sha1`；assets 对象存在即跳（除非开完整性检查）；asset index 校验 sha1；client jar 走内容寻址缓存；Forge processors 输出 sha1 全对则整段跳过。
- **落盘**：`DefaultGameRepositoryDraft.commit()` 在 `<base>/.hmcl/repository-drafts/` 留回滚点，然后写
  `versions/<id>/<id>.json`（`:425-430`）与 `versions/<id>/<id>.jar`（`:440-449`）。
- client jar 是**先下到共享缓存（按 SHA-1 命名）**，commit 时才拷成人类可读的 `<id>.jar`。

### 2.5 modloader 怎么表示：patch 优先，`inheritsFrom` 兼容

**HMCL 自己装出来的实例不用 `inheritsFrom`**，而是：

- 每装一个组件产出一个 `GameInstancePatch(id, version, priority, …)`
  （`ref/HMCL/HMCLCore/src/main/java/org/jackhuang/hmcl/game/GameInstancePatch.java`）。
- **优先级**：`PRIORITY_MC = 0` < OptiFine `10000` < Forge/Fabric/Quilt/NeoForge `30000` < LiteLoader `60000`。
- 落盘 = **字段已合并完成的 root manifest + 一个 `patches` 数组**（`GameInstanceManifest.reconstructByPatches`）。

`inheritsFrom` 仍被**读**（官方启动器/旧 HMCL/整合包产物），由
`ref/HMCL/HMCLCore/src/main/java/org/jackhuang/hmcl/game/DefaultGameRepositorySnapshot.java`
递归合并（带环检测；父缺失 → `NoSuchGameInstanceException`）。

**两套合并的优先级（这是最容易踩的细节）**：

| 字段 | `merge(parent)`（inheritsFrom） | `Builder.merge(patch)`（patches，按 priority 升序） |
|---|---|---|
| `libraries` | **child 在前 + parent** | existing 在前 + patch |
| `arguments.game/jvm` | **parent 在前 + child** | existing 在前 + patch |
| `mainClass` / `assetIndex` / `javaVersion` / `downloads` / `logging` | child 非空则覆盖 | patch 非空则覆盖（**高优先级胜**） |
| `complianceLevel` | **只取 child，无 parent 回退**（唯一例外的怪点） | 非空覆盖 |
| `minimumLauncherVersion` | `max` | `max` |

**库去重发生在启动期**（不在 resolve 期）：`ref/HMCL/HMCLCore/src/main/java/org/jackhuang/hmcl/game/LaunchManifestNormalizer.java`（本次已核对）：

- **去重键 = `groupId + ":" + artifactId`**（`:283`）—— **不含版本、不含 classifier**。
- `rules` 不同 → 两条都留（平台变体）；`rules` 相同 → **高版本胜**；
  同 id 同版本且 `equals` → 序列化更长者胜；同 id 同版本但坐标不等（如 text2speech jar vs natives）→ **都留**。

### 2.6 落盘细节（第三方要复刻时必须对齐的部分）

- 库路径 —— `Artifact`：`<group 点转斜杠>/<name>/<version>/<name>-<version>[-<classifier>].<ext>`
  （`ref/HMCL/HMCLCore/src/main/java/org/jackhuang/hmcl/game/Artifact.java`）。
  无 URL 时回退 `https://libraries.minecraft.net/`。
- 资源对象 —— `AssetObject.getLocation() = hash[0:2] + "/" + hash`
  （`ref/HMCL/HMCLCore/src/main/java/org/jackhuang/hmcl/game/AssetObject.java`）。
- **老版本资源映射**：`AssetIndex.virtual` / `map_to_resources` → 启动时把对象重建成
  `assets/virtual/<assetId>/<原名>`，必要时再写 `<runDir>/resources/`
  （`ref/HMCL/HMCLCore/src/main/java/org/jackhuang/hmcl/game/DefaultGameInstance.java`）。

### 2.7 natives

- 选包：`Library.classifier()` —— 先试老式 `natives` map（按 `os.name`/arch 拼 `native-`/`natives-` 前缀），
  再试 `downloads.classifiers` 里以 `native` 开头的键（`ref/HMCL/HMCLCore/src/main/java/org/jackhuang/hmcl/game/Library.java`）。
- 解压：`DefaultLauncher.decompressNatives(dest)`（`ref/HMCL/HMCLCore/src/main/java/org/jackhuang/hmcl/launch/DefaultLauncher.java`）
  → 目标是 `versions/<id>/natives-<platform>`；`ExtractRules` 是**前缀排除表**，空表 = 全解
  （`ref/HMCL/HMCLCore/src/main/java/org/jackhuang/hmcl/game/ExtractRules.java`）。
- 老/新版本在 HMCL 里**走同一条路径**（没有单独的"legacy natives 解包器"）。
- `${natives_directory}` → `-Djava.library.path`（来自 `Arguments.DEFAULT_JVM_ARGUMENTS`）。

### 2.8 用户视角的"装新版本"

`下载 → 游戏` 页选版本 → 向导（选 modloader / 版本名）→ 完成：
`DownloadPage.finishVersionDownloadingAsync` 组 `HMCLGameBuilder`，
**若选了 modloader 则按策略自动 `enableIsolation()`**（`DownloadPage.java:324-329`）→ `buildAsync()`。
给已有实例**加/换/删** loader 走 `UpdateInstallerWizardProvider` / `InstallerListPage`（不重建整实例）。

### 3.3 natives 位置

- **活跃位置**：`versions/<v>/<v>-natives/`（1.16.5 是 LWJGL2 时代全套 16 个 DLL；1.21.10 是 GLFW/OpenAL/jemalloc/jna）。
- `versions/1.21.10-natives/`（**版本目录的同级兄弟**）里**只有一个 `jna…tmp`** → 判定为**遗留垃圾**，不是活跃 natives 目录
  （活跃目录一定有整套 DLL）。

### 3.4 隔离的硬证据

**① 命令行考古**（`stuffs/.minecraft/versions/1.19.4/hs_err_pid26168.log`，本次已核对原文）：

```
-Djava.library.path=<gameDir>\versions\1.19.4\1.19.4-natives
-Dminecraft.launcher.brand=PCL -Dminecraft.launcher.version=361
… net.minecraft.client.main.Main --username <player> --version 1.19.4
  --gameDir   <gameDir>\versions\1.19.4      ← 隔离：游戏目录＝版本目录
  --assetsDir <gameDir>\assets               ← 共享
  --assetIndex 3
```

→ **PCL 的隔离就是切 `--gameDir`，assets 保持共享**。与 HMCL 同构。

**② 世界落点**：世界写在 `<gameDir>/saves/`，所以落点直接暴露当时的 gameDir：
根 `saves/{1_16_5,26_1_2,wow}` = 那几次运行**没隔离**；`versions/1.21.10/saves/Meow` = 那次运行**隔离了**。
→ 隔离是**逐版本开关**，同一份 `.minecraft` 里可以混着有/无。

## 6. 共同规律（可直接复用的设计结论）

1. **两个共享池是"必须"**：`libraries/`（Maven 路径天然多版本共存）+ `assets/`（内容寻址 `objects/<2>/<hash>`）。
   实测 `stuffs/.minecraft/libraries` 里 `authlib` ×4 / `guava` ×4 / `lwjgl` ×4 共存 —— 就是这个道理。
2. **`versions/<id>/` 是"实例"**：不可变载荷（`<id>.json` + `<id>.jar`）＋ 可变游戏数据（隔离时）。
3. **隔离只切"运行目录"这一个变量**，从不去复制/软链 `assets`+`libraries`。所谓"隔离各目录"其实是运行目录切换的**推论**，不是一份目录清单。
4. **natives 是各家最不一致的一处**（版本目录内 / 同级 / 应用缓存），是移植时最容易对不上的点。
5. **modloader 用"叠加"表达**：HMCL 用 `patches[]`（带优先级），Mojang/旧启动器用 `inheritsFrom`；**都不复制整份 json**。
6. **安装是幂等的**：存在即跳 + 校验和（jar 内 `checksums.sha1` / asset index sha1 / 对象 sha1）。
7. **`versions/` 目录名 = 实例 id**，且它就是 `GameComponentType`/`Setup.ini` 等元数据里"当前玩家看到的版本名"。

### 7.2 已实现（2026-09-10）

按 §2.2 的结论落地，改动面确实极小 —— **关键就是 `-Duser.dir` 这一个变量**：

- **开关**：逐版本。**2026-09-10 当时**存 Preferences（`KEY_VERSION_ISOLATION`，JSON id 列表；`putSync` 后必 `flushSync`）；
  **2026-09-15 起改为存各实例目录内的 `<gameRoot>/versions/<id>/.hmmcraft/instance-settings.json`**
  （主进程 UI 与游戏进程 `GameLauncher` 读同一份实例文件；旧 Preferences 键弃用），见
  [`../20-design/launch/实例设置存储-方案.md`](../20-design/launch/实例设置存储-方案.md)。
- **UI**：版本行的"编辑"按钮可展开/收起（文案 `编辑` ↔ `完成`），面板内是逐实例开关（隔离 / 渲染后端 / 线程化渲染）。
- **生效点**：`MinecraftLauncher` 的 `gameDir` 选项 → `-Duser.dir` 取它 → `GameDirs.profile`
  → `${game_directory}` 宏 → MC 的 `--gameDir`。
  `-DMEOWCRAFT_GAME_DIR` / `assets_root` / `-Dmeowcraft.path.minecraft` **都不变**（仍指共享根），
  所以 `versions` / `libraries` / `assets` 不随隔离移动；`-Duser.home` 也保持根（不参与隔离）。
- **默认关**（未勾选 = 维持原行为，现有落在根 `saves/` 的世界不受影响）——与 PCL / HomoLauncher 默认一致。
- **未做**：世界迁移提示（根 `saves/` → 版本 `saves/`）；natives 无需动（我们本来就不放版本目录）。
- **Fabric 的 `.fabric/` 落运行目录（= 用户存储，2026-09-27）**：Fabric 首次 remap 写 `<gameDir>/.fabric/remappedJars/`，而手机游戏目录在**用户存储**（FUSE/hmdfs，**拒 chmod**）⇒ `jdk.zipfs` 的 `setPosixFilePermissions` 失败、Fabric 崩；属 **JDK 侧** best-effort 修复（见主仓 `tools/jre26/` 与 [`../00-current/现状基线.md`](../00-current/现状基线.md) §5 第 27 条、[`../90-archive/Fabric安装-方案.md`](../90-archive/Fabric安装-方案.md) §6.2）。
