## §1 判读前提（三条，来自 canonical §9，必须先记住）

1. **信号链顺序固定**：`0 = libdfx/DFX` → `3 = musl` → `usr`（普通 `sigaction` 全在最后）⇒ **抢不到 DFX 前面** ✗。
2. **平台报告会 latch 良性 fault**：`Reason: …@0x0000005afce7d000`（`[---p]`，safepoint 轮询页）+ 寄存器里 `x8` 等于该地址
   ⇒ **这条不是崩因** ✗；**只挑非轮询页的读** ✓。
3. **`Registers:` 段是精确的** ✓；`LastFatalMessage: Failed to unwind stack…` 只说明报告里那串 `#00…#31` 帧**不可信** ✗。

## §2 采集仪器

### 2.1 项目抓栈器 `meowbt`（能拿寄存器全量）

**开法**（两个 env，写在「高级选项 → 渲染环境变量」里，`;` 分隔）：

```
MEOW_BT=1;MEOW_BT_FILE=/data/storage/el2/base/haps/entry/files/meow-vk-crash.txt
```

- `MEOW_BT`（`meowbt.c`）——**总开关**；`0`/空 = 不装。
- `MEOW_BT_FILE=<path>`——**落盘路径**（不给就只打 stderr ✗）。
- ❌ **不要** `MEOW_BT_LOW=1`：那是"关近空过滤"，会灌满良性 NPE ✗（文档点名的死路）。

**落点与格式**：
- 文件以 **`O_WRONLY|O_CREAT|O_APPEND|O_CLOEXEC, 0644`** 打开 ⇒ **追加、跨轮累积** ✓
  ⇒ 判断"本轮写了什么"要**看每条记录自带的 `T=<epoch>`**（不是文件 mtime）✓。
- **同一文件两个视角**（同一份数据 ✓）：

  | 视角 | 路径 |
  |---|---|
  | App 自己写的 | （设备端，非本机路径）/data/storage/el2/base/haps/entry/files/meow-vk-crash.txt |
  | 我的 shell 读的 | （设备端，非本机路径）/data/app/el2/100/base/meow.liny.craft.awa/haps/entry/files/meow-vk-crash.txt |

- 每轮开头是**安装块**（banner + `mapcount=` + KEY 映射 + `prev_segv_handler=<addr> <lib>+off`）⇒ **可当"本轮是否走到某阶段"的心跳** ✓。

**它能看到什么 / 看不到什么**（实测）：
- ✅ **`SIGABRT`（abort）** 与 **`ACCERR`（如轮询页）** 会进它的 handler；
- ⚠️ **`MAPERR`（低地址野读）大多进不去**（DFX 在用户层之前就判死 ✗）——**但不是绝对**：2026-09-17 的转储里就有 meowbt 亲手记下的 `sig=11 code=1`（=MAPERR）`addr=0x0` 记录（工作区根 `stuffs/research/vulkan/vk-m1-evidence/meow-vk-crash-NOW.txt`）⇒ **别据此认定该通道一律不可用**；
- ⇒ 所以：**"dump 里没有某条 fault" ≠ "没发生"** ✗ —— 先排除采集侧（是否被 DFX 抢先、是否被环形截断、是否根本没开）✓。

**安装自保（已实现）**：`meow_bt_install_once()` 装前先 `sigaction(SIGSEGV,NULL,&cur)`，
若旧动作是 `SIG_DFL`/`SIG_IGN`（HotSpot 还没装）⇒ **拒绝安装并 hilog 告警**，且**不置 `g_installed`**（留给后续调用重试）✓。
Vulkan 档的安装点放在 **shim 的第一次 Vulkan 调用**（保证在 JVM 之后）✓。自证行：`meowbt: installed pid=<N> (chained-to … valid=1 …)` ✓。

### 2.2 卡死看门狗 `MEOW_VK_WD`（自触线程转储）

```
MEOW_VK_WD=15
```
—— 超过该秒数**没有任何 Vulkan 活动** ⇒ 打 hilog + **`SIGQUIT`（标准线程转储信号，刻意不是 SIGSEGV ✓）** ⇒
HotSpot 打印**全部线程栈**，经启动器转发为 **`[jre_stdout]`** ✓（本次就是靠它看到"`main` 卡在 `BuiltInRegistries.bootStrap`" ✓）。

⚠️ 两个坑：① 它假设"Vulkan 活动 = 存活" ⇒ **非 Vulkan 阶段（如 MC bootstrap）会误报** ✓（日志会写 `last seen: (none)` ✓）；
② 最多触发 3 次、每次间隔一个阈值 ✓。

### 2.3 平台 faultlog（**真凶现场的主通道**）

```sh
# 我自己的 shell 直接读（不要用 hdc ✗）——但要写【全路径】：父目录 /data/log 反而 Permission denied ✗
ls -t /data/log/faultlog/faultlogger/ | grep meow.liny.craft.awa | head
grep -m1 '^Reason:' /data/log/faultlog/faultlogger/cppcrash-meow.liny.craft.awa-*
```

- **`hdc shell` 读不到**（uid 2000 ✗）；`hdc file recv` 能整目录拉（另一条权限链 ✓），但没必要 ✓。
- **只保留最近一批、会被清理** ✗ ⇒ **读到就当场归档**到 `stuffs/research/vulkan/vk-faultlog-archive/` ✓；
  **禁止**用它的"有无/多少"做历史或范围推断 ✗。
- 读法：先看 `Reason`（挑非 `@0x5afce7d000` 的 ✓）⇒ 再看 `Pid`（用来找同轮 `hotspot_pid<pid>.log` ✓）⇒
  取 `Registers:` 的 `lr:… sp:… pc:…` 那一行 ✓。

### 2.4 hilog 导出（`.logs/`）

- 需要日志时**请用户导出**（agent 禁止自己抓日志 ✗）；导出是**环形快照** ⇒ 会被海量输出挤掉 ✗ ⇒ **崩后先导出再重启** ✓。
- 两类行：`[jre_stdout]`（JVM 的 stdout：**线程转储** ✓、JVM 启动期报错 ✓）与 `[jre_stderr]`（JVM 的 stderr ✓）。
- 我们的 native 用 `MEOWLOGI` 直接进 **hilog** ✓（不经 stderr ⇒ **不会被猝死丢缓冲** ✓）——**诊断自证的输出优先走它** ✓。
- **日志级别决定"会不会出现"**：某行能否被采集到取决于**该行级别 ≥ 采集级别** —— 例如 `meowSendKey` 是 **DEBUG 级**（`主仓 libs/meowcraftlib/src/main/cpp/meowjrebridge/meowjrebridge.cpp` 约 855）⇒ **INFO 级采集里不会出现**；**不可**用"日志里没有"推断"没发生" ⇒ **先核该行日志级别与采集级别** ✓（同 §5 第 9 条）。
- **SDL fork 鼠标埋点判读（常开限频）**：本工程随包 SDL 打 `[jre_stderr] MeowSDL: BUTTON/MOTION src=… grabbing=…`（`SDL_Log` 在本平台不可见 ⇒ 走 stderr）。**判读**：某来源若在 `BUTTON down` 后**紧跟**一条 `MOTION` ⇒ 该来源是"点击致视角微转"的嫌疑（按键坐标被当位移）；逐来源比对 `MOTION src=bridge` / `src=pumpdiff` / `src=warp` / `src=pumpabs` 计数可定位。

### 2.5 `-XX:+LogCompilation`（**符号化燃料**）

```
-XX:+UnlockDiagnosticVMOptions -XX:+LogCompilation
```
⇒ 每次运行在**实例目录**产 `hotspot_pid<pid>.log`（每条 nmethod 带 `address`+`size` ✓）+
`hs_c<compileid>_pid<pid>.log`（噪声 ✗）。**没有它，`pc` 就反查不了** ✗（本役曾因它被关掉而空转两轮 ✗）。

### 2.6 MC 侧产物

- `versions/<id>/crash-reports/crash-*.txt`：**Java 层崩溃**才会出现（若只是原生死 ⇒ 不出现 ✗）；
- `versions/<id>/logs/latest.log`：本机曾**整体缺失** ✗ ⇒ 不要以它的存在为前提。

## §3 分析仪器

### 3.1 `resolve_pc.py`：`pc` → Java 方法

```sh
python3 stuffs/research/vulkan/resolve_pc.py \
        stuffs/.minecraft/versions/26.2/hotspot_pid<pid>.log 0x<pc> 0x<lr>
```
输入 = **同轮**的 `hotspot_pid<pid>.log`（pid 取自平台报告的 `Pid:` ✓）。
输出：命中的 nmethod（`方法名 + compile_id`）／`not in any nmethod (inside range: stub/non-method area)`／
`OUTSIDE code cache by 0x… below/above`。

⚠️ 三个坑：① **`lr` 可能是脏值** ✗（实测落在 JVM 的 C 堆带内、与 `rthread` 同带）⇒ 别把 `lr` 当铁证；
② 只覆盖 **nmethod**：stub / 运行时代码会报 `inside range` ✓（这本身就是信息）；
③ **"崩点漂移"要先怀疑"调用了一个坏函数指针 / 一个坏对象被到处消费"** ✗，不要一头扎进那个方法 ✗。

### 3.2 寄存器从哪来

平台报告 **`Registers:` 段是精确的** ✓（这是首选）；需要 **`x2`/`x8` 等全量**时用 `meowbt` 的转储 ✓（§2.1）。

### 3.3 ★ **去 `-DNDEBUG`，让第三方库自己招供**（本役最有效的一招）

**原理**：第三方库（如 VMA）内部普遍有 `ASSERT`；随包构建为性能去掉 `-DNDEBUG` 之外还会关掉它们 ✗
⇒ **只在诊断构建里保留断言** ⇒ 库会当场打印 **`文件:行号: 条件`** 再 abort ✓✓。

**本役实例**：VMA 直接喊出
`Assertion failed: m_VulkanFunctions.vkGetPhysicalDeviceProperties2KHR != nullptr`（`vk_mem_alloc.h:13825`）✓
⇒ 一步定案"函数表里有 NULL" ✓。

**配套**：顺手加"**NULL 清单诊断**"（遍历函数表，谁为 NULL 打一行 ✓）——比逐个猜快得多 ✓。

⚠️ **坑（实测）**：**不要用 `#define memset` 之类劫持标准函数** ✗ —— 它会重写**后续系统头里的声明**，
报 `redefinition … as different kind of symbol` ✓。要加桩就**只包具体调用点**（正则/逐处替换 ✓）。

### 3.4 产物自报版本

每次构建让 native 打一行 `<tag>`（本工程：`meowvulkan: shim build 2026-09-17.5 (…)` ✓）
⇒ 任何一轮都能**一眼证明"设备上跑的是哪一版"** ✓（本役踩过"改了但没部署到设备"的坑 ✗）。
**规则**：**改变了产物就升 tag** ✓。

### 3.5 VM 参数**先自校**

- 形式错会让 **JVM 拒启**（`Unrecognized VM option …` / `Error: Could not create the Java Virtual Machine`）⇒
  现象是"**崩得更快**"（`SIGABRT`）✓ —— 别误读成"这次崩了" ✗；
- 本役两次栽跟头：`-XX:-UseImplicitNullChecks`（**不存在这个名字** ✗）、
  `-XX:CompileCommand=exclude,java/util/HashMap::computeIfAbsent`（**`/` 与 `::` 混用** ✗，JVM 提示 `replace '/' with '+'` ✓）；
- ⇒ **先让 JVM 校验形式**（它会明确报），或 **`-XX:CompileCommand=help`** ✓。

## §4 实验设计手段

### 4.1 单变量 + 对照（永远是第一原则）

例：**只改渲染后端**（Vulkan ↔ auto/GL，其余设置不动）⇒ 本次据此确认"崩溃与 Vulkan 路径绑定" ✓。

### 4.2 `-XX:CompileCommand=exclude,…`（把某方法逼成解释执行）

**正确语法**（读自 JVM 自带帮助 `ref/jdk26u/src/hotspot/share/compiler/compilerOracle.cpp:620-660` ✓）：
`<class>.<method><descriptor>`，兼容 `Class::method`（**两者不可混用** ✗）；**类名与方法名都支持 `*`** ✓，**可给多条** ✓：

```
-XX:CompileCommand=exclude,java/util/HashMap.*
-XX:CompileCommand=exclude,com/mojang/datafixers/*.*
```
**能做什么**：让该方法（及其调用者）走解释器 ⇒ **显式空检查 ⇒ 可能把"原生野读"变成可读的 `NullPointerException`** ✓。
**本役结论**：**有效但"漂移无界"** ✗ —— 排除一族后崩点立刻搬到另一族（`SHA5` / `ClassLoader.compareCerts` / `List.of` …）
⇒ 只在"崩点集中在少数族"时才值得用 ✓。

### 4.3 ★ `-Xint`（决定"**是不是 Java 层面**"）

```sh
-XX:+UnlockDiagnosticVMOptions -XX:+LogCompilation -Xint
```
**全部解释执行、零 JIT** ⇒ 若那个坏东西是 **Java 对象**，`NullPointerException` 必然被正常抛出 ✓（可读 MC 自己的栈）；
若是 **native 层面**（如 `memset(NULL, …)`），崩点会**回到 musl** ✓ —— **本役即如此**（`SIGSEGV@0x0` + pc=musl `memset` + `x2=0x8000` ✓）。
⚠️ **很慢**（MC bootstrap 从 20 s 变 165 s ✓）⇒ 耐心等，别动它 ✓。

### 4.4 其它 JVM 侧开关（各自能证什么）

| 开关 | 能证 | 本役结果 |
|---|---|---|
| `-XX:-ImplicitNullChecks`（**注意没有 `Use` 前缀**）| 能否让"隐式空检查"变成显式 | ✗ 本役无效（⇒ 故障不是"空接收者"读写）|
| `-XX:+VerifyBeforeGC -XX:+VerifyAfterGC` | **Java 堆是否被写坏** | ✓ 全程未报 ⇒ **堆没坏** |
| `-XX:+UnlockDiagnosticVMOptions` | 解锁上面那些 diagnostic 旗标 | —— |

### 4.5 env 门控总闸（**默认零行为变化**）

`MEOW_VK_SHIM` 未设/`0` ⇒ shim **纯透传**（与系统 loader 行为一致 ✓）。
⇒ 任何"疑似我们自己造成的崩溃"，**第一对照就是"关掉总闸"** ✓（本次即用此法证明"崩溃需要绕过门控才出现" ✓）。

### 4.6 为什么"钩子二分"做不到（结构性）

本 shim 的 4 个钩子**每一个都是 MC 接受 Vulkan 后端的必要条件** ⇒ 关掉任一 ⇒ MC 直接回退 GL ⇒ **不崩 = 无信息** ✗
⇒ **别在这条路上花时间** ✗。

## §5 反模式 / 死路（都踩过）

1. **等 `hs_err`** ✗（DFX 在链首，永不产）；
2. **以为**我们的 dumper **一律**抓不到 `MAPERR` ✗（**大多**被 DFX 抢先，但 2026-09-17 实测也有进得去的——见 §2.1 的 `sig=11 code=1` 记录）；
3. 想用 `sigaction` **抢在 DFX 前** ✗（sigchain 定序）；
4. **`MEOW_BT_LOW=1`** ✗（灌满良性 NPE）；
5. **在 JVM 进程里劫持 SIGSEGV** ✗（会破坏 HotSpot 的隐式空检查 ⇒ 在**第一个良性空检查**处就 abort；现象 = "**崩得更快**"）；
6. 用 faultlog 的"有无/多少"做**历史或范围**推断 ✗（它会被清理）；
7. **凭记忆写 VM 参数 / 结构体字段序 / 函数名** ✗（本役三次栽在这上面）；
8. **只读 `Reason` 就下结论** ✗（要挑非轮询页的）；
9. **用一句 `grep` 没命中去推断"没有发生"** ✗（要先排除采集侧：环形截断 / 未刷 / 不同轮 / 被抢先）；
10. **劫持标准库函数名（`#define memset` 等）加桩** ✗（会破坏后续系统头声明）；
11. **一次性写就、又不自证** ✗（本役 5 处自己的问题**全部**出自这个模式）。
